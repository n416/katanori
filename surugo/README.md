# 刷るぞー

**印刷ターム（プレート 1 枚）を単位にして、刷る前に計画を立て、刷った結果をログに積む道具。**

```
python surugo/server.py        →  http://127.0.0.1:8731/
```

## なぜプレート単位なのか

番手もフィルムの状態も位置も、**部品ではなくプレート単位で効く**。いちばんはっきりした例が
[docs/PRINT.md](../docs/PRINT.md) 冒頭の「大きい部品は板が厚く出る」で、あれは
**同じプレートに載っている他の部品が、小さい板の厚みを変えている**現象である
（45mm 離れた大きい板が +0.9 変えた）。部品ごとの STL という単位では、この現象を表現できない。
印刷時間も同じで、「一番背の高い部品だけが決めている」のはプレートの性質である。

## 出力は「結合した 1 つの STL」

✅ 実機で確認済み（[docs/PRINT.md](../docs/PRINT.md) §3）。**CHITUBOX は読み込んだ STL の
座標を捨てて、bbox の中心をプレート中央に合わせる。** 部品ごとに別ファイルで出すと、
相対位置すら保たれない（衝突を避けて勝手にずらされる）。⇒ 1 つに結合して出す。
向きと Z は変えられないので、動くのは XY だけ。

書き出す配置は bbox の中心が (0,0) になるよう作ってあるので、**中央合わせが何もしないのと同じ**になる。
⇒ CHITUBOX では読み込んで、**動かさずにスライスする。**

⚠ プレート上の絶対位置（傷を避ける・フィルムの摩耗を散らす）は、必ず中央へ寄るので指定できない。
やるときは「移動量を出して、人が CHITUBOX の数値欄に入れる」マニュアル操作になる。

## 書いてよい人が種類ごとに違う

ログ（`hardware/print_log.jsonl`）は追記だけの出来事の列。

| 種類 | 中身 | 誰が |
|---|---|---|
| `term` | 印刷ターム（部品・接地・配置） | 人でも **AI でもよい**（STL から導ける事実だから） |
| `placed` | 移動指示を実際に適用したという確認 | 人 |
| `result` | 刷り上がりの結果 | **人だけ** |
| `film` | フィルム交換（摩耗の累積がここで 0 に戻る） | **人だけ** |
| `plate` | 研ぎ直し（番手が決まるのはここ） | **人だけ** |
| `resin` | レジン交換 | **人だけ** |

🔒 2026-09-02 ユーザー「間違えた時に戻す方法ないぞこのあぷり」。⇒ ヘッダの**「ログ」**で全行を見て、
行ごとに**編集・削除**できる（人だけ）。書き換える前に必ず `hardware/print_log_bak/<時刻>.jsonl` へ
丸ごと写し、**「戻す」はその写しを戻す**。行を直しても STL は動かさない（archive へ移す・消すのは
`result` / `drop` を積んだときだけ）。実例: 1405 に書いた失敗の result を 1404 へ付け替えた（16:40）。

🔴 **AI に物理の観測を書かせない。**推測が観測の顔で混ざると、勘を反証するために貯めている
記録が最初から汚れる。⚠ `by` の判定は規律のための柵であって錠前ではない。

⭐ 番手とレジンを**印刷のたびに打ち込ませない**のは、毎回手で入れる欄が必ず腐るからである。
出来事として一度書けば、以後のタームはそれを引き継ぐ。

## 大きい部品は単独で刷る（接地が LCD の 30% 以上）

🔒 2026-08-31 ユーザー「デカイのを刷る時は他のを置いちゃだめ。引きずられて寸法が狂うから」。
接地が `rules.json` の `alone_grip_mm2` 以上の部品が入っていると、**並べずに止まる。**

境目は **3,855mm² ＝ Mars 3 の LCD（143.43 x 89.6 = 12,851mm²）の 30%**。
この機種の系統で知られている目安で、原因は Z の柱でもプレートの取り付けでもなく
**プリンタ本体のベースプレート（土台）のたわみ**。出典と表は
[docs/PRINT.md](../docs/PRINT.md) の節「これは Mars 系で知られている現象だった」にある。

⭐ **うちの実測とも合っている。** btntest 9% → 育ち 0 ／ v4_top 40% → +1.2 ／ テスト板（大）50% → +1.2。
30% の線が「出た組」と「出なかった組」のちょうど間に落ちる。

🔒 **見るのは接地ではなく断面。**原文は "cross-sections"。v4_top は接地 5192.9（40%）に対して
断面の最大が 5579.8（**43%**）で、接地だけでは過小評価になる。⇒ 部品ごとに層ごとの断面積を持つ。

🔒 **効くのは「その層に載っている合計」。**原文の "you don't have any large cross-sections" は
プレート全体の話で、たわむ原因が剥離力である以上そうなる。⇒ **1 個ずつ線の下でも、同じ層で
足して 30% を超えたら止める。**例: `v4_lwall` + `v4_rwall` は 11 層目（Z 0.55mm）で合計 53%。

## 判定はまだ入れていない

番手の 3 段（#600 / #800 / #1000）を接地面積から自動で出すことは**していない**。
あの境目は実績ではなくユーザーの勘で、n が小さいため
（[docs/PRINT.md](../docs/PRINT.md) §4「まだ道具にしない」）。**先にやるのは判定ではなく記録**である。

## 数字を二重に持たない

接地面積・島・持たれていない天井は [_stl_preflight.py](../hardware/_stl_preflight.py) を
そのまま呼んで出している（`measure.py`）。同じ数字が 2 か所にあると、片方だけ動く。

## 浮かせて刷る部品

いまのパイプラインでは扱えないので、`rules.json` の `lifted` に名前があると止まる。
🔴 **これを幾何から推論してはいけない。**一度そうしたら、直置きで刷れている
`v4_shutter` / `v4_seat` / `v4_hatch` まで弾いた。置き方は PRINT.md §3 のとおり人が決める。

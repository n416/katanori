# 呼びかけ検知のロードマップ

「ロボットが、自分に話しかけられたと分かる」ための計画。
現状はレベル0（ボタン）で、これを**仮のOK**として先に進める。

関連: [firmware/esp32/README.md](../firmware/esp32/README.md)（実測値と計測モード） /
[仕様書.md](../仕様書.md)（3章・5章）

## 目指す姿（レベル100）

- **呼び名を自由に決められる。** 「カタノリ」でも「ねーねー」でも「なーロボ」でもいい。
  設定画面から変えられる（アプリ側 yorisoi-care-app と同じ体験）
- **テレビや家族の会話では起きない。** 装着者が自分に話しかけたときだけ反応する
- **曖昧なら聞き返す。** 人間と同じように「私ですか？」と返し、違えば黙って戻る
- ボタンを押す必要がない

## レベル

| Lv | 状態 | 判定の材料 | 現況 |
|---|---|---|---|
| 0 | ボタンで起動 | なし（人が押す） | **✅ 現在ここ。仮OK** |
| 10 | 声が聞こえたらクラウドで文字にして呼びかけか判断 | 音量 | 方式決定・未実装 |
| 30 | 装着者の声とそれ以外を機体側で切り分ける | 音量の倍率＋低域比 | 計測中（低域比が未検証） |
| 50 | 目線で確認する（音で起こして、目で確かめる） | ＋カメラ | 未着手（カメラ未搭載） |
| 70 | 曖昧なときは聞き返し、文脈で続きを判断する | ＋会話の文脈 | 未着手 |
| 100 | 呼びかけを意識せず会話が始まり、自然に終わる | 上記の総合 | — |

レベル0を仮OKとする理由: ボタンは確実に動く。ここで止まっても製品として成立はする。
以降は「話しかけるまでの一手」を減らしていく改善であって、作り直しではない。

## 要素1: 音声の聞き分け

肩乗りなので、装着者の口はマイクのすぐ近くにある。この距離差を使って
「装着者が喋ったか」を機体側で判定する。

### 実測で確定したこと（2026-07-26）

- **絶対音量は当てにならない。倍率で見る。** 騒音床が38〜469と12倍動いた
  （ReSpeaker側の自動音量調整）。倍率は安定しており、装着者が床の15〜58倍、
  隣にいる家族が4〜10倍
- **長さでは分けられない。** 装着者の5秒の発話と家族の0.2秒の相槌が、
  長さの判定では逆に出る。「呼びかけは短い」という当初の仮定は破棄
- **騒音床は追従させる。** 1回だけ測る実装では、部屋が騒がしくなった時点で
  「発話中」のまま固まり2分間無反応になった

### 未検証

- **低域比（近接効果）**。口が近いほど低域が持ち上がる。距離で決まる物理現象なので
  「遠くの大声」に騙されない。XMOSのノイズ抑制で低域が削られていると使えない。
  計測モードに実装済みで、静かな環境での実測待ち

### 測り方

`firmware/esp32/` を書き込んで、シリアルで `vad`。
`me` で【自分】【周囲】を切り替えながら交互に喋る。1分ごとに判定が出る。
音声はどこにも送らない。

## 要素2: 目線取得

肩の上を見る動作は、意図がないと起きない。テレビの音でも家族の会話でも起きない、
非常に特異的な合図になる。

### 組み合わせ方

カメラを回しっぱなしにするのはウェアラブルでは電力的に厳しい。

1. 声が聞こえた（音量ゲート、常時・軽い）
2. **その瞬間だけ**カメラを見る（数百ms）
3. こちらを見ていた → 反応する。見ていなければ黙る

こうすればカメラは1日数分しか動かない。しかも**クラウドへ送る前に判断できる**ので、
無関係な会話が外へ出ない。

### 着手前に確かめること

**ロボットを載せる位置にスマホを置いて2枚撮る。**
(1) 正面を向いたとき (2) ロボットを見たとき。
そもそも顔が写るのか、2枚が明らかに違うのかを見る。ここで駄目ならカメラを買っても解決しない。

### 分かっている障害

- **角度**。肩から見上げる構図。顔検出は正面顔で学習されたものが多く、認識されるか不明
- **社会的な見え方**。肩にカメラが載っていると周りが身構える。ローカル処理でもそう見えない
- **ハード**。XIAO ESP32S3 の Sense 版がカメラ付きで同じ形。ただし顔検出を動かすには
  ESP-IDF への移行が要る可能性が高い

## 検討して却下したもの

同じ議論を繰り返さないために残す。

| 案 | 却下の理由 |
|---|---|
| microWakeWord / WakeNet で「カタノリ」を学習 | 語を変えるたびに学習と書き込みが要る。「呼び名を自由に」と両立しない |
| ReSpeaker `ch0-asr/ch1-mww` ファームに載せ替え | ウェイクワードを検出しない。外部エンジン向けの音声を出すだけ。DFU版は48kHzで現構成と不一致 |
| Picovoice Porcupine（文字入力でカスタムワード生成） | 対応が Arm Cortex-M4 のみ。ESP32-S3(Xtensa)では動かない |
| ブラウザの音声認識モデルを載せる | 実体は数百MBのネイティブ部品かクラウド。ESP32とは桁が2〜3つ違う |
| 音源方向（DOA）で判定 | 4マイクの上位機(XVF3800)の機能。ReSpeaker Lite(2マイク)では取り出せない。I2Sから来るのは処理済み音声で自前計算も不可 |
| 発話の長さで呼びかけを判定 | 実測で逆に出た（上記） |

## 費用の目安

クラウドで文字にする方式にしても、費用は問題にならない。

- Cloudflare Workers AI `whisper-large-v3-turbo`: **音声1分 $0.00051**
- 無料枠: **1日10,000ニューロン ≒ 音声3.5時間ぶん**

装着者が喋った分だけ送るなら、1日数分〜数十分。無料枠に収まる見込み。
判断がCloudflare内で完結するため、呼ばれたと分かるまでGoogleへは何も送らない。

### 0. LCDの生存確認 ← **最優先。ここが通らなければ他は全部無意味**

モノクロLCDは消耗品で、寿命は2000時間前後。**譲り受けた個体は残り寿命が不明。**

1. **レジンバットを外す**（レジンは入れない）
2. 本体メニューの露光テスト機能で**画面全体を光らせる**
3. **ドット抜け・ムラ・暗い領域**が無いか見る

ここで異常があれば、LCDの交換（数千円）から始まる。**レベリングや露光テストを
先にやっても無駄になる。**

⚠ 直視しない。UV光。

手順: バットを外したままLCDにA4用紙を1枚敷く → プレートを付けて固定ノブを締める →

⚠ **Z=0 の設定を忘れると調整が全部消える。**

### ⚠ 底面が広い部品を直置きしない（2026-08-02・3回目の事故）

**起きたこと**: base（56 × 36mm の平面がまるごと接地）がプレートから剥がれず、
こじった結果 **ビルドプレートに金属の傷**が付き、**base のスタンドオフが2本折れた**
（突起を取っ手にして引っ張ったため）。

**印刷の成功しやすさと、取り外しやすさは逆を向く。** 底面積が大きいほど食いつきは強く、
ボトム35秒×5層で焼き付いている。「サポート不要で確実に刷れる」置き方は、
そのまま「一番剥がれない」置き方でもある。**1回目・2回目のゲージは薄板だったので問題に
ならなかったが、厚みのある実部品では通用しなかった。**

対策は2つ。

1. **プレートごと冷凍庫へ45〜60分。** 造形物を付けたまま入れると、金属と樹脂の収縮差で
   浮く（硬化した樹脂のほうが金属より縮むので、界面がずれる）
2. **角から攻めない。長い辺の真ん中から。** 角は肉が少なく、力が集中して欠ける
3. **突起を取っ手にしない。** 力は必ず底面の縁に、面で掛ける

#### 🔒 「10〜15分」「力が要るうちは冷却不足」は実機で反証された（2026-08-05）

⚠ **15分やって「全く変わらない」。**（ユーザー報告。同じ回に fittest の角が欠けている）

冷やす向き自体は合っているが、**プレートは金属で熱容量が大きく、15分では界面まで冷えない。**
表面が冷えただけで終わっている。**そして「効かない＝冷却不足」と決めつけない。**
15分で1mmも動かないなら、冷え方ではなく**接地面積の問題**を先に疑う（下の表）。

#### 🔒 「温めるのは逆効果」は誤りだった（2026-08-05・書いた直後にユーザーの指摘で撤回）

⚠ **ここには一度「温めるのは逆効果。樹脂のほうが膨張が大きく、界面が押し合う方向に
なる」と書いた。機構の説明が間違っている。**

膨張率の差が界面に作るのは**面に沿ったせん断**で、**縮んでも伸びても剥離の方向に働く。**
「押し合う」は起きない。**ネット上に「温めろ」という記事が多いのは、そちらも機構として
正しいから。** 片方だけを正解として書いたのが誤り。

そして、書いた時に見落としていたのはこちら:

| | 界面 | 部品そのもの |
|---|---|---|
| 冷やす | せん断が出る | ⚠ **樹脂が脆くなる。**こじった瞬間に欠けやすい |
| 温める | せん断が出る | しなやかになる。欠けにくい |

**冷やす方法には「これから力を掛ける部品を、いちばん脆い状態にしてから掛ける」という
副作用がある。** 2026-08-05 に fittest の角が欠けたのが冷却後だったことと話が合う
（⚠ 因果は未確認）。

⚠ **ただし、水洗いレジンに温水を直接かけない。** 未硬化の表面が水に侵される。
温めるならプレートの裏からドライヤー、または袋に入れて湯煎で、**造形物を濡らさない**。

⬜ **どちらが良いかは未確定。** 次に剥がすとき片方ずつ試して、ここに実測を書く。

#### 🔒 「光造形ではラフトが効かない」は書き方が誤りだった（2026-08-05・ユーザーの指摘）

⚠ **以前ここには「『ラフトで浮かせる』はFDMの作法で、光造形では効かない」と太字で
書いてあった。** 条件を後ろの小さい字に置いて、見出しに一般論を書いていたため、
**「光造形ではサポートで浮かせられない」と読める。** 実際にユーザーがそう受け取った。

- **効かないのは「ラフト単体」**（部品をラフトにベタ置き）。融着して一体になるだけ。ここは正しい
- **「サポート＋ラフト」は光造形の標準的な作法。** CHITUBOX に最初から入っている。
  **できないのではない**

**それでも直置きを選ぶ理由は、サポートが使えないからではない。** 枠のように
**壁が垂直な部品は、どの層も断面積が同じ**（`as5600_frame` は全層 585mm²）。傾けずに
浮かせると、1層ごとの剥離力を細いサポートの足だけで受けることになり、途中で落ちやすい。
傾ければ剥離力は下がるが、**上を向いた基準面が斜めに焼かれて精度を失う。**

→ **分かれ目は「底面が平らかどうか」ではなく、こちら:**

| | 直置き | サポートで浮かせる |
|---|---|---|
| 傾けてよい／断面が層ごとに変わる部品 | | ✅ 標準の作法 |
| 壁が垂直で、上面に精度の要る基準面がある部品 | ✅ | 傾けると基準面を失う |

✅ **当てはめた例: 卓上スタンドのトラス（2026-08-10）。** 丸棒だけで構成され、上を向いた
基準面が無い。**上の行＝サポートで浮かせる側**である。これを直置き（足の底 φ5.5 × 3 ＝
約70mm²）で刷ったところ、**床トラスがボロボロになった。**
✅ 確かなのはここまで（**サポート無しで刷った／床トラスが荒れた**）。
⚠ 「横に寝た棒が空中で島になったから」は AI の推論であって、確かめていない。
**「サポートを必要とする部品にサポートを付けなかった」だけで説明が付く。**
🔴 **⚠「傾ければ直る」も AI が根拠なく言ったもの。取り消す。** 傾ける理由として一般に
挙がるのは「1層あたりの断面積を減らす」「大きな平らな面を寝かせない」で、細い丸棒だけの
この部品には当てはまりが薄い。**島はサポートで潰すものであって、傾けて潰すものではない。**

🔴 **同日の失敗: 「足を下へ伸ばして浮かせれば良くなる」は逆効果だった。** 三角が
プレートから 0.57mm → 4.57mm へ上がり、浮き島の位置が高くなったうえ、全体が
φ5.5 の柱3本にぶら下がる形になって**前回より悪化した**。⚠ **AI が提案。**
造形中に何がその重さを支えるのかを見ずに「浮かせる＝良い」と考えたのが誤り。
足の切りしろに入れた溝も、いちばん力のかかる区間を細くするだけだったので取り消した。
⚠ さらにその後「棒の下にヒレを立てて接地面積を稼ぐ」という設計変更まで提案したが、
**この表を読んだ上でそこへ行ったのが誤り。** 部品の分類を先に当てはめること。

> 🔒 **「プレートの傷は造形に影響しない」は反証された（2026-08-05）。**
> 以前ここにそう書いてあったが、誤り。傷の**めくれた縁にレジンが流れ込んで焼き付くと
> 機械的なアンカーになり、部品はそこだけ剥がれずに、傷の真上で折れる。**
> 橋を溝→タブ→リブと3回設計変更しても折れ続け（同日6枚破損）、割れた位置を
> ユーザーが照合して傷と一致することを突き止めた。設計側の対策では直らないはずだった。
>
> 対処（この順で）:
> 1. **応急: CHITUBOXで部品を傷のないエリアに配置する**（配置＝プレート上の位置）
> 2. **恒久: プレートの研ぎ直し（傷のバリを均す）。** 耐水ペーパー#400を**平らな当て木**に巻き、
>    水研ぎでバリを「爪が引っかからない」まで落とす → #600〜800で全面を均一な梨地に。
>    **鏡面にしない**（食いつきが死ぬ）。**指で直接研がない**（面がえぐれる）。
>    ⚠ アルミ粉がバットに入るとFEPを突き破る。プリンタから離れて作業し、水洗→乾燥→IPA脱脂
> 3. 削った後は**レベリングとZ=0をやり直す**（手順2をもう一周）
> 4. **平面が崩れていないか確かめる。** 手順2の紙の抵抗を**中央と四隅の5点**で比べる。
>    中央だけ明らかに緩ければ**皿状に凹んでいる**（深い傷を追ったときに起きる）

#### 実施記録（2026-08-06）: #120→#600 で**4時間**。手研ぎは方法として遅すぎた

**とんでもなく深い傷**があり、除去に4時間かかった（ユーザー報告）。#120から入って#600まで。
上の手順2は「平らな当て木に巻く」までしか書いておらず、**小さい当て木を手で動かす**
読み方になっていた。**これが4時間の主因で、記録側の不足。**

⚠ **ただし電動サンダーは使わない**（ユーザーの感想は「電動でやるべきだった」。
**遅さへの不満は正しいが、道具の選択としては逆**）。オービタル・パッド式は面に追従し、
**押し圧の高い所を深く削る**。深い傷を狙えば傷の周りだけ凹む。光造形では
**プレートの平面がそのまま1層目の精度**なので、速いかわりに取り返しがつかない。

⬜ **速くて平面も出る方法（次回これで試す。⚠ この機体では未実施・一般的な擦り合わせの作法）**:
耐水ペーパーを**平らな基準面**（厚いガラス板・御影石タイル・定盤）にテープで貼り、
**プレートを裏返して面を下にし、8の字に動かす**。当て木を動かすのではなく、
**基準面を固定してプレートを動かす**。

- 面全体が一度に当たるので、小さい当て木より速い
- 基準面が平らなので**高い所から先に削れる＝勝手に平面が出る**（凹む方向に転ばない）
- プレート裏のボス・ノブがそのまま持ち手になる
- Mars 3 のプレートは 143 × 89mm。**A4サイズのガラス板1枚で全面が乗る**

### (1) 磁石ポケットのゲージ

[../hardware/magnet-fit-gauge.stl](../hardware/magnet-fit-gauge.stl)
（生成スクリプト: [../hardware/gen_magnet_gauge.py](../hardware/gen_magnet_gauge.py)）

内径 **3.8 / 3.9 / 4.0 / 4.1 / 4.2 / 4.3 / 4.4 / 4.5mm** のリング8個。

**8個は桟で1枚につながっている。** 1回目でピンを1本紛失したので、バラバラの
小部品にしない。桟は穴の縁から 0.35mm 逃がした位置に通してあり、穴を塞がない。
高さもリング（3.0mm）より低い 1.5mm なので、切り離したければニッパーで切れる。

**磁石が「少し力を入れると入り、ガタつかない」最小のリングの内径が、
そのままホルダーのポケットの設計値になる。**

これが効くのは、**ホルダーの設計に要るのが磁石の絶対径ではないから**。
必要なのは「どの設計値で穴を作れば刷ったときにこの磁石が嵌まるか」で、
それは磁石の公差と樹脂の縮みの**両方を含んだ値**でなければ意味がない。
ノギスで磁石だけを測っても、そこから縮み量を推定する一手間が残る。

桟に並んだ順が内径の順。**外径も内径と一緒に大きくしてある**ので、桟を切り離した
あとでも大小に並べ直せば順番が復元できる。

#### 結果（2026-08-02 未明）: **確定**

穴の大きい方からA〜Hと呼んだ（A=4.5 … H=3.8）。

| リング | 内径 | 結果 |
|---|---|---|
| D | 4.2mm | 嵌るが**逆さまにすると落ちる**（緩い） |
| **E** | **4.1mm** | **スポッと嵌り、逆さまでも落ちない** |

> **AS5600の磁石ポケットの設計値 = 内径 4.10mm**
> （レジン①・層厚0.05mm・露光2.5秒・ボトム35秒×5層）

**穴の縮み量も出た。** 硬貨の判定から磁石は公称φ4.0mmなので、**設計4.1mmの穴が
実寸4.0mm前後に焼き上がっている＝穴は約0.1mm縮む**。ノギスで測りたかった数字が、
現物合わせで直接出たことになる。

⚠ **この 0.1mm はレジン①・下の設定での値。** この設定を**恒久的に変える**（別の値で今後も刷る）なら取り直す。
**うっかり別設定で刷った回があっても、この表に戻せば数字はそのまま有効。** その場合の実害は
「別設定で刷ったその部品に、この数字が効いていない」ことだけ（2026-08-05: 初期層3層/25秒で
刷ってしまった回に「較正が無効になった」と誤読された。この行の書き方が原因）。

### この数字が成立する条件（CHITUBOX の設定）

**4.10mm も 0.1mm も「この設定で焼いたときの値」。** 設定を変えると寸法ごと変わる。

| タブ | 項目 | 値 |
|---|---|---|
| 印刷 | レイヤーの高さ | **0.050mm** |
| 印刷 | 初期層の数 | **5** |
| 印刷 | 露光時間 | **2.500s** |
| 印刷 | 初期層の露光時間 | **35.000s** |
| 高度設定 | **収縮補償** | **OFF** |
| 高度設定 | 許容範囲補償 / ボトム公差補償 | **OFF** |
| 高度設定 | アンチエイリアシング / 画像ぼかし | グレースケール（127〜255）/ 2px |

⚠ **収縮補償を絶対にONにしない。** 上の「穴は約0.1mm縮む」は**補償OFFで測った実測値**で、
設計値に手で足す前提になっている。ONにするとスライサーの補正と二重にかかり、
**穴が大きくなる**（4.2mm＝逆さで落ちる側へ寄る）。

### (2) 板バネ（片持ち梁）のゲージ

厚み **0.4 / 0.6 / 0.8mm** × 長さ **12 / 18 / 24mm** の **9枚**。根元は桟で固定。
並びは左から「0.4の短中長 / 0.6の短中長 / 0.8の短中長」で、長さの短中長が3回
くり返すので、その切れ目が厚みの境目になる。

**1回目の結果（8mmの短冊が「折れないが戻らない」）を受けた再試験。**
原因の候補が2つあるうち、**今回はレジン①のままなので、切り分けられるのは
形状（長さ）だけ**。それでも:

- 長い梁が**戻る** → 原因は形状だった。本番レジンならさらに良くなる
- 長い梁も**戻らない** → 原因は材料。レジン②か金属（リン青銅片）へ進む

と2つの仮説が切り分けられる（[KNOB-TROUBLE.md](KNOB-TROUBLE.md) の
「一度に1つしか変えない」に沿う）。

1回目との違いは**支持条件**。1回目はただの短冊を指で曲げただけで根元が固定されて
いなかった。今回は**根元を桟に固定した本物の片持ち梁**にしてある。

⚠ **刃は寝かせず「立てて」ある**（厚みが水平方向）。厚みをZに取ると、ボトム層
（35秒露光の5層＝0.25mm）が刃の大部分を占めてしまい、**過硬化した層の硬さを
測ることになる**。立てれば刃はどの高さも同じ露光で焼かれる。

### 結果（2026-08-02 未明）

見積り12分18秒。番号は太くて長い方から順に1〜9（実機で扱った呼び方）。

| # | 厚み × 長さ | 結果 | t/L |
|---|---|---|---|
| 1 | 0.8 × 24 | **戻る** | 1/30 |
| 2 | 0.8 × 18 | **戻る** | 1/22.5 |
| 3 | 0.8 × 12 | **戻る** | 1/15 |
| 4 | 0.6 × 24 | 戻らない | 1/40 |
| 5 | 0.6 × 18 | **戻る** | 1/30 |
| 6 | 0.6 × 12 | **戻る** | 1/20 |
| 7 | 0.4 × 24 | 戻らない | 1/60 |
| 8 | 0.4 × 18 | 戻らない | 1/45 |
| 9 | 0.4 × 12 | **戻る** | 1/30 |

> **設計ルール: レジン①でプリント一体の板バネを作るなら、厚み ≧ 長さ ÷ 30。**
> ⚠ **ただし刷りたてに限る。下の「翌日の再試験」を必ず読むこと。**

**t/L が 1/30 以上なら全部OK、1/40 以下なら全部NG。例外なし。** OKの下限3つ
（#1・#5・#9）は厚みも長さもバラバラなのに t/L がぴったり 1/30 で揃った。
**成否を決めているのは絶対寸法ではなく縦横比**と読める。

### 再試験（2026-08-03）— ❌ **同じ9枚が全部割れた**

上の試験から約1日半後、**同じ9枚**をもう一度押したところ、**押した瞬間にパキッと
全数破断**。前回「戻る」と判定された #1・#5・#9 も、いちばん太く短い #3（0.8×12・
t/L 1/15）も含めて例外なし。

**変わったのは形状ではなく時間。レジン①が経時で脆化した**（光造形のレジンは
刷った後も硬化が進む）。前回の試験は「一度押して戻るか」を刷った直後に見たもので、
**時間の経過は変数に入っていなかった**。

> 🔒 **結論: レジン①でプリント一体の板バネは作れない。**
> t/L の比率をどう取っても助からない（比率がいちばん有利な #3 も割れた）。
> これは前回の試験計画で立てた「長い梁も戻らない → 原因は材料」の判定そのもの。
> **レジン②（高靭性）か金属片（リン青銅など）へ進む。**

**教訓: 弾性部品の合否は「刷った直後」で判定してはいけない。** 数日置いてから
同じ試験をやり直すまでが1セット。硬さ・寸法は直後でよいが、**曲げるものは別**。

⚠ **この🔒の守備範囲は「弾性部品」だけ。** 「砕けた」「バリバリ」と言葉づかいが
似ていても、**未硬化の部品が剥がすときに割れる話は別件**（経時ゼロでも割れた実例が
ある。2026-08-05・lock）。破壊の言葉の一致を診断の証拠にしない。

⚠ **加える力は手で、揃っていない。** この 1/30 は「手で普通に押した範囲では戻る」
という意味。デテントの山の高さを決めるには、実際の山を付けて感触を見る一段が要る。

⚠ **これはレジン①（水洗い）の値。** レジン②（Ultra高靭性）ならもっと緩い比率でも
成立する可能性が高い。本番の板バネはレジン②で刷るので、そのとき取り直す。

**向きはSTLの時点で正しく回してある。** CHITUBOX で置き直さないこと。

設定はゲージのときと同じ（**レジン①・層厚0.05mm・通常2.5s・ボトム35s×5層**）。
磁石ポケット4.10mm はこの設定で確定した値なので、**設定を変えると嵌合が変わる。**

> 3つ同時に1枚のプレートへ並べてよい。`part="all"` の配置で干渉しないことは確認済みだが、
> **STLは別々に刷るほうが失敗を切り分けやすい**（1つ剥離しても他が残る）。

### 刷ったあとに見ること

| 見るもの | 判定 | 外したときの直し方 |
|---|---|---|
| 軸がブリッジの穴に入るか | 抵抗はあるが回る | `.scad` の `BORE_CLEAR`（現0.25）を ±0.1 |
| 磁石がポケットに嵌るか | 逆さで落ちない | ゲージで確定済み。落ちるなら露光を疑う |
| ほぞがベースに刺さるか | 手で押して入る | `PEG_HOLE_D` |

**嵌め合いの修正は `.scad` の1行**を変えて書き出し直す:

```bash
openscad -o hardware/knob.stl -D 'part="knob"' hardware/knob_jig.scad
```

⚠ **接着はしない。** 回転テストで駄目だったとき刷り直すので、ほぞは差すだけにする。

### 結果（2026-08-02）: **治具として成立。回転テスト合格**

測定結果は [KNOB-ENCODER.md](KNOB-ENCODER.md) の「治具の実測」。印刷側の教訓：

| 起きたこと | 原因 | 反映 |
|---|---|---|
| base が剥がれず、プレートに傷・スタンドオフ2本折れ | 広い平面の直置き＋細い丸柱 | 上の「底面が広い部品」の節。柱は小判形へ |
| 軸がブリッジの穴に入らない（削って通した） | 凸は太る・穴の入口はボトム層で縮む | `BORE_CLEAR` 0.40・入口逃がし |
| コネクタのスロット位置が外れ（手加工で窓に） | **説明書を流し読みし、ピンの位置とピンヘッダーのサイズを考慮し忘れた**（下の🔒） | 基板の下を丸ごと窓に変更。⚠ **それでも直っていない**（下） |

上の2件は嵌合で、**現物合わせでしか確かめられない**類のもの。3件目は違う。

### 🔒 コネクタの件は「ピンヘッダーを想定していない設計」だった（2026-08-03・ユーザーの訂正）

> **ここは以前「ピン位置を推定で決め打ちした」と書かれていた。過小評価だったので
> 書き換えた。** 推定を外した話でも、実物を測らなかった話でもない。

**ユーザーは、そこにピンヘッダーが立っていることを事前に説明していた。**
情報は在った。**にもかかわらず、ピンヘッダーが設計の構成要素として入っていなかった。**

証拠は `.scad` に残っている。スタンドオフ6mmを「**ピンの逃げ**」と書いていた
（[knob_jig.scad](../hardware/knob_jig.scad) の `STANDOFF_H`）。基板から生えている物を、
**空間を占める部品ではなく、下に空ける高さの数字**として扱っている。だから
コネクタのハウジングが入る体積も、線が曲がる余地も、最初から設計に存在しなかった。
スロットの位置が外れたのは、その結果として出てきた症状にすぎない。

**外形が合っていても、基板は板ではない。** 上にも下にも物が生えていて、
そこにコネクタが挿さり、線が出て、曲がる。

> **設計に入る前に、基板から突き出ている物を部品として列挙する。**
> 輪郭（外形・穴ピッチ）は列挙の対象の半分でしかない。
> 一覧は [DIMENSIONS.md](DIMENSIONS.md) の「突き出ている物」に置く。

#### ⚠ 窓に変えた後も直っていない（2026-08-03・ユーザー報告）

**いま使っている最終版でも、ピンヘッダーに対して窓がギリギリで、基板が少し斜めに
付いている。** 「基板の下を丸ごと窓にしたから、ピンがどこに生えていても通る」は
**成立していない。** ここは**未解決**として開けておく。

⚠ **これは治具の目的に直接効く。** 治具はAS5600の**同芯**のために作ったもので、
基板が傾けば磁石とチップの距離と平行が崩れる。[KNOB-ENCODER.md](KNOB-ENCODER.md) の
回転テストは合格しているが、**その数字は傾いた基板の上で取られている。**
AGCを紙で調整した経緯（`CHIP_GAP` を 1.5→1.1 に落とした）も、傾きと切り分けられていない。

次に刷るとき（治具でも筐体でも）に効かせること:

- 窓は**ピンヘッダーの外形＋ハウジング＋線の曲がり**に対して余裕を取る。
  ギリギリで通すのではなく、**当たらない寸法**にする
- **基板の姿勢は座（スタンドオフ）で決める。** コネクタやピンに触れて浮くなら、
  それは座が効いていないということ。基板が水平に乗っていることを組んだ時点で見る

⚠ **寸法表だけでは、この事故は防げない。** 外形と穴ピッチの行がいくら正確でも、
「ピンヘッダーが立っている」は外形の行にならない。**表に載らない物のほうが落ちる。**

治具の目的（同芯）自体は初回の印刷で達成している。

# 音声の核の手配線 — 引き継ぎ（2026-09-15）

統合基板（`hardware/pcb/katanori61_voice/`・v6.1 ＋ Voice PE の音声部・4 層）のうち、
**XU316・Flash・水晶・コーデック・アンプ・マイクの電源**の周りを、Voice PE の配線を手本に手で置いて手で引く。
残り（v6.1 の電源・ESP32・口・つまみ）は自動配線のまま。背景は `docs/VOICE-BOARD.md`（10 節が配置と配線の記録）。

- 🔒 ユーザー 2026-09-15:「ごっちゃごちゃ。簡単にショートしそう」→ 受動部品を小さくして規則を緩め、核は手で引く。
- 🔒 ユーザー 2026-09-15: 核の手配線は別のスレッド（「ReSpeaker回路の配線」）に任せる。

## 1. 誰が何を持つか

| ファイル | 持ち主 |
|---|---|
| `hardware/pcb/voice_core.py`（新規）と、それが読むデータ（置くなら `hardware/pcb/voice_core/` の下） | **配線スレッド** |
| `gen_pcb_voice.py`・`gen_sch_voice.py`・`route.py`・`dsn.py`・`check_sch_voice.py`・`core_check.py`・`katanori61_voice/`・`docs/` | 統合スレッド（katanori-a7） |

- 配線スレッドは **commit も push もしない**（統合スレッドがまとめる）。持ち物の外を直したいときは、統合スレッドへ頼む。
- 回路（ネット）は変えない。変えたいときは統合スレッドに言う（`check_sch_voice.py` の照合をやり直す）。

## 2. 区画

`gen_pcb_voice.CORE_REGION = (0.6, 0.6, 62.0, 17.0)`。

- **板の座標**: mm、原点は板の左前の角、x は右へ（板の長さ 82.024）、**y は後ろへ（Y 上向き）**、前の縁が y = 0（奥行 37.4）。
  図面（KiCad）の座標との変換は `gen_pcb.bx(x, y)`（原点のずれ `G.ORG = (40, 40)`、Y の向きを反転）。
- 区画の外（y > 17 と x > 62）には、統合スレッドが核以外の部品を置く。**区画の中には核の部品と下の固定物しか入らない**
  （`legalize` が区画を立入禁止にする）。
- 狭すぎたら、区画を広げる相談を統合スレッドにする（ESP32 は x 37.6〜57.1・y 16.9〜37 に固定。その左の y 17 より奥は v6.1 の電源）。

### 区画の中にある固定物（動かせない）

| 物 | 板の座標の枠 | 備考 |
|---|---|---|
| J2 画面の口（1x07・2.54） | x 35.47〜54.26, y 3.00〜6.54 | 貫通の足。ライザーの位置は筐体が決める |
| J15 マイクのライザーの口（1x05） | x −0.01〜13.71, y 10.04〜13.57 | 貫通の足 |
| 取付穴 J5 付近のナット | 中心 (4.0, 3.5)、半径 2.56 | 銅も部品も入れない |
| つまみの軸（区画のすぐ外） | x 62.2〜69.2, y 10.3〜17.3 | AS5600（U4）以外は入らない |

正確な形は `gen_pcb_voice.keepouts()` と `gen_pcb_voice.BOX` から取る（数字を写さず、import して読むこと）。

### 🔴 裏（B.Cu）に部品は置けない

**電池の影 x 16.05〜66.05・y 0〜31.4 は、裏に部品を置けない**（電池の上の隙間 2.0mm）。
配線と穴は構わない。Voice PE で XU316 の真裏にあったパスコン 16 個（とコーデックの FB8・C123・C144）は、
**表（F.Cu）でチップの周りに並べ直す**。核の部品は全部 F.Cu に置く（今の `gen_pcb_voice` も、裏の部品を鏡に映して表へ置いている）。

## 4. ネット

- ネット名は回路図が決める。**推測しないで板から読む**: `katanori61_voice.kicad_pcb` のパッドの `(net …)`、
  または `gen_pcb.netlist()`（`gen_pcb_voice` を import した後）。
- 名前の付け方（`gen_sch_voice.RENAME`）: `Net-(U2-XIN)` → `N_U102_XIN`、`+3V3`/`ESP_3V3` → `V33`、`+5V` → `V5`、
  `SPK+` → `SPKO`、`SKP-` → `SPKM`、`Net-(U1-GPIOn)` → `GPIOn`。GND と **GNDA は別のネット**（R175・R182 の 0Ω でつなぐ）。
- 核だけで閉じるネット: 62 本（**手で全部引く**）。
- 境界を越えるネット（25 本）: 核の中は手で引き、外へは自動配線がつなぐ。区画の縁まで線を出しておくと自動配線が楽になる。

| ネット | 核の外の相手 |
|---|---|
| GND | 全体（4 層のベタ・縫いのビア） |
| V5・V33・V18・V09 | 電源の部品（U111・L102 など）・ESP32・v6.1 の部品 |
| I2S_BCLK・I2S_LRCK・I2S_MCLK・I2S_DIN_ESP・I2S_DIN_SEC | 直列抵抗 R194・R193・R195/R246・R197・R196 → ESP32 |
| I2S2_BCLK・I2S2_LRCLK・I2S2_DATA・I2S2_MCLK | 直列抵抗 R192・R201・R202・R109/R246 → ESP32 |
| SCL・SDA | R228・R223・U3（INA）・U4（AS5600）・U5（ESP32） |
| AUDIO_PA_EN・MIC_MUTE・XU316_RST | U5（ESP32） |
| MUTE_ON | R48 |
| MIC_CLK_M・MIC_DATA_M・VDD_MIC | J15（マイクのライザー） |
| SPKO・SPKM | J5（スピーカーの口） |

⚠ 爆音対策の SHUTDOWN のネット（U109.1・R125.1・R135.2・C129.1）と PA_EN の側は、回路を変えないこと
（`check_sch_voice.py` の 3 番が見ている）。

## 5. 規則（`gen_pcb_voice.py` の頭）

| 項目 | 値 |
|---|---|
| 線の幅 | 0.2 を基本。細いピッチのパッドの手前だけ 0.15 まで（板の下限 0.15） |
| すきま（線・穴・ベタ） | **0.15**（`katanori61_voice.kicad_dru`） |
| パッドどうし | 0.12（足形そのものが狭い: XU316 0.146・U118 0.123） |
| 貫通穴 | **0.45 / 0.2 の F.Cu〜B.Cu 貫通だけ**（ブラインドやマイクロビアは無し。自動配線の取り込みが貫通しか書かない） |
| 層 | F.Cu（部品・配線）／In1.Cu（GND の面・なるべく切らない）／In2.Cu（配線と電源）／B.Cu（配線と GND） |

- Voice PE の値（線 0.156・すきま 0.125・穴 0.4064/0.2032）より太い。**写した線はそのままだと違反になる所がある**。
- 層の対応（Voice PE → この板、鏡に映して表へ）: B.Cu → F.Cu、In2（GND の面）→ In1（GND の面）、In1（電源）→ In2、F.Cu → B.Cu。
- GND のベタは統合スレッドが 4 層すべてに敷く（優先 0）。GNDA の島などは `zones()` で返す（優先 1 以上）。

## 6. `voice_core.py` の形

どれも**板の座標**（2 節）で返す。

```python
def place():
    """{ref: (x, y, 角度)} 部品の原点の位置。核の部品だけ。全部 F.Cu。"""

def tracks():
    """[(ネット名, 層, 幅 mm, [(x, y), (x, y), ...]), ...] 折れ線。層は "F.Cu" "In1.Cu" "In2.Cu" "B.Cu"。"""

def vias():
    """[(ネット名, x, y), ...] 大きさは 0.45 / 0.2 に決まっている。"""

def zones():            # 無くてもよい
    """[(ネット名, 層, [(x, y), ...], 優先), ...] 多角形のベタ（GNDA の島など）。優先は 1 以上。"""
```

- `gen_pcb_voice.build()` がこれを読み、部品は**固定**、線と穴は KiCad の板に書き、自動配線の DSN には
  **`(type protect)`**（自動配線が動かさない線）として渡す。
- ⚠ Freerouting 2.4.1 が protect の線を SES に返してくるか、`route.py` の `merge()` がそれを残すかは**まだ確かめていない**。
  最初に中身の入った `voice_core.py` が来たときに統合スレッドが確かめて直す。
- 手本の Voice PE: `hardware/ref/voice_pe/`（読むだけ。`voicepe.py` の `VoicePE` が読み込みの道具）。

## 7. 確かめ方

```bash
cd hardware/pcb
python core_check.py
```

- `build/core_check/` に板を書いて KiCad の DRC をかける（**`katanori61_voice/` は書き換えない**）。
- 出る物: 区画の中の違反（間隔・短絡・重なり・穴）と、**核だけで閉じるネットの未接続**。境界を越えるネットの未接続は数えない。
- 目標: 区画の中の error 0、核だけで閉じるネットの未接続 0。
- 絵は `kicad-cli pcb export svg`（`kicad_paths.CLI`）で `build/core_check/katanori61_voice.kicad_pcb` から描ける。

⚠ `gen_pcb_voice.py` を直接 `python gen_pcb_voice.py` で走らせると `katanori61_voice/` を書き換える。配線スレッドは走らせないこと
（統合スレッドが自動配線をかけている最中のことがある）。

## 8. 渡し方

1. `voice_core.py` がひと区切りついたら（区画の中の error 0・閉じたネットの未接続 0）、統合スレッドに知らせる。
2. 統合スレッドが、板に組み込んで自動配線（区画の外）→ DRC → `check_sch_voice.py` → commit。
3. 自動配線が区画の縁で詰まったら、どのネットがどこで詰まったかを返すので、縁の線の出し方を直す。

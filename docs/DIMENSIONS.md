## 🔒 この表の使い方（設計ルール）

### 起きた事故

つまみの卓上治具（2026-08-02・[PRINT.md](PRINT.md) 3回目）で3件やった。

| 起きたこと | 何を間違えたか |
|---|---|
| コネクタのスロット位置が外れ、手加工で窓に開け直した | **説明書を流し読みして、ピンの位置とピンヘッダーのサイズを考慮し忘れた** |
| 軸がブリッジの穴に入らず、削って通した | 凸は太る・穴は縮むという**印刷側の補正**を穴の設計値に入れ忘れた |
| スタンドオフが2本折れた | 長穴の向きの肉厚を**計算していなかった**（0.3mmしか無かった） |

**3件を一つの教訓にまとめない。** 原因が別々で、まとめると薄まる。
1件目は**在った情報を読み落とした**（ユーザーもピンヘッダーが立っていることを
説明していた）。2件目は**補正を入れ忘れた**。3件目は**計算しなかった**。
どれも「難しくて分からなかった」ではない。

⚠ **以前ここには「3件とも現物を当てずに数字を置いた」と書いてあった。**
事故を認識論の話へ格上げした書き方で、実際より上品にしていた。書き換えた
（2026-08-03・ユーザーの指摘）。

### 下の格付けが効く範囲

**上の3件には効かない。** 格付けが効くのは別の型 — **公称値をそのまま設計値にする**
事故（外形は📄で足りるが、穴の位置に使うと外す）。上の3件は、**在った情報を
使わなかった**型。**同じ表では防げないので、分けて持つ。**

⚠ **そして 2026-08-03、同じ読み落としをこの表を書きながらもう一度やった。**
公式ページに両面のピンアウト図があるのに、テキストの仕様表だけ見て
「面の割り当てはネットに無い」と書いた（下で訂正済み）。**一次情報を開いて、
最後まで見る。** 仕様表・図・写真は別々の情報で、表だけ読むのは流し読みと同じ。

### だから、数字に格付けを付ける

| 記号 | 意味 | 設計で許されること |
|---|---|---|
| ✅ | **実測** — 手元の現物で測った・嵌めて確かめた | **穴を置いてよい** |
| 📄 | **カタログ** — メーカー／販売ページの公称値 | **外形の当たり（入るか／どのくらいの箱か）まで**。穴は置かない |
| ⚠ | **推定** — 誰かが決め打ちした値。写真からの読みも含む | 設計に使うなら**長穴・窓・逃がし**にする |
| ⬜ | **未取得** | 使わない |

> **📄と⚠の上に、位置の決まった丸穴を置かない。**
> 逃げ方は治具でもう出ている — 位置が怪しければ**丸ごと窓にする**（基板の下を全部開けた）、
> ピッチが怪しければ**長穴にする**（±1mm 吸収）。**手加工で開け直すより、
> 最初から開けておくほうが安い。**

### 📄 を拾うときは一次情報から

⚠ **ここには一度「XIAOの外形は出どころによって 21×17.5 / 21.5×17.5 / 21×17.8 と
食い違う」と書いた。誤り。**
[Seeed の仕様表は **21 × 17.5 mm** の一つだけ](https://wiki.seeedstudio.com/xiao_esp32s3_getting_started/)。
食い違って見えたのは、検索結果に出たまとめサイトや販売店の記事を一緒に数えたから
（2026-08-03 訂正）。**公称値が当てにならないのではなく、公式を見ていなかった。**
ReSpeaker Lite の **35 × 86 mm** も同じで、公式の仕様表に最初から書いてある。

**📄 に採ってよいのは、メーカーの wiki・データシート・製品ページだけ。**
検索結果の要約や転載記事は数に入れない。

## 1.5 突き出ている物（外形の表に載らない）

**基板は板ではない。** 上にも下にも物が生えていて、そこにコネクタが挿さり、線が出て、
曲がる。**外形と穴ピッチだけを並べた設計で1回やらかしている**ので、輪郭と同じ扱いで
ここを埋める。

| 基板 | 生えている物 | 状態 |
|---|---|---|
| **ReSpeaker Lite** | ピンヘッダー7本×2列＋ワイヤー ／ XIAO ／ USB-C ×2 ／ スピーカー端子 ／ 3.5mmジャック ／ マイク ／ ボタン ／ パッド列 | ▶ **[RESPEAKER-LITE.md](RESPEAKER-LITE.md)** に面・端つきで全部ある |
| **AS5600 モジュール** | ピンヘッダー4本 ＋ Dupontハウジング | ⚠ ハウジング約14mm・幅10.2mm（`knob_jig.scad`）。位置は未取得のまま基板の下を丸ごと窓にして回避したが、⚠ **最終版でも窓がギリギリで基板が少し斜めに付いている**（未解決・[PRINT.md](PRINT.md)） |
| **XIAO ESP32S3** | USB-C ／ 両側のヘッダピン（ReSpeakerのソケットに刺さる） | ⬜ ReSpeaker上面からの高さが未取得 |
| **OLED** | 4ピンヘッダ ＋ 挿さるコネクタ | ⬜ |

**数えるのはコネクタ本体だけでは足りない。**

1. **挿さる相手のハウジング**（コネクタは挿すと伸びる）
2. **線が出て曲がる余地**（真横に折れない。曲げ半径のぶん空間が要る）
3. **抜き挿しする指**（一度組んだら触らない所か、繰り返し挿す所かで要る空間が違う）

⚠ **「ピンの逃げ」という書き方をしない。** 高さの数字に潰した瞬間に、
ハウジングと線が設計から消える。**部品として置く。**

## 4. 印刷の補正（穴を開けるときに必ず足す）

**寸法表と別に持たない。** 部品の寸法を筐体の穴に変換するのはここ。
全部 [PRINT.md](PRINT.md) の実測で、**レジン①・層厚0.05mm・通常2.5s・ボトム35s×5層・
収縮補償OFF** のときの値。

| | 値 | 使い方 |
|---|---|---|
| 穴の縮み | **約 0.1mm** | 穴系の**設計値に足す**（`SHRINK`） |
| 凸の太り | **約 0.1mm** | 軸などの外径から引く／隙間の見積りに入れる |
| 回る嵌合の遊び | **直径 +0.25mm**（✅2026-08-05 実測ばっちり） | 🔒 **入口逃がしとセットで成立**。逃がし無しの旧実測が「0.25では通らない」だったため一時0.40まで開けたが、ガタが出た（`BORE_CLEAR`） |
| 差し込み嵌合（ほぞ） | **ほぞ径 = 穴の設計値 − 0.25**（✅2026-08-05 穴3.35にほぞ3.1で確定） | 3.0はプカプカ・3.2は入らない（実測3点）。先端に面取り0.5を付ける（`PEG_FIT_D`/`PEG_TIP_C`） |
| ボトム層の過硬化 | 0.25mm（35s × 5層） | **プレートに接する面の穴は入口を逃がす**（+1.2mm × 深0.6mm） |
| 長穴の遊び | ±1mm（`SLOT_LEN` 2.0） | ピッチが📄・⚠のときの逃げ |
| 板バネ | 🔒 **レジン①では作れない** | 刷った直後は戻るが、**1日半で全数破断**した |

⚠ **設定を1つでも変えたら、この列は全部取り直し。**
⚠ **レジン①は経時で脆い。** 樹脂にネジを切らず、**M2は貫通＋ナット**にする。
（根拠は**板バネ試験1件だけ**＝薄肉0.4〜0.8mmを二次硬化後・1日半経過で曲げた話。
設計ルールとしてはこのまま使うが、**破壊の原因診断にこの行を前科として使わない** —
2026-08-05、未硬化のまま剥がすとき割れた部品が一度これで誤診された。経時ゼロで
割れているのだから経時脆化では説明できない、が正しい読み）

スタンドを立体で一発で刷ると時間がそのまま伸びる。平板を寝かせて刷る作法は
ここでも正しい。

## 4.6 見せる部品を刷るなら、レジン②へ（段階4が要る）

**プレゼンで使う前提なら、レジン①（水洗い灰・テスト用）では出せない。**
本番用は **SK本舗 Ultra 高靭性 白**（[PRINT.md](PRINT.md) の「手元にあるもの」）。

⚠ **ただし、レジンを替えると 4章の補正値が全部無効になる。**
0.1mm の縮みも、`BORE_CLEAR` 0.40 も、板バネの 1/30 も、**レジン①・この露光設定での
実測値**であって材料の性質ではない。[PRINT.md](PRINT.md) の **段階4（本番レジンの
露光時間出し）が未実施のまま**なので、そこを通してから、磁石ポケットのゲージを
レジン②で刷り直して数字を取り直す。

**脆さの問題もここで解決する見込みがある。** レジン①は経時で割れる（板バネ9枚が
1日半で全数破断）が、これは高靭性レジンへ進む根拠として [PRINT.md](PRINT.md) に
🔒で残してある判定そのもの。

### 🔒 スタンドに要るのは 35 × 86 と板厚だけ

⚠ **ここには一度「外形・取付穴・各コネクタの位置・マイクの位置を全部測る」と
書いてあった。要らない**（2026-08-03 訂正）。持ち方が決まると、必要な数字は激減する。

**基板は立てて、長辺の縁を溝で受ける。**

| 要らなくなった実測 | なぜ |
|---|---|
| コネクタが端から何mmか | **両方の短辺を丸ごと開ける**ので、位置を知る必要がない |
| マイクが端から何mmか | **マイク面は中央しか受けない**ので、端は最初から開いている |
| ピンヘッダーの位置 | **XIAO面には触れない** |
| 取付穴の位置 | 保持は縁で行う。ネジで姿勢を出さない |

| 数字 | 値 |
|---|---|
| 外形 | 📄 **35 × 86 mm**（公式仕様表） |
| **板厚** | ✅ **1.25 mm**（2026-08-03 ユーザー実測）。**標準の1.6ではない** |
| → 溝幅の設計値 | **1.50 mm** ＝ 1.25 ＋ 縮み0.1 ＋ 遊び0.15 |

**これで数字は揃った。** 板厚ゲージ（`board_gauge.scad`）は実測が出たので**刷らない**。

> **測る量は、持ち方が決まるまで確定しない。** 先に全部測るのは無駄になるし、
> 逆に、持ち方を決めずに数字だけ集めても設計は始まらない。

### 参考: 筐体（肩に載せる本番）まで行くと要るもの

**スタンドには不要。** 本番の箱を作る段になったら測る。

- OLEDモジュール（外形・パネルの窓・穴の有無）… 今はブレッドボードに挿してある

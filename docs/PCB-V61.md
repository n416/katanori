この資料は **「v6.1 の 1 枚基板に何が載るか」だけ**を持つ。板の外形・穴・口の座標は筐体（`hardware/case_v6_1.scad`）が
持っていて、ここには写した値と、それを板の座標へ直した値だけを置く。配線の進み具合は別の資料にする。

v6.1 の板は、v5 でバラバラだった **ハブ基板（ユニバーサル 44 × 81.2・54 部品）・PowerBoost 1000C・INA226 モジュール・

⭐ **2026-09-16 夕に右の帯へ移し、縦（トップ型 B2B-PH-K）にした。** 🔒 ユーザー「ケーシング作ったから垂直のがいい。結局一番穴は小さくなる」。

**置ける所は次の 4 つで決まった**（板の座標）:
- X 66.05 より右（世界 68.05 ＝ 電池の右端。ここより左は電池の抜け道）
- 床の柱 φ7 を外す（X 69.0〜76.0 × Y 0〜7.0 と 29.9〜36.9）
- 🔴🔴 **J10 は裏に付くが、はんだ足 2 本は表へ突き抜ける。** その足を
  ① 表の **J4 の胴**（Y 〜14.30）と ② **J4 に挿さったプラグ**（Y 14.30〜16.30 ＝ 胴 ＋ 2.0）の外へ出す
- **USB-C のシェルの足**（スルーホール・Y 20.63〜）を外す

②と④に挟まれた帯は **4.33** しかなく、パッドを Y へ並べる形（枠 5.5 × 6.9）は入らない。
⇒ **パッドを X へ並べた**（枠 6.9 × 5.5・角度 180）。枠 **X 73.00〜79.90 × Y 14.475〜19.975**。
足は J4 のプラグから **0.60**・枠は USB-C の足から **0.655** 空く。

⚠ その代償で、**極性の言い方が「手前／奥」から「左／右」に変わった**（8 章）。

②を最初に見落として 1 度置き、筐体側の `hit_wires`（1.17mm³ ＝ SPK IN の線が J10 の足に当たる）で見つかった。
基板側の検査は「表と裏は当たらない」で切り分けた所で**足を見ていなかった**ので、同日に
`gen_pcb.py` のプラグの通り道の検査へ「相手が裏なら、その**板を貫くパッド**だけを見る」を入れた。

📄 `hardware/ref/jst_ph/ePH.pdf` 1 ページに「With a mounting height of 8 mm ... in the top-entry version」とあり、
**トップ型は嵌合した高さが板の面から 8.0** ある。ナイロン版は板の裏が Z 12.0・床まで 12.0 なので、**4.0 余して入る**。

⚠ ただし帯の Z 7.0〜8.2 には電池のケーシングの天板が渡っている。**そこに窓を開けてもらうのが前提**で、
嵌合したプラグ（下端 Z 4.0）は天板を 3.0 突き抜けて下へ出る。窓は胴 6.31 × 4.91 ＋ 逃げ 0.5 で足りる（PHR-2 が胴の中に収まるため）。

⚠ 電池の真上は板の裏まで 6.0 しか無い（嵌合 8.0 が入らない）ので、裏の口は電池の外の帯にしか置けない。

🔴 **組む順**（縦にしたので変わった）: 電池を左の窓から入れて線を右の帯へ垂らす → **プラグを J10 に挿してから板を降ろす**
（下向きの口なので、板を据えてから下から挿す手は入らない）→ ねじ 3 本。PHR-2 は胴の中なので窓を通る。

**SPK OUT のプラグを抜く向きは −X（左の縁）**である。裏の口がサイド型だった時に、表の通り道と裏のパッドが
板の面で重なったので変えた。トップ型に戻った後も、筐体が −X で当たりを取り直して空なので、そのままにしている。

🔒 **電池はタブ（線の出る端）を**右**にして入れる。** タブは短い辺（35 の端）から出る（v4 の配置の記録・`hardware/parts/parts.scad`）。2026-09-16 夕に `BAT_RZ` 90 → 270（🔒 ユーザー「バッテリを Z 軸１８０度回転」）で、タブが世界 X 18.05（左）から 68.05（右）へ移った。J10 を板の右へ移したのと対。
🔒 **外形は渡された 82.024 × 37.4 が最大**で、広げない（ユーザー 2026-09-14）。

**リードとトグルは同じ EN と GND を並列に落とすだけ**なので、4 ピン 1 つにまとめた。
トグルは板には立たない。ハッチの板に付いて（世界 X 79.854・Z 24.05）、線 2 本で来る。
板の表から 14.45 上にあるので、板から立てる形にはできない（筐体 2026-09-14）。

前の縁の外は ReSpeaker の板（世界 Y 8.185〜10.035）まで 3.5 しか無いので、**前（−Y）向きの口は挿せない。**
後ろの縁は、柱の欠き 2 つと留めねじの頭 2 つを避ければ、板の外へ通り道を出してよい（殻の側で空けてもらう）。

## 4. 私が仮に決めた事

線の口を JST-PH 2.0 にした。ライザーは 2.54 のピンソケットで、足跡の奥行きは 2.54 と置いた。
リードとトグルを 1 つの 4 ピンにまとめた。
ミュートリレーを板の (56.3, 17.8)〜(71.6, 28.5) に置き、ここへ収めるために筐体の仮置きから前へ 2.0 動かした
（筐体が示した限界は 2.5 で、つまみの軸まで 0.5 残る）。この 2.0 は筐体へ伝えてある。
充電の USB-C は v6 と同じ **HRO TYPE-C-31-M-12（16P・LCSC C165948）**にした。足跡は
`hardware/frozen/v6/pcb/katanori.pretty/` にあり、胴は **8.94 × 7.30 × 3.26**・courtyard は 10.64 × 9.42 である。
筐体の一般値（8.94 × 3.26・奥行 7.35）とほぼ同じなので、殻の口は直さなくてよい。

🔴 **板の縁から出す長さが 2.6 を超えると、前のシェルの足 2 本（足跡の Y +1.05）が板から外れる。**
v6 は 3.0 出していたので足を 2 本省いた `NoFrontLegs` 版を作ったが、**v6.1 は 1.53 出しなので素の足跡（足 4 本）が使える**。
板の座標でいうと、胴が X 76.254〜83.554（1.53 が板の外）・パッドの芯が X 75.859・courtyard の内側の端が X 74.634 になる。

区画と口の地図は `hardware/pcb/v61_map.svg`（`python hardware/pcb/v61_map.py` で刷り直す）。
同じスクリプトが、区画・口・プラグの通り道 × 動かせない物 の重なりを数えていて、いまは 0 件である。

## 5. 次にやること

板の外へ出る物（口 5 つ・ソケット 2 つ・USB-C・AS5600・穴）は 2026-09-14 に全部決まり、筐体の模型にも入った。
USB-C の型番も 2026-09-14 に決まったので、**板の外へ出る物は全部決まった。**

板は 2026-09-14 に**配線まで通った**（DRC エラー 0・未接続 0）。道具は `hardware/pcb/` にある。

```
python hardware/pcb/gen_sch.py && python hardware/pcb/check_sch.py   # 回路図と突き合わせ
python hardware/pcb/gen_pcb.py && python hardware/pcb/route.py       # 配置 → 自動配線 → DRC
python hardware/pcb/fab.py && python hardware/pcb/check_fab.py       # 製造ファイルと、その検算
```

🔴 **発注の前に回すのは `check_fab.py`。** ガーバーとドリル（JLCPCB へ送る物そのもの）を
配置のコードとは別の道で読み、外形・電池の極性・取付穴・ライザーの穴を突き合わせる。

残っているのは発注だけで、ユーザーの判断で**来月**である。そのとき JLCPCB の在庫と区分と価格を取り直す
（2026-09-14 時点で AS5600（C79815）が LCSC で在庫切れ。DigiKey などには在庫があるので一時的と見ている）。

## 6. ライザーの受け方が 3 回変わった（2026-09-14）

最初は線（PH の横型）だった。次にライザーの板を立てることになり、板の側を **2.54 の縦のメスソケット**にした。
ところがこのソケットは背が 8.5 あり、ライザーの板の下端が世界 Z 18.1 になって、XIAO の下のメス（15.61）に
**2.49 届かなかった**（筐体が模型に入れて出した）。

🔒 ユーザー 2026-09-14「ライザーは裏から L 字の水平に出すソケットを付ければいけるか」で決着した。
**板の側はオスのピンヘッダ**（樹脂は板の上に 2.5 ほど）で、**ライザー側が裏面の L 字のメス**で受ける。

## 7. L 字のメスの寸法（2026-09-14・Sullins の .100 系のカタログ）

ライザーの裏面に付く **2.54 の L 字（右角）のメス**の寸法を、
[Sullins の .100" Female Headers のカタログ](https://sullinscorp.com/catalogs/101_PAGE114-115_.100_FEMALE_HDR.pdf) から取った。
1 列の右角（型番の 3 文字が `LGB`）は **.335" [8.50]（胴の長さ）× .100" [2.54]（胴の幅）・足 .124" [3.15]** である。

KiCad の `PinSocket_1x07_P2.54mm_Horizontal` は説明文に「8.51mm socket length」と書いてあり、この系列と同じ物である。
足跡の外形 10.03 は、胴 8.50 ＋ 足の曲がりの 1.53 に当たる。

⇒ **胴は板の面から 2.54 の厚みで寝ていて、接点の軸はその真ん中＝ 1.27**。
筐体が置いた「ライザーの板 1.6 ＋ 1.27 ＝ **2.87**」はこれで裏が取れた。
⚠ 残る仮定は「胴が板に密着して寝ていること」と「接点が胴の厚みの真ん中にあること」の 2 つで、
図面の断面までは読んでいない。型番を最終的に決めるときにもう一度当てる。

## 8. 🔴🔴 電池の口（J10）の極性 — 組む前に必ず読む

J10 は**板の裏**に付く。裏面の足形は KiCad の中で鏡になるので、表と同じ角度で置くと
口が逆（−X）を向き、2 つのピンの位置も入れ替わる。**2026-09-14 に置いたあとの座標を測って固定した。**

🔴🔴 **2026-09-16 夕に言い方が「手前／奥」から「左／右」へ変わった。前の手順書を見ないこと。**

| | 板の座標 | 板の上での言い方 |
|---|---|---|
| パッド 1 ＝ **GND（−）** | (**77.450**, 17.770) | **右**（USB-C の側） |
| パッド 2 ＝ **VBAT（＋）** | (**75.450**, 17.770) | **左**（つまみの側） |

左右は**板を表（部品の面）から見た**左右で、板の座標の X が大きい方が右である。
口（プラグの入る側）は **−Z ＝ 真下（電池の側）**。枠は X 73.00〜79.90・Y 14.475〜19.975。
この 2 点は `gen_pcb.py` の `CHECK_PADS` に入れてあり、**入れ替わると生成の時点で止まる**。
`check_fab.py` も、パッドが並んでいる軸を見て「右が GND ／ 左が VBAT」と刷る。

⚠ 並びを変えたのは好みではなく、**置ける帯が 4.33 しか無かったから**である（2 章）。
前後に並べる（角度 270）と枠 6.9 が Y に要り、J4 に挿さったプラグの下へ足が入る。

### 組むときの手順（🔴 通電の前に）

1. 電池のプラグは**色で判断しない。** 手持ちの PH の圧着ペアは規格が無く、噛み合わせると赤が黒に当たる個体があった（2026-09-11）
2. **電池のプラグの 2 本を、テスタの電圧レンジで当たる。** 3.7〜4.2V が出る側が ＋
3. その ＋ が **左（つまみの側）のピン**へ入る向きで挿す。右（USB-C の側）が GND
   ── 板を表から見て、**板の座標の X が小さい方が ＋**。⚠ J10 は板の裏なので、裏から覗くと左右が逆に見える
4. 挿したら、**通電の前に**板の上の VBAT と GND のあいだをテスタで当たり、ショートしていないことを見る

⚠ ここを逆にすると INA226 から煙が出る。2026-09-11 に実機で起きている（[POWER.md](POWER.md)）。

### ⚠ 用語 — 電源の略称（初出で開く）

| 略称 | 開くと | 何のことか |
|---|---|---|
| **`EN`** | **Enable** | 昇圧のオン/オフ端子。**GND に落とすと 5V 出力が止まる。** 基板側でプルアップ済みなので、何も繋がなければ常にオン。**リードスイッチとマスタートグルはここにぶら下がる**（2章） |
| `LBO` | Low Battery Output | 電池が減ると出る信号。稼働時間はこれが落ちるまでを測る（6章） |
| `VBUS` | — | USB から来る 5V（充電の入り口） |
| `VLIPO` / `VBAT` | — | 電池そのものの電圧（約3.0〜4.2V） |
| `5Vo` | — | 昇圧後の 5V 出力。ReSpeaker へ入れる側（5章） |
| `COM` / `NO` / `NC` | Common / Normally Open / Normally Closed | リレーと会話ボタンの接点。**NO＝ふだん開いている**（4.5章） |

⚠ **電源以外の略称はここに書かない。**`AGC`・`MD/ML/MH` は [KNOB-ENCODER.md](KNOB-ENCODER.md)、
`NVS`・`OTA`・`AEC` はファーム側の担当。

### ⬜ 案③ 電源の板を自分で起こす（2026-09-03・構想・未検証）

ハブ基板を JLCPCB のような PCBA で作るなら、PowerBoost と INA226 も同じ工程に乗せられる。
この場合、既製の板を探す問題ではなくなるので、上の①②とは別の道になる。

Adafruit は PowerBoost 1000C の回路図と EAGLE の .brd を公開している（[GitHub](https://github.com/adafruit/Adafruit-PowerBoost-1000C)。
[DIMENSIONS.md](DIMENSIONS.md) が寸法の出どころとして既に引いている）。したがって電源回路を
設計する必要はなく、写すだけでよい。中身は **TPS61090（昇圧）＋ MCP73871（充電・ロードシェア）**
の 2 個で、Type-C にするには micro-B のフットプリントを差し替えて CC の 5.1kΩ を 2 本足す。

**この案が成立すると、案①の弱点が 2 つとも消える。**

- 「2枚に基板を分ける」という否定（上の 2026-08-24）は、**既製モジュールを 2 枚買って箱に積む**
  話だった。bq24074 と昇圧 IC をチップとして 1 枚の板に載せるなら、板は 2 枚にならない。
- 「昇圧が 1A 上限」は MiniBoost という**製品**が TPS61023 を積んでいるからで、チップで選ぶなら
  現行と同じ TPS61090（内部スイッチ 2A）を置ける。⬜「決め手は実測のピーク」も、この経路では
  決め手にならなくなる。

JLCPCB はスルーホールも実装する。SMD と THT を 1 回の発注に混ぜられ、THT はフローはんだで、
追加費用は手はんだ工賃 $3.5 ＋ 1 ジョイント $0.0173、納期は SMT ＋1 日である。この板の口は
33 ピンなので、ヘッダと JST を全部載せて $4 ほどになる。発注に含めなかったスルーホールには
はんだが回らないので、一部だけ後付けにすることもできる。

#### ⬜ 板の分け方（2026-09-03・ユーザーの希望。決定ではない）

ユーザーは「2 基板に分けておきたい。1 枚でもいいがノコギリで切れるようにしたい」と言っている。
分け方は **「自作 PowerBoost ＋ INA226」の電源板**と、**今回作った中継基板（ハブ基板）**の 2 枚である。
1 枚のパネルに V カットを入れて出せば、割るか割らないかを後から選べる。

**リードスイッチとトグルは電源板側である。** どちらもスイッチだが、ネットは `EN` で、
PowerBoost の `EN` を GND に落とすために入っている（電源の口 `S6`＝`EN`、リード `S8`＝`EN`、
トグル `S12`＝`EN`）。したがって `EN` は電源板の中で閉じ、境界には出てこない。
逆に、もう一枚に残る唯一の「回路」はミュートリレーである（リレーの `COM` がスピーカー `IN(+)`、
`NO` が `OUT(+)`、駆動は `D3` → 1kΩ → 2SC1815。3章）。会話ボタンは `GND` と `D2` の 2 本なので、
中継せず XIAO へ直結できる。

境界を渡る線は **5 本**である。

| 線 | 出どころ（いまの口） |
|---|---|
| `5V` / `GND` | 電源の口（`S3` / `S5`。`S4` は空き。`S6` の `EN` は渡らない） |
| `3V3` / `SDA` / `SCL` | 電流計の口（`S17` / `S19` / `S18`。`S16` の GND は電源側と共通化） |

5 本のうち 2 本が I2C なので、**電源板は 5V を送るだけの板ではなく I2C バスの枝になる。**
INA226 のアドレスは実機で確認した `0x44` である（この章の後ろ）。

**電池の線は境界を渡らない。** 電池 → INA226 → PowerBoost が全部電源板の中で完結するので、
[CASE-V4.md](CASE-V4.md) の 🔴「電池の線は電池のタブから電流計の INPUT まで 1 本続きで、外れる所が
どこにもありませんでした」は、線ではなく銅箔になって消える。

V カットは回転刃が板の端から端まで一直線に走る加工なので、**2 枚は一本の直線で接する長方形**で
なければならない。L 字に食い込ませる分け方はできず、それをやるならルーターとミシン目になる。
切り離しを選べるようにするなら、カット線をまたぐ位置に 6 ピンのコネクタ跡を両側に置いておく。
1 枚のまま使うなら未実装でパターンがそのまま渡り、割るなら両側に実装してジャンパで繋ぐ。

⚠ **この案も現物は見ていない。** TPS61090 / MCP73871 / bq24074 が LCSC の在庫にあるか（Basic か
Extended か）と、JLCPCB の V カットの寸法規則は、まだ確かめていない。

### ReSpeaker Lite 側の事実

| 項目 | 内容 |
|---|---|
| 入力 | **5V必須。** USB-C ポートと基板上の外部5V給電パッドの2つだけで、3.3V/3.7V を直接入れる口は無い |
| 充電機能 | **無い。** 5Vをもらって動くだけの基板で、電池コネクタも充電ICも載っていない |
| 消費電流 | **非公開。** ReSpeaker Lite も XMOS XU316 も数値が出ていない |
| XIAO の給電 | ボード側から給電される。XIAO 自身の USB-C は書き込み用に別にある（USB-C は2つある） |

**リポで動かすなら昇圧が要る。** 電池3.7V → 昇圧5V → ReSpeaker の5V、という経路になる。

### XIAO の充電回路は使わない

XIAO は充電回路を内蔵しているので「電池を XIAO に繋いで XIAO の USB-C で充電」が一見いちばん
簡単に見えるが、採らない。理由は3つある。

1. 🔴 **充電電流が 100mA しかない。** これが決定的で、本機の消費は待機でも 200〜300mA あるため、
   **繋ぎっぱなしでも充電が追いつかず減っていく**
2. **書き込み用の口と兼用になる。** パソコンに挿すとシリアルとして認識され、DTR/RTS で再起動が
   かかる（`monitor_dtr = 0` を入れているのはそのため）。利用者が充電のつもりで挿す口としては危うい
3. **充電経路が2つになる。** 昇圧のために電池は外付け回路へ繋ぐので、XIAO 側でも充電すると
   同じ電池に充電器が2つぶら下がって制御が競合する

昇圧とパススルーは外付けで用意することが確定しているので、充電もそこへ寄せる。

### PowerBoost 1000C のピン

✅ **実物で確認した（2026-08-14・ユーザーがシルクを読み上げ）。** 下辺に1列8ピン・2.54mmピッチ。
基板の外形は **36.2 × 22.86mm**（USBコネクタは外へはみ出す）。

```
5Vo  GND  LBO  GND  EN  Vsh  LiPo  USB
```

⚠ **GND は 2 本ある。使い分けはこれだけ**: `5Vo` の隣の GND は 5V 出力と対。`EN` の隣の GND はリード／トグルの戻りと対。

| ピン | 役割 | この機体での使い道 |
|---|---|---|
| `5Vo` | 昇圧出力。**約5.2V**（5.0Vちょうどではない） | ReSpeaker への給電 |
| `GND`（5V側） | 上と対のグランド | 同上 |
| `LBO` | 🔴 **既定で BAT にプルアップされている。** 電池が3.2Vを切ると0Vに落ちる | 下記 |
| `GND`（EN側） | 電池・スイッチ側のグランド | リード／トグルの戻り |
| `EN` | 既定でVSへプルアップ。**GNDに落とすと昇圧が止まる**（消費20µA） | リードスイッチ＋トグルの両方 |
| `Vsh` | ロードシェア出力。充電中は約5V、それ以外は電池電圧 | **使わない** |
| `LiPo` | JSTに直結（3.0〜4.2V） | **使わない**（電池はJSTへ直結する） |
| `USB` | micro USB の5V。**充電用の入力で、出力ではない** | 利用者が挿す充電の口 |

充電は最大 1000mA で、1000mAh の電池なら1〜1.5時間。⚠ 充電しながら最大出力で使うと発熱する
ので、**USB電源は2A以上のものを使う**（Adafruit 注記）。

### 🔴 LBO を ESP32 に直結してはいけない

Adafruit のピン説明に "By default it is pulled high to **BAT**" とある。つまり LBO の H レベルは
5V でも 3.3V でもなく**電池電圧そのもの（3.0〜4.2V）**で、✅ 実測でも **4.06V** だった。
**ESP32 のピンは 3.3V までなので、直結すると壊す。**

⚠ **分圧抵抗では解けない。** プルアップ元が電池なので、**電池が減るとH側の電圧も一緒に下がる**。
満充電4.2Vで3.3V以下に収め、かつ3.2V（LBOが落ちる直前）で ESP32 が H と読む 2.48V 以上を保つには、
分圧比が **0.775〜0.786** の幅に入っていなければならない。**1.4% しか無く、5%品では作れない。**

解はトランジスタ1石で受けることで、こうすると ESP32 のピンには電池の電圧が一切かからない。

```
LBO ──[100kΩ]── B
                 2SC1815      C ──→ 空きGPIO（内部プルアップで読む）
                 E ── GND
```

- 電池が元気なうち＝LBO が H＝トランジスタON＝**GPIOはLOW**
- 電池が3.2Vを切ると＝LBO が 0V＝トランジスタOFF＝**GPIOはHIGH**
- ⚠ **論理が反転する。** ファームでは「HIGH＝電池切れ間近」と読む
- ⚠ 100kΩ を 10kΩ にすると待機が 350µA になり、つまみOFF時の 20µA を1桁上回る。**保管中に効く**

🔴 **ただし繋ぐ GPIO が無いので、この回路は宙に浮いている**（2026-08-14）。`D0`〜`D10` の11本すべてに
用途がある（[ARCHITECTURE.md](ARCHITECTURE.md)）。**電池残量は INA226 で読むことにしたので**
（6章）、**この回路は当面使わない。**

## 2. 電源の入切 — リードスイッチで切る・AS5600で予告する

🔒 **決定（2026-08-01）。つまみのOFFで完全に落とす**（20µA）。起動は数秒で済むので、疑似電源OFFで
待機電力を垂れ流す意味が無い。**トグルスイッチは非常用**で、日常では触らせない。

### なぜファームで EN を落とせないか

**「マイコンが EN を落として自分の電源を切る」は発振する。**

1. ファームが GPIO で EN を Low に引く → 2. 昇圧が止まり **ESP32自身も死ぬ** →
3. 死んだ GPIO は Hi-Z → EN は基板上で VS へプルアップされ **High に戻る** →
4. 昇圧が再起動 → ESP32 が起動 → つまみは OFF 位置のまま → 1へ戻る

AS5600 化で OFF が「角度の閾値」になったことで、これは致命的になった。可変抵抗の連動スイッチなら
接点が機械的に Low を保持できたが、**角度はファームでしか読めず、そのファームが死ぬ。**
電源ゼロの状態から ON に戻す主体がいない。

### 解: リードスイッチを EN⇔GND に入れる

**電源が無くても効く部品**でなければならない。ホールICは電源が要るので使えない。リードスイッチは
**磁石で閉じる無接触・無電源の接点**で、この条件を満たす唯一の現実的な選択肢である。

```
つまみOFF位置 → 磁石がリードスイッチに近づく → 接点が閉じる → EN=GND → 完全停止(20µA)
つまみを回す  → 磁石が離れる → 接点が開く → ENがプルアップで復帰 → 数秒で起動
```

🔒 **保持は機械（磁石）が担うので発振しない。ファームは EN に触らない**＝GPIO での EN 制御は
実装しない。

### ミュートの順序は AS5600 が担保する

リードスイッチが直接 EN を切るだけでは、再生中にブツ切りになって轟音の穴を踏む。そこを
**絶対角度センサだからできる形**で埋める。**リードスイッチが閉じる数度手前に、ファーム側の
ミュート閾値を置く。**

| 角度 | 起きること | 担当 |
|---|---|---|
| OFF手前（数度） | ミュート・会話終了・停止処理 | ファーム（AS5600の角度） |
| OFF位置 | EN=GND・完全停止 | リードスイッチ（磁石） |

つまみは連続的に回るので、角度が閾値に入った時点で走り切ってから、数度あとに電源が物理的に
落ちる。**順序が構造的に保証される。**

### ✅ 角度差の実測（2026-08-17・つまみを組んでテスタで当てた）

| 項目 | 値 | 出どころ |
|---|---|---|
| リードの境界（OFF位置から） | **約15度** | 📷 写真からの読み取り。つまみの印の向きで測定 |
| ヒステリシス（開く角度と閉じる角度の差） | **見えなかった**（同じ角度） | ユーザー実測 |
| ファームのミュート閾値 `KATANORI_KNOB_OFF_DEG` | **5 → 25** に変更 | 上の実測から。余裕 10度 |

🔴 **既定の 5度 のままだと順序が逆だった。** リードは 15度 で閉じるので、ファームが
まだ鳴らしている 15〜5度 の区間で EN が落ちる。狙っていたフェードが効かず**ブツ切り**になる。
閾値は**リードより外側（角度の大きい側）**でなければ意味がない。

🔴 **この境界を「実機で `knob` の相対角度を見て詰める」ことはできない。**
一度そう書いたが成立しない（2026-08-17・ユーザーが却下）。
- **落ちる経路そのものを通した測定になっている。** 電源が落ちた時点で観測側も死ぬので、
  最後に出た1行がいつの角度なのか決められない
- `OFF_DEG` より内側では `pct` が 0 のまま動かず、**そもそも表示が更新されない。**
  出てくるのは閾値の 25度 であって、リードの境界ではない（自分で入れた数字を読むだけ）

✅ **正しいのは、いま採った方法そのもの。** テスタをリードの足に直接当てる測り方は、
電源にも ESP32 にも依存しない**独立した観測**になっている。
残る誤差はリード側ではなく**角度の読み取りが写真であること**だけなので、詰めるなら
つまみの向きの測り方（分度器など）を上げる。⚠ 余裕を 10度 取ってあるので、
±数度 の読み取り誤差はこの閾値を揺らさない。

🔒 リード用磁石の座る高さは刷り直しでも据え置いてある（`knob_v5.scad` の `MAG2_SEAT_Z`）。
**この 15度 は刷り直しても持ち越せる。**

⚠ **これで塞がるのは「つまみを回して切る」経路だけ。** 再生中の電池切れ・クラッシュ・
ウォッチドッグ・ブラウンアウトは守れない（3章のミュートリレー）。

### ⚠ チャタリング対策の 0.1µF は EN⇔GND に入れる

リードスイッチは接点が閉じる瞬間に数回跳ねる（実測仕様で**バウンス0.6ms**前後）。EN に直結すると
昇圧が1ms弱パタつき、ブラウンアウトで中途半端なリセットを踏む余地が残る。**EN⇔GND に 0.1µF を
1個入れる。**

⚠ **効いているのは立ち上がり側である**（2026-08-14 訂正）。リードが閉じる瞬間はコンデンサがスイッチで直接放電
されるので**立ち下がりは鈍らない**。効くのはそのあとで、**跳ねて一瞬開いたときに EN が復帰しきらない**
ことによる。EN は基板の中でプルアップされているので、開いている間の立ち上がりは
τ＝プルアップ抵抗×0.1µF で鈍る。バウンス0.6msに対して十分に遅いので昇圧は再起動しない。
**この機序なので、容量を減らすと効かなくなる。**

### ⚠ 磁石が2つになる（AS5600 への干渉）

**これがこの方式でいちばんの risk。** AS5600 は軸上の磁石の**磁界の向き**を読んでいるので、
リードスイッチ用の磁石が近いと角度がずれる。AS5600 の磁石は**軸の中心**、リード用の磁石は
**つまみの外周**へ置いて距離を稼ぐ。ずれたかどうかは `STATUS`(0x0B) の MD/ML/MH と `AGC`(0x1A) を
見れば数字で分かる（[KNOB-ENCODER.md](KNOB-ENCODER.md)）。

### トグルスイッチ（非常用）

**リードスイッチと並列**に、同じ EN⇔GND へ入れる。どちらか一方でも閉じれば止まる。つまみが
どの位置にあっても、ファームがハングしていても落とせる。

> 「なにがあっても落ちる」を突き詰めるなら電池の JST 線を切る手もあるが、PowerBoost では
> **そこが充電器と共用**なので、OFF のまま充電できなくなる。EN を落とせば TPS61090 が停止するので、
> 実用上はこれで足りる。

🔒 **EN の節点はハブ基板に載せる。** `EN` ⇔ `GND` には**リードスイッチ・マスタートグル・0.1µF の
3つが並列に入る**ので、板の上に節点を作って、外に出る2つはコネクタで受ける。

## 3. ミュートリレー — 耳を守る仕組みをソフトに依存させない

🔒 **決定（2026-08-03）・実装と実機合格（2026-08-08）。**
アンプ出力とスピーカーの間にリレーの接点を入れ、**無通電で開**（ノーマルオープン）にする。
閉じるのはファームが起動し切ってから。

**決め手は再生中の電池切れである。** アンプの消費がピークなのは喋っている最中なので、電池が
力尽きるのも「よりによって再生中」になる。しかも電圧が落ちきらない領域では **ESP32だけが
ブラウンアウトでリセットを繰り返し、コーデックは通電したまま解除状態を保持する**ため、
ROMブートログの爆音が連続で出るループに入り得る。爆音自体がさらに電流を食うので悪化方向に回る。
**肩に載る＝耳から数cm**でこれが起きる。2章の EN 制御が守るのは「意図した電源断」だけで、
この経路は守れない。

| 条件 | 理由 |
|---|---|
| ノーマルオープン（無通電で開） | ESP32のGPIOはリセット直後フローティング。駆動側にプルダウンを置き、**無電・リセット中・クラッシュ中は必ず開**にする |
| **ラッチングリレーは使わない** | 消費電流では有利だが、電源が落ちても閉じたまま保持する＝防ぎたい状態そのもの。ここは譲れない |
| 閉じるのは `setup()` の最後 | 落とすときは逆順（ミュート → リレーを開く）でポップを避ける。ただし非常時の保証はリレー単独で成立する |
| 駆動はトランジスタ経由 | GPIO直結では駆動できない。フライバックダイオードを入れる |

⚠ **コイルは動作中ずっと電流を食う**（5V 30〜50mA前後）。1000mAh の電池に対して無視できない量なので、
稼働時間の見積もりに必ず入れる。

### ファーム側の実装（`main.cpp` の `muteRelaySet()`）

| いつ | 何をするか |
|---|---|
| `setup()`（I2S初期化とコーデックのミュートの後） | 接点を**閉じる**。⚠ 行として最後ではない。最終行に置くと**Wi-Fi設定モードだけ音が出ない**（手前で return するため） |
| つまみOFF | **コーデックをミュート → 接点を開く**の順。逆にすると鳴っている最中に切れてポップが出る |
| つまみON | **接点を閉じる**（コーデックはミュートのまま＝乾いた開閉）。解除は `pumpOutputGate()` が鳴らす直前 |
| 意図した再起動・OTA | `muteBeforeRestart()` でミュートの後に開く |
| 音声の初期化に失敗 | **閉じない。** 鳴らせないのに繋ぐ理由が無い |

⚠ **このコードは異常時を守っていない。** 守っているのは基板側の 10kΩ プルダウンで、リセット・
書き込み中・クラッシュ・ブラウンアウトでピンが浮けば**接点は勝手に開く**。ファームは
「普段どおり動いているときに閉じる」だけを担当している。

### 回路

```
              +5V ●──────┬────────────┬──────────────┐
                         │            │              │
                       0.1µF     コイル 167Ω      1N4148
                        ═╧═      Y14H-1C-5DS     ───┬───  ← 帯(カソード)
                         │        (29.9mA)        ／ ▲ ＼    が +5V 側
              GND ●──────┘            │           ───┴───
                                      │              │
                                      └──────┬───────┘
                                             │
                                             ● C（コレクタ）
                                            ╱
   D3(GPIO4) ●────[ 1kΩ ]────●──── B ───┤  2SC1815-GR (NPN)
                             │            ╲
                             │             ● E（エミッタ）
                         [ 10kΩ ]          │
                             │             │
              GND ●──────────┴─────────────┘
```

```
  ReSpeaker Lite                                  スピーカー
   スピーカー出力(+) ●──── COM        NO ────────● (+)
                              ╲
                               ╳  NC ── 何も繋がない（開放のまま）

   スピーカー出力(−) ●───────────────────────────● (−)   ← こちらは切らない
```

**COM–NO を使う**（COM–NC ではない）。⚠ **これが安全の本体**で、コイルに電気が来ていない間は
接点が開き、スピーカーが物理的に切り離される。**NC に繋ぐと「電源が無いとき鳴る」回路になり、
安全が丸ごと裏返る。**

| # | 部品・端子 | 相手 |
|---|---|---|
| 1 | XIAO **`D3`(GPIO4)** | 1kΩ の片足 |
| 2 | 1kΩ の反対側 | 2SC1815 の **B（ベース）** |
| 3 | 10kΩ | **B ⇔ GND** |
| 4 | 2SC1815 **E（エミッタ）** | GND |
| 5 | 2SC1815 **C（コレクタ）** | リレーのコイル片側 |
| 6 | リレーのコイル反対側 | **+5V** |
| 7 | 1N4148 | コイルに**並列**。**帯(カソード)を +5V 側**、アノードを C 側 |
| 8 | 0.1µF | **+5V ⇔ GND**。板のどこに置いてもよい（下記） |
| 9 | リレー **COM** | スピーカー `IN(+)` コネクタ（4章） |
| 10 | リレー **NO** | スピーカー `OUT(+)` コネクタ（4章） |

⚠ 駆動ピンは **`D3`(GPIO4)** である。もともと `D10`(GPIO9) を選んでいたが、**`D10` は ReSpeaker 側が
XMOS の MCLK に使っていて、電源を入れただけでリレーが閉じた**（2026-08-08 実測で確定・
[ARCHITECTURE.md](ARCHITECTURE.md)）。🔴 **教訓は「ファームで未使用」と「電気的に空いている」は
別だということで、選んだピンは必ず実機で検証する。**

### 数字の裏取り（なぜこの定数か）

| 項目 | 計算 | 判定 |
|---|---|---|
| コイル電流 | 5V ÷ 167Ω = **29.9mA** | 2SC1815 の Ic max 150mA に対し余裕 ✅ |
| ベース電流 | (3.3V − 0.8V) ÷ 1kΩ = **2.5mA** | GPIO の負担として軽い ✅ |
| 必要な hFE | 29.9mA ÷ 2.5mA ≒ **12** | GRランクは hFE 200〜400。**深く飽和する** ✅ |
| 10kΩ が食う電流 | 0.8V ÷ 10kΩ = **80µA** | 無視できる ✅ |
| 接点に流れる電流 | 8Ω 2W → **0.5A rms** | 接点定格 1A 以内 ✅ |

🔴 **10kΩ（プルダウン）がこの回路で一番大事な部品である。** ESP32の GPIO はリセット直後・
書き込み中・クラッシュ中に**フローティング**になる。10kΩ が無いとベースが浮いてリレーが不定になり、
**守りたい状況でスピーカーが繋がる**。⚠ **10kΩ は必ずリレー基板側に置く**（ESP32側に置くと、
信号線が抜けたときにベースが浮く）。これで**線が外れても必ず開**になる。

**接点は「乾いた状態」で開閉する。** 順序が「コーデックをミュート → リレーを開く」なので、電流が
流れている最中に接点が切れることはない＝アークがほぼ出ない。定格1Aに余裕がある理由でもある。

### 0.1µF の位置は効かない

「パスコンはリレーの近くに」は一般論としては正しいが、**この回路では効かない。板のどこに置いてもよい。**

| | 数字 |
|---|---|
| 0.1µF が 5V で蓄える電荷 | **0.5µC** → コイルの 30mA なら **17µs** で尽きる |
| コイルの電流の立ち上がり | τ = L/R。信号リレーのコイルは数十〜数百mH なので **0.3〜3ms** |

**コイルが電源から電流を引く速さは、0.1µF が効く速さより2桁遅い。** インダクタ自身が di/dt を
抑えているので、近くに置いても遠くに置いても差が出ない。

🔴 **速い現象は 1N4148 の側にある。** OFF時の逆起電力は**コイル ↔ ダイオードのループに閉じ込め
られていて、コンデンサを通らない。** だから「**ダイオードは裏でコイルの直近**」という指定は本当に
効くし、「コンデンサをリレーの近くに」は効かない。⚠ この2つを混同しないこと。

⚠ **カチカチ発振（電源の落ち込み）に効くのも 0.1µF ではない。** あれは ms オーダーなので
**10〜100µF の電解**が要る。0.1µF を増やす方向は無駄である。

### 部品の向き

| 部品 | 向き |
|---|---|
| **2SC1815-GR** | ⚠ **平らな印字面を手前にすると左から E–C–B**（＝奥に向ければ B–C–E）。**EとBを逆にすると動かない。** 逆向きだと B–E が逆バイアスになるので**熱すら出ない**。見分け方は「**エミッタの足が GND に落ちているか**」 |
| **1N4148** | ⚠ **帯（カソード）が +5V 側。** 逆だとコイルを迂回して +5V→ダイオード→トランジスタが**短絡**になる。⚠ **このとき、トランジスタがOFFならコレクタが開放で電流が流れないので熱くならない。「鳴らない・熱くもない」を理由にダイオードを容疑から外さないこと**（2026-08-08 に半日溶かした） |
| **1N4148 の場所** | 🔴 **半田面（裏）で、コイルの2本に直接またがせる。** 表はリレー本体の下なので置けない。裏なら**ループ面積も最小**。⚠ **接点の2本に架けない**（接点をショートする） |
| **10kΩ** | 足が **GND** に落ちること ← ★安全の要 |

### 🔴 レイアウトの最優先条件は +5V と GND を離すこと

この板の `+5V` は**機体まるごとの電源**を運ぶ。PowerBoost からの 5V を板で受けることになったので、
行き先は「コイルと 0.1µF」ではなく **XIAO の 5V ピン（＝ReSpeaker 全体）が加わって約 0.5A** になる。

- 🔴 **`+5V` はレール（バス）にしない。点から点へ1本で引く。レールは GND だけ**
- 🔴 **`+5V` は表の被覆線で運ぶ。裏に長く這わせない**（GND と隣り合う距離を作らないため）
- 🔴 **`+5V` と `GND` を隣り合うパッドに置かない。** 2026-08-14 の作図中に PowerBoost の 5V を
  INA226 の GND の隣に置いてしまい、**検査が2件の赤で止めた**（`S13`–`S14` と `R13`–`R14`）

### 配線の規則

**斜めに通さない。交差させない。** perfboard では斜め線は裏で長さが読めず、交差はショートの温床。

- ジャンパは**縦か横だけ**。曲げるときは**直角**に折る
- **レールは半田面（裏）に裸のスズメッキ線、ジャンパは部品面（表）に被覆線。** 面が違うので、
  絵の上で1箇所だけ交差しても短絡しない
- 🔒 **裸のレールは通った穴を全部その電位にする。被覆線は両端しか繋がない。**
  だから節点へ寄せるのは被覆線で、レールで寄せると通り道の穴まで同じ電位になる
- **裸のレールどうしは交差できない**（触れたら短絡）
- 表はリレー本体とコネクタが場所を取るので、レールで埋めない

### 図の物理検査

図は動かすたびに検査が走る。**赤は物理的に成立しない、黄は成立するが作りにくい。**
🔒 **赤がゼロでなければ組まない。**

| 判定 | 内容 |
|---|---|
| 赤 | 1穴に導線2本以上 ／ 別ネットが1つの節点に繋がる（短絡） ／ 同じネットが2つ以上の島に分かれる（断線） ／ 被覆線の全長が10mm未満 ／ 端の剥き線の2穴以内に別ネットのパッド ／ 部品の胴が使用穴を覆う ／ ジャンパが胴の上を通る ／ 抵抗の足の折り返し余裕が2mm未満 ／ ブリッジが隣接していない ／ 板からのはみ出し |
| 黄 | ジャンパどうしの直交交差（被覆線なので短絡はしない） ／ レールの通る穴への挿し込み ／ 部品の胴が穴間より広い |

⚠ **短絡と断線は、宣言ではなく実際の繋がりから判定している。** 端子が宣言するネットを種にして、
レール・ブリッジ・ジャンパ・リレー内部結線をたどって伝播させ、1つのかたまりに2つのネットが
入れば短絡、同じネットが分かれていれば断線と出る。**「繋いだつもり」が図の上で潰せる。**

✅ **赤0・黄0**（2026-08-17 にユーザーが全面的に引き直した版。2026-08-20 にブラウザで再確認）。
OLED を行E へ、AS5600 を列25 へ動かして幹線を引き直したことで、**ジャンパどうしの交差もゼロになった。**

⚠ 初期レイアウトを書き換えたら HTML 内の `SAVE_KEY` の版数を上げる。上げないと前回の保存内容が
読み込まれて新しい初期値が出ない。

### スピーカーは基板の IN / OUT コネクタで受ける

🔒 **決定（2026-08-10・ユーザー指摘）。** `COM` から線を外へ出す形は採らない。基板の中で繋ぐのは
3本だけで、**`IN(+)` → `COM`**、**`NO` → `OUT(+)`**、**`IN(−)` → `OUT(−)`**（(−) は接点を通さず素通し）。

**なぜこの形でなければならないか。** この基板は「外へ出る線は全部コネクタで受ける」と決めてある。
狙いは**引っ張りをコネクタで受けて基板のパッドに掛けないこと**と、**抜き挿しで分解・交換ができる
こと**である。スピーカーは筐体側に付いて線が動く部品なので、`COM` に線を直付けすると引っ張りが
そのまま半田点に乗り、いずれパッドごと剥がれる。IN/OUT の2つを載せれば、ReSpeaker 側もスピーカー側も
コネクタ1本ずつで抜き差しでき、**完成しているスピーカーを切らずに済む。**

⚠ **この設計を最初から持っていなかったのが設計の欠陥である**（2026-08-10 ユーザー指摘）。
🔴 **「板に載らない」を「板に口が要らない」と読み替えると、その部品の口が設計から抜け落ちる。
部品を「載らない」に分類したら、そのぶん口を1つ数えること。**

🔒 コネクタは **PH2.0 2ピン**（ReSpeaker のソケットも同型）。⚠ **PH2.0 は 2.0mm ピッチで、
2.54mm 格子には素直に載らない**（2ピンなので足を開けば届く範囲）。⬜ トップ型かサイド型かは
現物合わせで、**サイド型にすると線が板と平行に抜けるので積み方向の逃げが約10mm浮く。**

🔒 **買った PH の圧着済みペアは、噛み合わせると赤と黒が入れ替わる**（2026-09-11 ユーザーが現物で指摘）。
オス側・メス側とも「黒が左・赤が右」で作られているので、片方を 180° 回して挿す＝**赤が黒に当たる**。
ペアのまま延長線にすると逆接になる。直すときは**片側だけ**ハウジングの窓から爪を起こして端子2本を抜き、
左右を入れ替える（両側やると元に戻る）。線の色は信用せず、電池をつなぐ前にテスターで当たること。

🔴 **これは事故として起きた。**2026-09-11 未明、このペアをそのまま電池線に入れて通電し、
**INA226 から煙が出て、PowerBoost が発熱した。**外して確かめた結果、被害はこの電池の経路だけで止まり、
ハブ基板・ReSpeaker・OLED・つまみ・Wi-Fi・音声は USB 給電で全部動いた（同日 02:31 のシリアルログ）。
この事故の直接の原因は、圧着ペアの色を配線の情報として扱ったこと。

✅ **同日 03 時台に切り分けた結果、焼けたのは INA226 の 1 枚だけだった。**PowerBoost は
発熱したが生きている（EN を外して電池を直結し、`5Vo` に **5.1V** を確認。LED も点灯）。
⚠ **「発熱した」「煙が出た」を死亡と書いたのは早すぎた。**PowerBoost は無事で、
INA226 も煙を見ただけで未検証のままである。試せる部品は試してから交換と書くこと。
同日 03 時台に電池駆動へ戻し、トグルの動作も確認できた。**確認できた被害は INA226 の 1 枚だけ。**

### 🔴 「PowerBoost は 5V を出しているのに機体が起動しない」の切り分け

2026-09-11 の復旧で 30 分使った。原因は **GND の DuPont が外れていた**こと。5V の線は
繋がっていたので、PowerBoost 側では正常な 5V が読めた。[配線の仕様](#配線の仕様)の
「DuPont は緩む前提の接続」の実例である。**電源が来ないときは 5V ではなく GND を先に疑う。**

測る順番はこれでよかった。同じことが起きたらこの順で切る。

| 測る所 | 出た値の意味 |
|---|---|
| ① PowerBoost の `5Vo` ⇔ 隣の GND（負荷を繋いだ状態） | 0V なら保護で止まっている。すぐ電池を外す |
| ② ハブの `XIAO` の口 1本目(5V) ⇔ 3本目(GND) | ここが 0V なら PowerBoost から板までで切れている |
| ③ ハブの `PWR` の口の 5V ピン ⇔ 板の GND | ①が5V・②が0V のとき、線か GND のどちらが切れたかが決まる |

⚠ **`PWR` の口は 4 穴で 3 本目が空きなので、3 本のハウジングが 1 つずれて挿さっても入る。**
測る前に「空きが 3 本目にあるか」を目で見ること。

### ✅ 煙が出た INA226 の切り分け（2026-09-11）

**アドレスは 0x40 ではなく `0x44`。**ファームに実装するときはこの値を使う。
I2C だけ繋いだ状態で機体は正常に起動し、バスも 3V3 も落ちなかった。
`INA` の口の並び（GND・3V3・SCL・SDA）は、この配線のまま応答したので **✅ 確定**。

⚠ **煙を出した個体と新品の差は、手元の道具では出なかった。**

| 検査 | 現品 | 新品 |
|---|---|---|
| I2C で応答（0x44） | ✅ | — |
| バスを止めない・3V3 を落とさない | ✅ | — |
| 外側 2 穴（+ 側・シャント） | 0Ω | 0Ω |
| 内側 2 穴（− 側） | 0Ω | 0Ω |

シャントは切れていない（切れていれば OL になる）。ただし DT10B では 0.1Ω を 0 と区別できないので、
**「切れていない」までしか言えない。**何が煙を出したのかは特定できていない。
🔒 **本番には新品を使い、現品は「2026-09-11 に煙が出た個体」と書いて分けておく。**

🔴 **口ごとに 4 本の並びが違う。OLED とつまみは逆順である。**

| 口 | 板の外から見た並び |
|---|---|
| OLED | GND ・ VDD ・ SCL（緑）・ SDA（黄） |
| AS5600（つまみ） | SDA（黄）・ SCL（緑）・ 3V3 ・ GND |

同じ 4 本で並びだけが逆なので、**挿し間違えても物理的には入る。**同じ夜、OLED がこの向きで
挿さっていて、①I2C バスが止まってファームがスキャンの途中で固まる ②向きを直すと 0x3C で応答するが
画面は真っ暗、という 2 段階の症状を出した。⬜ **どちらかの口の並びを揃えるか、逆挿しできない形にすること。**

### 配線の仕様

| 項目 | 仕様 |
|---|---|

## 5. 5V の受け口

**道は 1 本で、もう板に組んである。**

```
PowerBoost 下辺 8 ピンの 5Vo / GND(5V側) / EN
   → ハブ基板の PWR の口（5V / 空き / GND / EN・4 ピン）          … 線は ⑪（CASE-V3.md）
   → ハブの +5V ネット
   → ハブの XIAO の口（7 本）の 5V
   → XIAO のパッド列ヘッダの 5V ピン（＝ ReSpeaker の +5V ネット・公式回路図で確認）
```

ReSpeaker の外部 5V パッド（⑨）は**穴の無いランド 2 枚でヘッダが立たない**（[RESPEAKER-LITE.md](RESPEAKER-LITE.md) ⑨）ので使わない。
XIAO の 5V ピンは ReSpeaker の `+5V` ネットに直結（📄 ReSpeaker Lite v1.0 回路図 XIAO ブロック・14 番 → `+5V`。XIAO 側のネット名は `VBUS`）。

⬜ **残る判断は 1 つ**（[TODO.md](TODO.md) A-2）: このヘッダ経由（DuPont・分解できる）で行くか、外部パッドへ線を直に半田するか。**ユーザーが決める。**

### 🔴 制約: XIAO の USB-C と 5V がぶつかる

XIAO の 5V ピンは USB-C の VBUS に直結で、間にダイオードは無い（ショットキー D2 は VBUS → XIAO 内部の VIN 側にだけ入っている）。
⇒ **PowerBoost の 5.2V と PC の 5V が、この経路で直接ぶつかる。**

```
USB-C VBUS ──┬──────────────────→ 5V ピン（14 番）← ここへ PowerBoost の 5.2V が来る
             ├──[D2 ショットキー]──→ VIN ──[U3 降圧]──→ 3V3
             └──[U4 充電 IC]──────→ VBAT
```

🔒 運用で避ける: **PC に挿して書き込むときはマスタートグルを OFF**（昇圧が止まる）。
⬜ 外部パッド ⑨ と ReSpeaker 側の USB-C が `+5V` ネットにどう繋がるか（逆流防止の有無）は公開範囲の外で不明。

## 6. 消費電流・測定・INA226

### 見積もり（推定）

**実測していないので、あくまで桁を掴むための数字。** XMOS の消費が非公開なのが最大の不確定要素。

| 部品 | 会話中(推定) | 待機中(推定) |
|---|---|---|
| XIAO ESP32S3（Wi-Fi常時接続） | 100〜150mA（送信時は瞬間的に300mA前後） | 80〜120mA |
| XMOS XU316（音声処理） | 100〜150mA | 100〜150mA（**常時動いている**） |
| OLED | 10〜20mA | 10〜20mA |
| スピーカーアンプ（音量35%） | 50〜150mA | ほぼ0 |
| **合計（5V側）** | **約300〜450mA** | **約200〜300mA** |

⚠ **スピーカーは未接続の状態で見積もっている。** ここまでの動作確認は3.5mmジャックにイヤホンを
挿して行っており、アンプは一度も動かしていない。接続後に増える。

これを3.7Vのリポから昇圧（効率85%と仮定）して取ると、電池からは1.5倍ほど流れる。

| 電池容量 | 会話が続く時間 | 待機が続く時間 |
|---|---|---|
| 1000mAh | 約1.5時間 | 約2時間 |
| 2000mAh | 約3時間 | 約4時間 |
| 3000mAh | 約4.5時間 | 約6時間 |

⭐ **これを詰めるのに電流計は要らない。** 知りたいのは電流値そのものではなく「1000mAh で何時間
持つか」なので、**満充電から LBO が落ちるまで動かして時計を見る**のが一番直接的で、推定を挟まない。
会話させ続ける版と待機のまま放置する版の2回で、上の表の2列がそのまま埋まる。

⚠ **待機でもあまり減らないのが問題である。** XMOS は常時動いていて眠らない。「使っていない時間が
長い」使い方なら、待機電力が寿命を決める。だから2章の「つまみOFFで完全に落とす」が効いてくる。

🔒 **USB電流チェッカーによる測定は打ち切った（2026-08-14）。** 実際に試したが表示が 0W から動かず、
機体は確実に動いていた。この個体はスマホの充電具合を見る程度の精度の機材で、この機体の
1.5〜2.3W を切り分ける分解能を持っていない。**0W という表示から意味を読み取ろうとしないこと。
この線はもう追わない。**

### INA226 で読む

⭐ **代案として I2C の電力モニタを積む**（2026-08-14・ユーザー提案）。I2C にぶら下がるだけで
**ピンを1本も食わない**ので第1世代の構成のまま載り、**動かしながら消費電流が読める。**

🔴 **定番の残量計 MAX17048 は使えない。** I2Cアドレスが **0x36 固定で変更できず、つまみの
AS5600（0x36 固定）と正面衝突する。**

| 系統 | 部品 | I2Cアドレス | 判定 |
|---|---|---|---|
| 電圧だけ | ADS1115 | 0x48・空き | ❌ 消費電流が測れず、目的の半分が残る |
| **電圧＋電流** | **INA226** | **0x40〜0x4F から選べる・空き** | ⭐ **採用** |
| 残量% | MAX17048 | 0x36 ＝ AS5600と衝突 | ❌ 不可 |
| 残量% | LC709203F | 0x0B・空き | △ IC が生産終了扱いで入手が読めない |

✅ **実機の I2C アドレスは `0x44`**（2026-09-02）。`0x40` ではない。電流計の I2C 4 本を抜くと `0x44` だけが消え、挿すと戻ることで確かめた。読むコードはこのアドレスで書く。

✅ **同じスキャンに出る `0x42` は ReSpeaker の XMOS 本体**（`firmware/xmosver/src` に `kXmosAddr = 0x42`。リソースID `0xF0`・コマンド `0xD8` で版数が読める）。⚠ **起動直後の自動スキャンには出ない。** XMOS の起動が ESP32 より遅く、間に合っていないだけで、しばらく経ってから `s` を撃つと出る。

✅ **着荷済み（2026-08-24）。Amazon の INA226 モジュール `B0GDX2P81Y`（ネジ端子・¥893）。
現物の刻印は `R010` ＝ 10mΩ で確定**（[TODO.md](TODO.md) A-2）。決め手はネジ端子で、電流の経路に半田付けが要らないこと。

### 挿す場所は「電池と PowerBoost のあいだ」

**リポ電池と PowerBoost の電池入力のあいだに、直列に入れる。**

理由は、INA226 が読む「バス電圧」が**そこに入れたときだけ電池電圧そのものになる**からである。
5V の側（PowerBoost の出力）に入れると電流は測れるが、読める電圧は 5V レールなので電池の減り具合が
分からず、「電池残量」が別問題として残ってしまう。電池側に入れれば、**消費電流の実測と電池残量が
本当に1個の部品で片付く。** 充電中は電流が逆向きになるが、INA226 は符号付きで読めるので、
充電中か放電中かもそのまま分かる。

### 🔒 電源の 4 穴の極性は「内側 2 本が GND（−）・外側 2 本が +」

✅ **2026-09-10 ユーザー実測。** 5 ピンヘッダの `GND` ピンと大穴の導通で判定した（無通電。ヘッダのシルク
`VCC/GND/SDA/SCL/ALER` が唯一の確実な基準で、大穴側のシルクは読まなくてよい）。ヘッダと反対の短辺に
4 穴が一列に並び、**内側の 2 穴が − ・外側の 2 穴が +** である。

⚠ どちらの端が INPUT でどちらが OUT かは図面読みのまま（[parts.scad](../hardware/parts/parts.scad)
`ina_pwr_pins()`: `y < 10` が INPUT 側）。この並びが正なら 端から INPUT+ / INPUT− / OUT− / OUT+ になる。

🔴 **守るのは + と − だけ。INPUT と OUT は取り違えても壊れない。** どちらも同じシャントの両端なので、
逆に入れれば電流の符号が反転して読めるだけである（INA226 は双方向）。**+ と − を逆にすると、その先の
PowerBoost に逆電圧がかかる。**

✅ **線の割り込み方は JST の延長ケーブル**（2026-09-10 ユーザー「電池から、延長を繋いで、電流計の IN に
入れたい」）。電池付属のケーブルは切らず、延長を1本足してそちらを切って割り込ませる（失敗しても延長
ケーブルを捨てるだけで済む）。⚠ 延長は赤黒がハウジングの向きで逆に出ることがあるので、切る前に電池を
挿した状態で先端の電圧を測って + を確かめる（剥いた 2 本を触れさせないこと）。

### 🔴 音量の上限はソフトではなくアナログ側に置く

肩＝耳道から数cmで、8Ω 2W に一般的な感度を仮定すると 10cm で 105〜110dB SPL 台の概算になる。
基板側のアンプは5Wまで対応（Seeed wiki）で、スピーカーの定格2Wより大きいので、ソフトの音量
（既定35% = `gain_`）を上げすぎるとスピーカー側の定格を超えられる。

⚠ **既定の35%は3.5mmジャックにイヤホンを挿して決めた値である。** スピーカーを繋いだら音量は
取り直しになる。**最初は35%より下げてから鳴らし、耳から離した状態で確かめること。**

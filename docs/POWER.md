# 電源設計メモ

肩に載せて持ち歩くための電源をどうするか。
仕様書は「ReSpeaker Lite USB-C (5V給電)」としか書いておらず、電池の記述が無い。

**状態（2026-08-01）: ✅ 電池駆動は実機で動いている。** PowerBoost 1000C ＋ リポ
1000mAh で、スピーカーを鳴らしたまま**20分連続動作して問題なし**。
**「1Aで足りるか」はこれで決着**（下の見積もり表は、それ以前の推定として残す）。

残っているのは ①稼働時間の実測（電池容量の確定）②筐体への組み込み
③**EN制御の自己遮断問題**（下記・配線する前に決める）。

| 品目 | 実物 | 備考 |
|---|---|---|
| 充電＋昇圧 | **Adafruit PowerBoost 1000C** | TPS61090昇圧 + MCP73871充電。**ロードシェアリング内蔵** |
| 電池 | **リポ 3.7V 1000mAh** | 容量は実測前の暫定。稼働時間を見て決め直す |
| マスタースイッチ | **トグル MTS-102**（6A 125VAC・ON-ON） | EN⇔GNDに入れる。詳細は [SHOPPING.md](SHOPPING.md) |

PowerBoost 1000C の出力は **連続1000mA+**（内部スイッチ2A・ピーク制限約2.5A）。
20分の連続動作で電圧降下による再起動が起きていないので、**この使い方では足りている**。
残る余白は「音量最大を長時間」だけで、そこは実運用の音量（既定35%）を決めてから見る。

## 分かっていること

| 項目 | 内容 | 出典 |
|---|---|---|
| ReSpeaker Lite の入力 | **5V必須**。USB-Cポートと、基板上の「外部5V給電パッド」の2つだけ。3.3V/3.7Vを直接入れる口は無い | Seeed wiki |
| ReSpeaker Lite の充電機能 | **無い。** 5Vをもらって動くだけの基板で、電池コネクタも充電ICも載っていない。充電・昇圧・パススルーはすべて外付けで用意する | Seeed wiki |
| 消費電流 | **非公開。** ReSpeaker Lite も XMOS XU316 も数値が出ていない | — |
| XIAO ESP32S3 の給電 | ReSpeaker Lite に載る形で、ボード側から給電される。XIAO自身のUSB-Cは書き込み用に別途ある（USB-Cは2つある） | 実機 |
| XIAO のバッテリー | 裏面に BAT+/BAT- パッドがあり充電回路も内蔵。ただし出力は電池電圧（3.7V）で、**5Vを作る機能は無い**（5Vピンは入力） | Seeed |
| XIAO の充電電流 | **100mA**。この機体では使えない（下記） | Seeed |

**結論: リポ電池で動かすなら昇圧回路が要る。** 電池3.7V → 昇圧5V → ReSpeaker の5Vパッド、
という経路になる。XIAOはそこから給電される。

## 電源回路の要件

肩に載る組み込み前提。**モバイルバッテリー基板の流用は不可**（厚い・重い・USB-Aコネクタが無駄）。

| | 要件 | 理由 |
|---|---|---|
| 必須 | **パススルー（ロードシェアリング）** | 充電しながら使えること。これが無いと充電中は使えず、電池にも負担がかかる。※ こちらで載せる充電ICを選ぶ話。よく使われる安価なTP4056モジュールは負荷と電池が並列に繋がる作りでパススルーにならないため、これは選べない |
| 必須 | 5V昇圧 | ReSpeaker Lite が5V必須のため。1A以上（アンプのピークを含む） |
| 必須 | リポ1セルの充電（USB-C） | 利用者が触る窓口。XIAO側のUSB-C（書き込み用）とは別にする |
| 必須 | 物理スイッチ（**2種類は別物**） | ① 日常用＝つまみのOFF（EN制御・ソフト経由。ミュート→電源断の順序が保証され轟音の穴が塞がる）。② **マスタースイッチ＝ENをGNDに落とすトグルスイッチ**。①はファームが生きていないと効かず、電池搭載後はハング時に止める手段がこれしか無い。保管時の電池保護も兼ねる。**PowerBoost 1000C ではENを切っても充電回路は生きている**ので「OFFのまま充電可」も満たす。[TODO.md 1.電源](TODO.md#1-電源バッテリー) |
| 欲しい | 電池残量の取得 | ADCで電池電圧を読み、「充電してね」と喋らせる |
| 欲しい | 低電圧保護 | 過放電で電池を痛めない |

### 構成の候補

```
リポ ──┬─[充電IC＋パススルー]──VSYS──[5V昇圧]──> ReSpeaker 5Vパッド ──> XIAO
       │          ↑
       │       USB-C（充電）
       └──> ADCで電圧監視（XIAO）
```

- **試作**: **Adafruit PowerBoost 1000C（入手済み）**。充電・パススルー・昇圧が1枚に載る

  **✅ ピンの並びは実物で確認した（2026-08-14・ユーザーがシルクを読み上げ）。**
  下辺に1列8ピン・2.54mmピッチ。基板の外形は **36.2 × 22.86mm**（USBコネクタは外へはみ出す）。

  ```
  5Vo  GND  LBO  GND  EN  Vsh  LiPo  USB
  ```

  ⚠ **GND が2本ある。** `5Vo` の隣が5V出力側、`EN` の隣が電池・スイッチ側で、
  基板の中では1点でだけ繋がっている（回路図の注記
  "Both grounds must be connected on the PCB at only one point close to the GND pin"）。
  **5Vの出力は前者と対で、スイッチの戻りは後者と対で**使う。

  | ピン | 役割 | この機体での使い道 |
  |---|---|---|
  | `5Vo` | 昇圧出力。**約5.2V**（5.0Vちょうどではない） | ReSpeaker Lite の外部5Vパッドへ |
  | `GND`（5V側） | 上と対のグランド | 同上 |
  | `LBO` | 🔴 **既定で BAT にプルアップされている**。電池が3.2Vを切ると0Vに落ちる | 下記のとおりトランジスタ1石で受ける |
  | `GND`（EN側） | 電池・スイッチ側のグランド | リード／トグルの戻り |
  | `EN` | 既定でVSへプルアップ。**GNDに落とすと昇圧が止まる**（消費20µA） | つまみOFF（リードスイッチ）＋マスタースイッチ（トグル）の両方をここに繋ぐ |
  | `Vsh` | ロードシェア出力。充電中は約5V、それ以外は電池電圧 | **使わない** |
  | `LiPo` | JSTに直結（3.0〜4.2V） | **使わない**（電池はJSTへ直結する） |
  | `USB` | micro USBの5V。**充電用の入力で、出力ではない** | 利用者が挿す充電の口 |

  #### 🔴 LBO を ESP32 に直結してはいけない（2026-08-14・実測とデータシートで確定）

  Adafruit のピン説明に *"By default it is pulled high to **BAT**"* とある。つまり LBO の
  H レベルは 5V でも 3.3V でもなく、**電池電圧そのもの（3.0〜4.2V）**である。
  ✅ 実測でも **4.06V**（部分充電状態の電池電圧と一致）だった。
  **ESP32 のピンは 3.3V までなので、直結すると壊す。**

  ⚠ **分圧抵抗では解けない。** プルアップ元が電池なので、**電池が減るとH側の電圧も一緒に下がる**。
  満充電4.2Vで3.3V以下に収め、かつ3.2V（LBOが落ちる直前）でESP32がHと読む2.48V以上を保つには、
  分圧比が **0.775〜0.786** の幅に入っていなければならない。**1.4%** しか無く、5%品では作れない。

  **解: トランジスタ1石で受ける。** ESP32のピンには電池の電圧が一切かからない。

  ```
  LBO ──[100kΩ]── B
                   2SC1815      C ──→ XIAO の空きGPIO（内部プルアップで読む）
                   E ── GND
  ```

  🔴 **ただし、繋ぐ GPIO が無い**（2026-08-14 判明）。D0〜D10 の11本すべてに用途があり、
  最後の候補だった **`D0`(GPIO1) も実測で「使えない」と確定**した（何も繋がない状態で
  テスター10MΩを当てても3.3Vが動かない＝何かが固定している。`D10` と同じ穴。
  詳細は `firmware/esp32/src/main.cpp` の D0 の注記と [hardware/xiao_pinout.svg](../hardware/xiao_pinout.svg)）。
  **下の回路はピンが確保できた場合のもので、いまは宙に浮いている。**
  代案は「電源基板を既設の I2C にぶら下げる」だが、部品が1つ増えるため未決。

  - 電池が元気なうち = LBO が H = トランジスタON = **GPIOはLOW**
  - 電池が3.2Vを切ると = LBO が 0V = トランジスタOFF = **GPIOはHIGH**
  - ⚠ **論理が反転する。** ファームでは「HIGH＝電池切れ間近」と読む
  - 部品はリレー駆動段と同じ 2SC1815。待機電流は100kΩで約35µA（つまみOFF時の20µAに上乗せ）
  - ⚠ 100kΩを10kΩにすると待機が350µAになり、OFF時の消費を1桁上回る。**保管中に効く**

  - **パススルーの自作（Pch MOSFET＋ショットキー）は不要になった。** MCP73871が
    ロードシェアリングを内蔵しているため（[SHOPPING.md](SHOPPING.md) の自作案は削除済み）
  - 充電は最大1000mA。1000mAhの電池なら1〜1.5時間
  - 充電しながら最大出力で使うと発熱するので、**USB電源は2A以上のものを使う**（Adafruit注記）
- **製品化**: 充電IC（MCP73871 / BQ24074 などパススルー内蔵）＋ 昇圧IC を自前基板に載せる。
  筐体の形が決まってからでよい

### EN制御は「リードスイッチで切る・AS5600で予告する」（2026-08-01 決定）

**方針: つまみのOFFで完全に落とす**（20µA）。起動は数秒で済むので、疑似電源OFFで
待機電力を垂れ流す意味が無い。**トグルスイッチは非常用**で、日常では触らせない。

#### なぜファームでENを落とせないか

**「マイコンがENを落として自分の電源を切る」は発振する。**

1. ファームがGPIOでENをLowに引く → 2. 昇圧が止まり **ESP32自身も死ぬ** →
3. 死んだGPIOはHi-Z → ENは基板上でVSへプルアップされ **Highに戻る** →
4. 昇圧が再起動 → ESP32が起動 → つまみはOFF位置のまま → 1へ戻る

**AS5600化でOFFが「角度の閾値」になると、これが致命的になる。** 可変抵抗の連動
スイッチなら接点が機械的にLowを保持できたが、角度は**ファームでしか読めず、その
ファームが死ぬ**。電源ゼロの状態からONに戻す主体がいない。

#### 解: リードスイッチをEN⇔GNDに入れる

**電源が無くても効く部品**でなければならない。ホールICは電源が要るので使えない。
リードスイッチは**磁石で閉じる無接触・無電源の接点**で、この条件を満たす唯一の
現実的な選択肢（[KNOB-ENCODER.md](KNOB-ENCODER.md) にEC11案の控えとして調査済み）。

```
つまみOFF位置 → 磁石がリードスイッチに近づく → 接点が閉じる → EN=GND → 完全停止(20µA)
つまみを回す  → 磁石が離れる → 接点が開く → ENがプルアップで復帰 → 数秒で起動
```

**保持は機械（磁石）が担うので発振しない。** ファームはENに触らない＝GPIOでの
EN制御は実装しない。

#### ミュートの順序は AS5600 が担保する

リードスイッチが直接ENを切るだけでは、**再生中にブツ切りになって轟音の穴を踏む**
（[TODO.md](TODO.md) 3）。そこを**絶対角度センサだからできる形**で埋める。

**リードスイッチが閉じる数度手前に、ファーム側のミュート閾値を置く。**
つまみは連続的に回るので、角度がその閾値に入った時点で
「コーデックをミュート → 会話終了 → 停止」まで走り切ってから、
数度あとに電源が物理的に落ちる。**順序が構造的に保証される。**

⚠ **ただしこれで塞がるのは「つまみを回して切る」経路だけ。** 再生中の電池切れ・
クラッシュ・ウォッチドッグ・ブラウンアウトは守れない（下の**ミュートリレー**）。

| 角度 | 起きること | 担当 |
|---|---|---|
| OFF手前（数度） | ミュート・会話終了・停止処理 | ファーム（AS5600の角度） |
| OFF位置 | EN=GND・完全停止 | リードスイッチ（磁石） |

閾値のあいだの角度差は、**組んでから実測で詰める**（回す速さに対して処理が
間に合う幅が要る。ファーム側の処理はms、回す動作は桁違いに遅いので余裕はある）。

#### ⚠ リードのチャタリング（EN⇔GNDに0.1µF）

リードスイッチは接点が閉じる瞬間に数回跳ねる（実測仕様で**バウンス0.6ms**前後）。
ENに直結すると**昇圧が1ms弱パタつく**。ミュートは角度閾値で先に済んでいるので実害は
薄いが、ブラウンアウトで中途半端なリセットを踏む余地が残る。

**EN⇔GND に 0.1µF を1個入れておく。** 手持ちの積層セラミックで足りる。

⚠ **効いているのは立ち上がり側**（2026-08-14 訂正。以前ここに「立ち下がりが鈍って跳ねが埋まる」
と書いていたが、機序が逆だった）。リードが閉じる瞬間はコンデンサがスイッチで直接放電されるので、
**立ち下がりは鈍らない**。効くのはそのあとで、**跳ねて一瞬開いたときに EN が復帰しきらない**ことによる。
EN は基板の中でプルアップされているので、開いている間の立ち上がりは τ＝プルアップ抵抗×0.1µF で鈍る。
バウンス0.6msに対して十分に遅いので、昇圧は再起動しない。
**この機序なので、容量を減らすと効かなくなる**（時定数がバウンス幅を下回る）。

#### ⚠ 磁石が2つになる（AS5600への干渉）

**これが一番の risk。** AS5600 は軸上の磁石の**磁界の向き**を読んでいるので、
リードスイッチ用の磁石が近いと角度がずれる。

- AS5600の磁石は**軸の中心**、リード用の磁石は**つまみの外周**へ置いて距離を稼ぐ
- ずれたかどうかは `STATUS`(0x0B) の MD/ML/MH と `AGC`(0x1A) を見れば数字で分かる。
  **診断コマンドが無いと「なんとなく合わない」で詰まる**（[KNOB-ENCODER.md](KNOB-ENCODER.md)）

#### トグルスイッチ（非常用）の位置

**リードスイッチと並列**に、同じ EN⇔GND へ入れる。どちらか一方でも閉じれば止まる。
つまみがどの位置にあっても・ファームがハングしていても落とせる。

> 「なにがあっても落ちる」を突き詰めるなら電池のJST線を切る手もあるが、PowerBoost
> では**そこが充電器と共用**なので、OFFのまま充電できなくなる。ENを落とせば昇圧IC
> （TPS61090）が停止するので、実用上はこれで足りると判断する。

#### 🔒 スピーカーのミュートリレー（2026-08-03 決定・**2026-08-08 実装＋実機合格**）

**ファーム側の実装（`main.cpp` の `muteRelaySet()`）**

| いつ | 何をするか |
|---|---|
| `setup()`（I2S初期化とコーデックのミュートの後） | 接点を**閉じる**。⚠ 行として最後ではない。最終行に置くと**Wi-Fi設定モードだけ音が出ない**（手前で return するため） |
| つまみOFF | **コーデックをミュート → 接点を開く**の順。逆にすると鳴っている最中に切れてポップが出る |
| つまみON | **接点を閉じる**（コーデックはミュートのまま＝乾いた開閉）。解除は `pumpOutputGate()` が鳴らす直前にやる |
| 意図した再起動・OTA | `muteBeforeRestart()` でミュートの後に開く |
| 音声の初期化に失敗 | **閉じない。** 鳴らせないのに繋ぐ理由が無い |

⚠ **このコードは異常時を守っていない。** 守っているのは基板側の 10kΩ プルダウンで、
リセット・書き込み中・クラッシュ・ブラウンアウトでピンが浮けば**接点は勝手に開く**。
ファームは「普段どおり動いているときに閉じる」だけを担当している。

**✅ 実機で全経路を確認した（2026-08-08・スピーカー未接続のまま）**

| # | 操作 | 結果 |
|---|---|---|
| 1 | 書き込んで起動 | ✅ 閉じる |
| 2 | `reboot` | ✅ 開く → 起動でまた閉じる（`muteBeforeRestart()` の本番経路） |
| 3 | `knobdis` → `knoboff` | ✅ 開く |
| 4 | `knobon` | ✅ 閉じる |

⭐ **つまみを繋がずに OFF/ON を試すため `knoboff` / `knobon` を足した**（診断専用）。
AS5600 は[「ボードを壊した犯人が未特定」の封印](#)で新ボードに繋げないため、つまみを回して試せない。
⚠ 先に `knobdis` で読み取りを止めないと、次の周回で本物の位置に戻される。

⬜ **残るのはスピーカー線の割り込みだけ。**

⚠ 以前ここに「ケーブル待ち」と書いていたが、**届いたのはメスメスのジャンパケーブル**で
（2026-08-10 ユーザー確認）、使い道は**ハーネスの作り直し**だった。スピーカー線の割り込みに
何が要るかは、この記述とは別件である。⬜ 基板側の白い2ピンから何で受けるかは未決。

**耳を守る仕組みをソフトに依存させない。** アンプ出力とスピーカーの間にリレーの接点を
入れ、**無通電で開**（ノーマルオープン）にする。閉じるのはファームが起動し切ってから。

決め手は**再生中の電池切れ**。アンプの消費がピークなのは喋っている最中なので、電池が
力尽きるのも「よりによって再生中」になる。しかも電圧が落ちきらない領域では**ESP32だけが
ブラウンアウトでリセットを繰り返し、コーデックは通電したまま解除状態を保持する**ため、
ROMブートログの爆音が連続で出るループに入り得る。爆音自体がさらに電流を食うので悪化
方向に回る。**肩に載る＝耳から数cm**でこれが起きる。

上のリードスイッチによるEN制御が守るのは「**意図した電源断**」だけで、この経路は守れない。
クラッシュ・ウォッチドッグ・ブラウンアウトも同じく守れない。**リレーが開いていれば、
これらは全部スピーカーが物理的に切り離された状態で起きる。**

| 条件 | 理由 |
|---|---|
| ノーマルオープン（無通電で開） | ESP32のGPIOはリセット直後フローティング。駆動側にプルダウンを置き、**無電・リセット中・クラッシュ中は必ず開**にする |
| **ラッチングリレーは使わない** | 消費電流では有利だが、電源が落ちても閉じたまま保持する＝防ぎたい状態そのもの。ここは譲れない |
| 閉じるのは `setup()` の最後 | コーデックをミュートし、I2Sを初期化し終えた後。落とすときは逆順（ミュート → リレーを開く）でポップを避ける。ただし非常時の保証はリレー単独で成立する |
| 駆動はトランジスタ経由 | GPIO直結では駆動できない。フライバックダイオードを入れる。GPIOはストラッピングピンを避ける |

⚠ **コイルは動作中ずっと電流を食う**（信号用リレーで5V 30〜50mA前後）。1000mAhの電池に
対して無視できない量なので、稼働時間の見積もりに必ず入れること。

**落ちた案**（いずれも検討して外した。蒸し返さないこと）:

- **減衰器（スピーカー線に固定の抵抗分圧）** — **不採用**。フルスケールが安全な音圧に
  収まる減衰量まで削ると、肝心の声が聞こえなくなる。必要なのは音量を下げることではなく
  **開閉すること**
- **eFuse `UART_PRINT_CONTROL=3` でROMブートログを消す** — **不採用**。リレーが開いて
  いればブート窓は音源ごと無音になるので、不可逆な操作をする理由が無い。検討の経緯は
  [firmware/esp32/README.md](../firmware/esp32/README.md) の轟音の節
- **手動の物理スイッチ** — **不採用**。人が操作しないと効かない。装着者にその判断は
  求められない

### 回路図（2026-08-06 作成・組み立ては 2026-08-07）

**手持ちの部品だけで組める。** 追加の買い物は無い。

#### 駆動側（ユニバーサル基板に載せる）

```
              +5V ●──────┬────────────┬──────────────┐
                         │            │              │
                       0.1µF     コイル 167Ω      1N4148
                        ═╧═      Y14H-1C-5DS     ───┬───  ← 帯(カソード)
                         │        (29.9mA)        ／ ▲ ＼    が +5V 側
              GND ●──────┘            │           ───┴───
                                      │              │
                                      └──────┬───────┘
                                             │
                                             ● C（コレクタ）
                                            ╱
  D10(GPIO9) ●────[ 1kΩ ]────●──── B ───┤  2SC1815-GR (NPN)
                             │            ╲
                             │             ● E（エミッタ）
                         [ 10kΩ ]          │
                             │             │
              GND ●──────────┴─────────────┘
```

#### 接点側（スピーカー線に割り込ませる）

```
  ReSpeaker Lite                                  スピーカー
   スピーカー出力(+) ●──── COM        NO ────────● (+)
                              ╲
                               ╳  NC ── 何も繋がない（開放のまま）

   スピーカー出力(−) ●───────────────────────────● (−)   ← こちらは切らない
```

**COM–NO を使う**（COM–NC ではない）。⚠ **これが安全の本体**で、コイルに電気が来ていない間は
接点が開き、スピーカーが物理的に切り離される。

#### 接続表（この通りに繋げば組み上がる）

| # | 部品・端子 | 相手 |
|---|---|---|
| 1 | XIAO **D10(GPIO9)** | 1kΩ の片足 |
| 2 | 1kΩ の反対側 | 2SC1815 の **B（ベース）** |
| 3 | 10kΩ | **B ⇔ GND**（1kΩ の後ろ側とGNDの間） |
| 4 | 2SC1815 **E（エミッタ）** | GND |
| 5 | 2SC1815 **C（コレクタ）** | リレーのコイル片側 |
| 6 | リレーのコイル反対側 | **+5V** |
| 7 | 1N4148 | コイルに**並列**。**帯(カソード)を +5V 側**、アノードを C 側 |
| 8 | 0.1µF | **+5V ⇔ GND**。板のどこに置いてもよい（下の「0.1µF の位置は効かない」） |
| 9 | リレー **COM** | ReSpeaker Lite のスピーカー出力(+) |
| 10 | リレー **NO** | スピーカー(+) |

⚠ **2SC1815 の足の並びは、平らな面を手前にして左から E–C–B**（ECB）。**EとBを逆にすると動かない。**

#### 数字の裏取り（なぜこの定数か）

| 項目 | 計算 | 判定 |
|---|---|---|
| コイル電流 | 5V ÷ 167Ω = **29.9mA** | 2SC1815 の Ic max 150mA に対し余裕 ✅ |
| ベース電流 | (3.3V − 0.8V) ÷ 1kΩ = **2.5mA** | GPIO の負担として軽い ✅ |
| 必要な hFE | 29.9mA ÷ 2.5mA ≒ **12** | GRランクは hFE 200〜400。**深く飽和する** ✅ |
| 10kΩ が食う電流 | 0.8V ÷ 10kΩ = **80µA** | 無視できる ✅ |
| 接点に流れる電流 | 8Ω 2W → **0.5A rms** | 接点定格 1A 以内 ✅ |

**10kΩ（プルダウン）がこの回路で一番大事な部品。** ESP32のGPIOはリセット直後・書き込み中・
クラッシュ中に**フローティング**になる。10kΩ が無いとベースが浮いてリレーが不定になり、
**守りたい状況でスピーカーが繋がる**。⚠ **10kΩ は必ずリレー基板側に置く**（ESP32側に置くと、
信号線が抜けたときにベースが浮く）。これで**線が外れても必ず開**になる。

**接点は「乾いた状態」で開閉する。** 順序が「コーデックをミュート → リレーを開く」なので、
電流が流れている最中に接点が切れることはない＝アークがほぼ出ない。定格1Aに余裕がある理由。

#### 0.1µF の位置は効かない（2026-08-07・レイアウト検討中に確認）

「パスコンはリレーの近くに」は一般論としては正しいが、**この回路では買えるものが無い**。
板のどこに置いてもよい。

| | 数字 |
|---|---|
| 0.1µF が 5V で蓄える電荷 | **0.5µC** → コイルの 30mA なら **17µs** で尽きる |
| コイルの電流の立ち上がり | τ = L/R。信号リレーのコイルは数十〜数百mH なので **0.3〜3ms** |

**コイルが電源から電流を引く速さは、0.1µF が効く速さより2桁遅い。**
インダクタ自身が di/dt を抑えているので、近くに置いても遠くに置いても差が出ない。

🔴 **速い現象は 1N4148 の側にある。** OFF時の逆起電力は
**コイル ↔ ダイオードのループに閉じ込められていて、コンデンサを通らない。**
だから「**ダイオードは裏でコイルの直近**」という指定は本当に効くし、
「コンデンサをリレーの近くに」は効かない。⚠ この2つを混同しない。

⚠ **電源の落ち込み（カチカチ発振）に効くのも 0.1µF ではない。** あれは ms オーダーなので
**10〜100µF の電解**が要る。0.1µF を増やす方向は無駄。

#### 組む順番（2026-08-07）

**⚠ スピーカーは最後まで繋がない。** 音が出る段に入る前に必ず声をかけること。

1. 駆動側だけを基板に組む（上の接続表 1〜8）。**リレーの接点側には何も繋がない**
2. **通電前に 1N4148 の帯の向きを目で確認**（下の失敗表の1件目）
3. +5V と GND を繋ぐ。**この時点では何も起きないのが正常**（GPIO9 は浮いていて 10kΩ で LOW）
4. **手で 1kΩ の入力側に 3V3 を当てる → カチッと鳴るか。** ファームは要らない
5. 3V3 を離す → もう一度カチッと鳴って戻る（開に戻る）
6. 接点の検証（下）→ 通ったらスピーカー線へ

#### 接点の検証（テスター無しでできる）

`gN` は内部プルアップで読む**導通チェッカー**（`main.cpp` の `testGround()`）。これを使う。

- リレーの **COM → `D2`**（⚠ 元は `D3` と書いていたが、**`D3` はリレーの駆動に取られた**）
- リレーの **NO → GND**

**駆動は手で3V3を当てず、シリアルの `high 3` / `hiz 3` を使う。** 手が空く。

| 駆動 | 期待される `g2` の答え | 意味 |
|---|---|---|
| **`hiz 3`**（駆動なし） | `なし (HIGH) -> 浮いています` | **接点が開いている＝安全側** ✅ |
| **`high 3`** | `あり (LOW) -> GNDに繋がっています` | 接点が閉じた ✅ |

流れるのは数十µAなので接点にもピンにも無害。**これで「無通電で開」が実測で確認できる。**

#### ✅ 接点の検証は完了（2026-08-08）

⭐ **`gN` ではなく、テスターで接点を直接測るほうが速くて確実だった。**
リレーの接点側はコイル側と絶縁されている（絶縁抵抗100MΩ以上）ので、
**通電したまま COM–NO の抵抗を測って構わない。GPIOを1本も使わない。**

**プローブを COM と NO に当てたまま `high 3` / `hiz 3` を交互に打つ。**

| 打つ | 実測 | 意味 |
|---|---|---|
| `hiz 3`（駆動なし） | ✅ **OL** | **接点が開いている＝安全の本体** |
| `high 3` | ✅ **0Ω** | 接点が閉じた |

🔒 **これでミュートリレーの安全機構は実測で成立した。**
「電気が来ていなければスピーカーは物理的に切り離される」が、コイルではなく**接点そのもの**で確認できている。

⚠ **`gN` を使う経路（COM→`D2`）は途中で行き詰まった。** 線をGNDに直接当てても
`浮いています` になり、`g3` は正常に `あり (LOW)` を返したのでコマンド側は無実。
**`D2` の線かピンのどちらかが繋がっていない**が、接点の検証はテスターで済んだので追っていない。
⬜ **会話ボタンで `D2` を使うときに、この件が再浮上する。**

| 症状 | 原因 | 対処 |

| **鳴らない**（熱いかどうかは当てにならない） | 🔴 **1N4148 が逆向き。** 帯がC側だとコイルを迂回して +5V→ダイオード→トランジスタが**短絡**になる。**2026-08-08 に実際にこれだった** | すぐ電源を切る。ダイオードを180°回す。1N4148 とトランジスタは死んでいる可能性があるので交換（どちらも予備あり） |

| 鳴らない・熱くもない（GNDは導通済み） | 2SC1815 の E と B の入れ違い | **平らな面が奥（行A側）**を向いていて、**エミッタの足が GNDレールの穴に載っている**か見る。逆向きだとベースがGND・エミッタが1kΩ側になり、B–E が逆バイアスで電流が流れないので**熱すら出ない** |

#### GNDの導通を5回で切り分ける（2026-08-08 に確立）

**電圧を読んで犯人を推理するより、抵抗を測って区間を潰すほうが速い。** 2026-08-08 に
「ベースが3V・コレクタが0V」から原因を推理しようとして半日を溶かし、テスターを当てたら
**1回目で見つかった**。以後は電圧の推理より先にこれをやる。

**電源を切ってから、抵抗レンジ（ダイヤル `Ω →|— •)))` ＋ SELECT で Ω）で測る。**
プローブは**半田面（裏）に当てる**。部品の足は全部飛び出ていて、レールは裸線なので、
穴にプローブを入れる必要はない。

| # | 何と何のあいだ | 期待値 | 切れていたら |
|---|---|---|---|
| 1 | 2SC1815 のエミッタの足 ⇔ 駆動側GNDレール | 0Ω | エミッタがレールに半田付けされていない |
| 2 | 駆動側GNDレール ⇔ バス側GNDレール | 0Ω | 🔴 **ジャンパ⑥。ここが唯一の橋** |
| 3 | バス側GNDレール ⇔ 着地列のGNDの足 | 0Ω | 着地ピンヘッダの足がレールに付いていない |
| 4 | 着地列のGNDの足 ⇔ ReSpeaker の3.5mmジャックの外側 | 0Ω | XIAOからの線かDuPontの接触 |
| 5 | 着地列の5Vの足 ⇔ コイルの+5V側のピン | 0Ω | +5V が来ていない |

🔴 **2番が本命。** 駆動側GNDレール（列7）とバス側GNDレール（列17）を繋いでいるのは
**ジャンパ⑥ の1本だけ**で、ここが浮くと 10kΩ・エミッタ・0.1µF が**まとめて宙に浮く**。
**10kΩ のプルダウンも同時に死ぬ**ので、ベースが 3.3V 近くまで持ち上がったまま
コレクタ電流が流れない、という一見わけの分からない状態になる。

⚠ **4番の3.5mmジャックの外側がGNDである確証は無い**（回路図が公開されていない）。
0Ω が出れば経路は生きていると言えるが、出なかったときに「線が切れている」のか
「当て先がGNDでない」のかは区別できない。そのときは XIAO 側の別のGND点で取り直す。

#### ✅ 2026-08-08 解決（吸着した）

**原因は 1N4148 の逆挿しだった**（次項）。付け直して、**5VとGNDだけを繋ぎ、
コレクタをGNDにジャンパで落とした状態でカチッと鳴ることを確認**。
赤ランプが暗くなる症状も同時に消えた。

⚠ **この時点で確認できたのは「+5V・コイル・リレー・ダイオード」まで。**
コレクタをGNDに落とすのはトランジスタを迂回する操作なので、
**2SC1815・1kΩ・10kΩ はまだ一度も通していない**（次は `high 10` で通す）。

下の項目はすべて実測で潰してあるので、**同じ測定を繰り返さないこと。**

| 確認したこと | 結果 |
|---|---|
| GNDの4区間＋5Vの1区間の導通 | ✅ 全部 0Ω（⑥ を繋いだあと） |
| 1kΩ の実測値 | ✅ 1kΩ（100kΩ の読み違いではない） |
| コレクタ ⇔ +5V（コイルを通した抵抗） | ✅ 167Ω |
| コレクタの電圧（駆動なし） | ✅ 5V |
| ベース・エミッタ間の電圧（3V3 を当てながら） | ✅ 0.7V |
| ベース→コレクタ／ベース→エミッタ のダイオード試験 | ✅ どちらも 0.6V。**E と B の入れ違いも否定された** |
| ~~1N4148 の向き~~ | 🔴 **この確認は無効だった**（下記） |
| リレー単体（直接通電） | ✅ 以前に吸着している |

#### 🔴 D10(GPIO9) は空きピンではなかった（2026-08-08・実測で確定）

**ダイオードを直したあと、電源を入れただけでリレーが閉じ、閉じたままになった。**
守りたい瞬間にスピーカーが繋がる、いちばん避けたい挙動である。

**切り分けの結果（すべて実測）**

| 測ったもの | 値 | 意味 |
|---|---|---|
| D10のピン ⇔ GND | 10.89kΩ | 1kΩ+10kΩ。**プルダウンは生きている** |
| D10のピン ⇔ 着地列の他6本 | 全部 OL | **短絡は無い。5VがGPIOに回り込んでもいない** |
| トランジスタの真ん中の足 ⇔ GND（電源OFF） | OL | **C–E短絡ではない。トランジスタは生きている** |
| トランジスタの真ん中の足 ⇔ GND（電源ON） | **0.1V** | 深く飽和している＝コイルに電流が流れている |
| **D10の線が挿さっているピン ⇔ GND（電源ON）** | 🔴 **1.49V** | **D10が外から持ち上げられている** |
| D10の線を抜いて電源投入 | **鳴らない** | 🔒 **D10が原因で確定** |

1.49V なら 1kΩ を通る電流は 0.74mA、10kΩ が 0.075mA を食って**ベースに 0.66mA**。
コイルの 29mA に対して十分で、コレクタ 0.1V の深い飽和と計算が合う。

⚠ **1.49V という半端な値の説明（推測）**: D10＝GPIO9 は ReSpeaker Lite 側で
**XMOS の MCLK の線**につながっている可能性が高い。`AudioIo.h` の
「MCLKは既定で出さない。必要なら 9 (D10) を指定する」は、**基板にその配線がある**ことを示す。
ReSpeaker Lite は **XMOS側がI2Sマスタ**なのでクロックを出しているのはXMOS。
**テスターは矩形波の平均値を表示する**ので、3.3Vのクロックなら1.5V前後になる。
リレーは機械なので平均に反応して吸い付いたままになる。

🔴 **選定の落ち度**: D10 を選んだ根拠は「ストラッピングピンでない・**ファームで**未使用」だけで、
**ReSpeaker Lite 側の結線を一度も確認していなかった。** ファームが使っていないことと、
ピンが電気的に空いていることは別である。**次のピンも同じ理由で外れうる。**

⚠ **ボード側の結線が不明なまま選ぶので、選んだピンは必ず実機で検証する。**
検証は「線を挿す → 電源を入れて**鳴らない**こと → `high N` で鳴ること → `hiz N` で戻ること」。
`high`/`hiz` で追従するかを見れば、**ピンの取り違えと駆動の可否が同時に確かめられる**
（コマンドで動く足は1本しかないので、ヘッダを数える必要がない）。

#### 🔴 原因は 1N4148 の逆挿し（2026-08-08 夕・解決）

**ユーザーが穴割り図の矛盾に気づいて解決した。** 図が**部品面でも半田面でもカソードを左に描いていた**が、
裏返せば左右は反転するので、**両面が同じ向きに見える時点でどちらかが必ず間違っている。**

**間違っていたのは半田面の図のほうで、正しくは以下になる。**

| | M3（コイルの+5V側＝カソード） | M5（コイルのコレクタ側＝アノード） | 帯があるべき側 |
|---|---|---|---|
| 部品面 | x=110 | x=174 | **左** |
| **半田面** | x=750 | x=686 | 🔴 **右** |

**1N4148 は半田面に付ける部品なので、裏を見ながら付ける。** そのため**半田面の図の誤りが
そのまま実装の誤りになった**（半田面から見て左＝M5＝コレクタ側に帯が向いていた）。

**この1点で、それまで説明できなかった観測がすべて揃う。**

| 観測 | 逆挿しならこうなる |
|---|---|
| トランジスタOFFのとき何も起きない・**熱くもない** | コレクタが開放なので +5V→ダイオード→コレクタ で電流が行き止まる。**無通電なので発熱しないのが正しい** |
| **コレクタをGNDに落とすと赤ランプが暗くなる** | その瞬間だけ +5V→ダイオード→GND がほぼ短絡になる。**唯一残っていた異常の正体** |
| それでも**吸着しない** | 5Vが潰れてコイルが感動電圧4Vに届かない |
| コレクタ⇔+5V が **167Ω**（矛盾しない） | テスターの抵抗レンジの印加電圧は 0.7V に届かないので、**並列のダイオードは導通せずコイルだけが見える** |

⚠ **「1N4148 の向き ✅ ユーザー確認済み」は、間違った図に対する確認だったので証拠にならなかった。**
**図を根拠にした確認は、図が正しいことを別に担保できるときにしか使えない。**

⬜ **直したあとに再確認すること**: 逆挿しの状態で 3V3 をベースに当てた測定を何度かしているので、
**2SC1815 と 1N4148 は過電流を経験している**（電源が落ち込んで電流制限が掛かっていたので
壊れていない可能性は高いが、確証は無い）。**1N4148 はどうせ外して回すので、予備の新品に替える。**

#### 図のバグ（2026-08-08 修正済み）

[relay_board.html](../hardware/relay_board.html) のダイオード描画が、カソードの向きを
**「cathode がどちらの穴か」という論理値**（`towardA`）で決めていた。`pt()` は裏返しで

#### レール（裸のスズメッキ線を這わせる。これが土台）

**ブレッドボードで使っていた4本のバス（VCC・GND・SDA・SCL）を、そのままレールに移しただけ。**
OLED も AS5600 も基板には載せず（それぞれ筐体と治具に付く）、**このレールから線を出す**。
これに駆動側の **+5V** と **GND** の2本が加わる。

🔒 **OLEDのVCCは3V3で確定。5Vを繋がない。**
モジュールの仕様は 3.3V〜5V だが、**3.3V で動かした実績がある**（ブレッドボード運用・ユーザー確認）。
動くと分かっている方を使う。5V にすると **I2C のプルアップ先が 5V になり**、
SDA/SCL が 5V へ引き上がって ESP32 の入力定格を超えうる。**得るものが無いので検討しない。**

▶ **どの行・どの列を何のレールにするかは [relay_board.html](../hardware/relay_board.html) の `RAILS`。**

⚠ **OLEDモジュールのシルクは `VCC GND SCL SDA` の順**で、一般的な `VCC GND SDA SCL` とは
SCL/SDA が逆（[firmware/esp32/README.md](../firmware/esp32/README.md)）。並び順の記憶で挿すと入れ替わる。

#### OLEDは線で出さない（2026-08-07 決定）

OLED の4ピンは**モジュールの上辺に横一列**に並んでいる（2026-08-07 ユーザー訂正）。だから
**I2Cのレールを縦に4本、シルクと同じ `VCC GND SCL SDA` の順に並べれば、
4ピンがそのまま4本にまたがって挿さる＝配線0本**になる。上の「出る」表で OLED が 0本なのはこれ。

🔴 **ピンが上辺なので、本体はピン列から「下」へ 27mm 垂れる。**
穴割り図はこの向き（ピン列が上・本体が下・表示が正立）で描いてある。
つまり**図の左右がそのままシルクの左右**なので、レールは左から `VCC GND SCL SDA`。

⚠ **OLEDモジュールのシルクは `VCC GND SCL SDA` の順**で、一般的な `VCC GND SDA SCL` とは
SCL/SDA が逆。**レールの並び順もそれに合わせてある**ので、
一般的な順序の記憶でレールを引き直すと入れ替わる。

🔴 **OLEDは組み立ての一番最後に挿す。** 本体（30 × 27mm）が板の広い範囲を覆い、
**その下にバスの半田点が40箇所隠れる**。先に挿すと二度と触れない。

⚠ **リードスイッチとマスタースイッチはこの基板に載らない。** 行き先が PowerBoost の `EN` で、
XIAO を通らないため（上の「リードスイッチでEN遮断」）。線2本ずつを直付けする。

- **レールは半田面（裏）に裸のスズメッキ線**、**ジャンパは部品面（表）に被覆線**。
  面が違うので、絵の上で1箇所だけ交差しても短絡しない
- 表はリレー本体とコネクタが場所を取るので、レールで埋めない

[relay_board.html](../hardware/relay_board.html)。** 部品とジャンパにチェックボックスが

#### 🔒 スピーカーは基板の IN / OUT コネクタで受ける（2026-08-10 決定・ユーザー指摘）

🔴 **下の表の「COM から線が外へ出る」という形は捨てる。** 代わりに、**ハブ基板に
スピーカー用のコネクタを2つ載せる。**

| コネクタ | 何を受けるか |
|---|---|
| **IN** | **ReSpeaker Lite のスピーカーソケットから来る線**を受ける |
| **OUT** | **スピーカーへ出す線**。(+) は基板の中でリレーの `COM`–`NO` を経由する |

基板の中で繋ぐのは3本だけである。**`IN(+)` → `COM`**、**`NO` → `OUT(+)`**、
**`IN(−)` → `OUT(−)`**（(−) は接点を通さず素通し）。

**なぜこの形でなければならないか。** この基板は「外へ出る線は全部コネクタで受ける」と
決めてある（下の🔒「コネクタ」）。狙いは**引っ張りをコネクタで受けて基板のパッドに
掛けないこと**と、**抜き挿しで分解・交換ができること**である。スピーカーは筐体側に付いて
線が動く部品なので、`COM` に線を直付けすると引っ張りがそのまま半田点に乗り、いずれ
パッドごと剥がれる。**IN/OUT の2つを載せれば、ReSpeaker 側もスピーカー側も
コネクタ1本ずつで抜き差しでき、完成しているスピーカーを切らずに済む。**

⚠ **この設計を最初から持っていなかったのが設計の欠陥である**（2026-08-10 ユーザー指摘）。
接点側だけを「外へ出る線」として扱い、他の全部に適用した「コネクタで受ける」という
自分の決定をスピーカーにだけ適用していなかった。

🔒 **コネクタは PH2.0 2ピン**（[SHOPPING.md](SHOPPING.md) の購入品・ReSpeaker のソケットも
同型）。⚠ **PH2.0 は 2.0mm ピッチで、ユニバーサル基板の 2.54mm 格子には素直に載らない**
（2ピンなので足を開けば届く範囲ではある）。⬜ **未購入**。トップ型かサイド型かは現物で決める。

🔴 **落ちた案: 2.54mm ピンヘッダ＋DuPont で IN/OUT を作る — 不採用**（2026-08-10・
ユーザー指摘。**AI が「PH2.0 が無くても在庫で組める」と提案して却下された。蒸し返さないこと**）。
スピーカー線をロジック線と同じ扱いにしてはいけない。理由は4つある。

1. **8Ω 2W で 0.5A rms** が流れる。信号線の桁ではない
2. **DuPont の接触抵抗が 8Ω と直列に入る。** しかも個体差が大きい
3. **DuPont は緩む前提の接続**（[TODO.md](TODO.md) 2章「持ち歩くと確実に外れる」）。
   鳴っている最中に接触が暴れればそれ自体がノイズになる
4. 同じ板に **I2C** が通っていて、**ReSpeaker のマイクが数cm** の距離にある。
   ⚠ アンプの方式は未確認だがスイッチング出力が普通で、被覆線の長い引き回しは避けるべき。
   そもそもこの doc 自身が「**スピーカー線は撚り合わせ、信号の束と一緒に束ねない**」と
   書いている（下の「線の太さ」）。その逆をやる案だった

⬜ **2026-08-11 のプレゼンは、C（完成しているスピーカー）を ReSpeaker に直結で通す**
（同日ユーザー判断）。リレーは組み上がって実測も通っているが、**IN/OUT のコネクタが
入手できるまで経路には入らない**。

**プレゼンでの見せ方（2026-08-10 ユーザー）**

1. **つまみを OFF に回してカチッと鳴らす。** AS5600 が戻ったので**本物のつまみ**でできる。
   コマンドを打たずに製品そのままの挙動で見せられる
2. 言うことは3つ。**電気が来ていないときは切れている**（実測: 駆動なしで `OL`、駆動で `0Ω`）／
   **閉じるのはソフトが正常に起動し切ってから**（守っているのは 10kΩ のプルダウンなので、
   リセット・書き込み・クラッシュ・電池切れでも勝手に開く）／
   **いまはコネクタが間に合わず経路に入っていない**
3. ⭐ **直結なので本番中に再起動すれば轟音が出る。が、それは失敗ではない。**
   「**こんな音がしてしまうので、ハードで止める設計にしました**」に繋がるので、
   むしろ説明の裏付けになる。慌てて避けなくてよい

#### 会話ボタンは線で出さない（2026-08-07 変更・ユーザー指摘）

**マイクロスイッチの3端子は1穴飛ばし（ピッチ5.08mm）で 2.54mm グリッドに乗る**
（2026-08-07 ユーザー実測）ので、**そのまま基板に挿さる**。線2本が消える。
**縦置き（リレーと同じ向き・上端もリレーに揃える）で 列9**。本体が 縦5 × 横12mm なので、
縦にすると幅が2列で済み、板の下の空き地に余裕で入る。
穴は **`J9`＝C（GND）／`L9`＝NO（信号）／`N9`＝NC（空き）**
（[hardware/relay_board.html](../hardware/relay_board.html) が正）。

⭐ **GNDレールは列7（B〜I）**。列6から寄せた（2026-08-07・ユーザー指示）。狙いは2つ:
1. **列6が完全に空く** → コレクタのジャンパ（E6→G6→M6→M5）が真っ直ぐ下りる。
   ⚠ **被覆線がGNDレールの上を走る形を作らない**こと。一度そう描いて却下された
2. **列8を空きの緩衝にできる** → レールの穴がスイッチの信号ピンの真隣に来ない

🔒 **裸のレールにするか被覆線にするかの判断基準**（2026-08-07 明文化）:
- **裸のレールは通った穴を全部その電位にする。被覆線は両端しか繋がない**
- **裸のレールどうしは交差できない**（触れたら短絡）

だから GND をスイッチへ寄せるのは**被覆線（⑧ = I7 → I9 → J9）**。レールで寄せると
通り道の穴＝C や NC のピン穴まで GND になる。同じ理由で ②(C6→C1) と ⑩(A13→A1) も
裸にできない（C3・A3 が +5V になると、真下の B3＝GND と 2.54mm で隣り合う）。

⚠ **信号のジャンパ⑨（A14→B14→B10→L10→L9）は F10 で⑥、H10 で⑦を跨ぐ**
（部品面の被覆線どうしなので短絡はしない）。**板の上半分と下半分は ⑥（行F）と ⑦（行H）で
仕切られていて**、跨がずに降りる道は「列20を下って OLED本体の下を這う」しかない。
テスト基板なので跨ぐほうを採った。

⭐ **⑧は行I（本体の上）、⑨は列10（本体の右）から入る**ので、**本体の下に被覆線は1本も通らない**。

⚠ **これを入れるために駆動回路を左へ寄せた**（1kΩ/10kΩ → 列3、2SC1815 → E5/E6/E7、
0.1µF → C6–C7、**GNDレール 列8 → 列7**）。**列2 は空けたまま**にする —
列1が +5V レールなので、隣に節点を置くと橋絡が
「+5V–GND短絡」「**リレーが閉じっぱなし**（ベース節点）」「5VがGPIOへ」に直結する。
**あの1列は空きではなく緩衝。**

⚠ **上の COM/NO/NC は「リレー」の話。マイクロスイッチにも同じ名前の3端子がある。**
混ぜないこと。マイクロスイッチ側は次のとおり（✅ 2026-08-07 ユーザー確認）:

| マイクロスイッチ（DAOKAI・ヒンジレバー3PIN）の端子 | 位置 | 穴 | 使い方 |
|---|---|---|---|
| **C**（COM） | **レバーの根本（ヒンジ）側の端** | `J9`（上・リレーと同じ行） | ジャンパ⑧で GNDレール（`I7`）へ |
| **NO** | **真ん中** | `L9` | `D3` から来るジャンパ⑨が着く |
| **NC** | **レバーの自由端（開いている側）の端** | `N9`（下） | ⚠ **何も繋がない。** 押していない間ずっと閉じている側なので、繋ぐと**会話が始まりっぱなし**になる |

**C と NO は単なる接点なので、どちらを `D3` に、どちらを GND にしても同じ**（極性は無い）。
🔒 **位置はレバーを基準に書いてある**（「左から C, NO, NC」ではない）。
**左右で書くと、基板を裏返して見たときに NO と NC が入れ替わる。**
レバーの根本はどちらの面から見ても同じ端なので、こう書けば裏返しても間違えない。

**リレーはコイル側と接点側が電気的に分離している**（データシート: 絶縁抵抗 100MΩ以上・
耐電圧 1000VAC 1分・全導体間）。コイルは電磁石で、**金属板を力で動かすだけ**。
そのため:

- ✅ **接点に何も繋がなくてもリレーは動作する。** 今日の「カチッと鳴るか」試験は**この状態でやる**
- ⚠ **ただし接点にスピーカー線を通すのが回路の目的**なので、繋がないまま終わるわけではない
- 🔒 **この分離こそが、半導体スイッチではなくリレーを選んだ理由。** ESP32が暴走しても電源が
  落ちても、スピーカーは「ソフト的にオフ」ではなく**物理的に切り離されている**

### XIAOの充電回路を使わない理由

XIAO は充電回路を内蔵しているので「電池をXIAOに繋いで、XIAOのUSB-Cで充電」が
一見いちばん簡単に見える。**採らない。**

1. **充電電流が100mAしかない。** これが決定的。2000mAhの電池なら満充電まで20時間以上。
   さらに本機の消費は待機でも200〜300mAあるため、**繋ぎっぱなしでも充電が追いつかず減っていく**
2. **書き込み用の口と兼用になる。** XIAO側のUSB-Cはファーム書き込み用。パソコンに挿すと
   シリアルとして認識され、DTR/RTSで再起動がかかる（`monitor_dtr = 0` を入れているのは
   そのため）。利用者が充電のつもりで挿す口としては危うい
3. **充電経路が2つになる。** 5V昇圧のために電池は外付け回路へ繋ぐ必要がある。
   そこでXIAO側でも充電すると、同じ電池に充電器が2つぶら下がって制御が競合する。
   どちらか一方に寄せるしかない

昇圧とパススルーは外付けで用意することが確定しているため、**充電もそこへ寄せる**のが自然。
充電電流も自由に選べる（2000mAhなら1A前後で2〜3時間）。

### 5Vを作らずに済ませられないか（保留）

ReSpeaker Lite の5V入力は基板上でレギュレータを通って3.3Vになっているはず。
そこへ直接3.3Vを入れられるなら、リポから降圧するだけで済み**昇圧が丸ごと不要**になる。
効率も部品も有利。

ただし **Seeed は回路図を公開していない**（GitHubにあるのはファームとサンプルのみ）。
実機のパッドを当たって電源経路を追う必要があり、テスターが要る。**保留。**
判明すれば構成が変わるので、テスターを用意したら最初に確認する価値がある。

## 消費電流の見積もり（推定）

**実測していないので、あくまで桁を掴むための数字。**
XMOSの消費が非公開なのが最大の不確定要素。

| 部品 | 会話中(推定) | 待機中(推定) |
|---|---|---|
| XIAO ESP32S3（Wi-Fi常時接続） | 100〜150mA（送信時は瞬間的に300mA前後） | 80〜120mA |
| XMOS XU316（音声処理） | 100〜150mA | 100〜150mA（**常時動いている**） |
| OLED | 10〜20mA | 10〜20mA |
| スピーカーアンプ（音量35%） | 50〜150mA | ほぼ0 |
| ※ | **スピーカーは未接続。** ここまでの動作確認は3.5mmジャックにイヤホンを挿して行っており、アンプは一度も動かしていない。上の値は完全な推定で、接続後に増える | |
| **合計（5V側）** | **約300〜450mA** | **約200〜300mA** |

これを3.7Vのリポから昇圧（効率85%と仮定）して取ると、電池からは1.5倍ほど流れる。

**以下の時間は、推定の上に乗った推定。** 元になる消費電流はXMOSの実測が無い。
倍ずれてもおかしくない。

**ただし、これを詰めるのに電流計は要らない。** 知りたいのは電流値そのものではなく
**「1000mAhで何時間持つか」**なので、**満充電から LBO が落ちるまで動かして時計を見る**
のが一番直接的で、推定を挟まない。会話させ続ける版と待機のまま放置する版の2回で、
下の表の2列がそのまま埋まる。

| 電池容量 | 会話が続く時間 | 待機が続く時間 |
|---|---|---|
| 1000mAh | 約1.5時間 | 約2時間 |
| 2000mAh | 約3時間 | 約4時間 |
| 3000mAh | 約4.5時間 | 約6時間 |

なお電流値そのものが要るのは、**設計を先読みしたいとき**（別の容量に載せ替えたら
何時間になるか、スリープでどれだけ伸びるか）だけ。**1000mAhで足りるかどうかを知る**
だけなら、上の「持つまで動かす」で済む。

**待機でもあまり減らないのが問題。** XMOSは常時動いていて眠らない。
「使っていない時間が長い」使い方なら、待機電力が寿命を決める。

対策の候補（未検討）:

- 物理スイッチで完全に切る（いちばん確実。つまみのスイッチは実装済みだが、
  今は疑似電源OFF止まりで待機電力には効かない。[TODO.md](TODO.md) 2.5）
- 一定時間使われなければ、ソフトからXMOSごと電源を落とす（回路が要る）
- ESP32のWi-Fiを間欠受信にする（XMOSが残るので効果は限定的）

## テスターが届いたらやること（手順）

上から順に。1と2で電池容量が決まり、3で構成が決まる。

### 1. 消費電流（USB電流チェッカー）

ReSpeaker Lite の USB-C と電源の間に挟むだけ。XIAOもボード経由で給電されるので
**そこ1点で全体が測れる**。上の4場面（起動時・待機・会話中・音量最大）を記録する。

### 2. スピーカーのインピーダンス（テスター・抵抗レンジ）

購入したもの: **8Ω 2W / PH2.0 2ピン / 角型パッシブ**（2026-07-26着予定）。
仕様書の前提（8Ω 2W）と一致するので、消費の見積もりは据え置きでよい。念のため実測で確認する。
表示は公称値なので、実測は少し低め（8Ωなら6〜7Ω程度）に出るのが正常。

基板側のアンプは**5Wまで対応**（Seeed wiki）。スピーカーの定格2Wより大きいので、
ソフトの音量（既定35% = `gain_`）を上げすぎるとスピーカー側の定格を超えられる。

🔴 **製品では、この上限をソフトではなくアナログ側に置くこと（2026-08-03）。**
肩＝耳道から数cmで、8Ω 2W に一般的な感度を仮定すると 10cm で 105〜110dB SPL 台の概算。
さらに **電池切れそのものが轟音の経路になる** — 電圧の垂れ下がりでESP32だけが先に
リセットし、コーデックは解除状態のまま生き残るため、書き込みリセットと同じ条件が
フィールドで発生する（⚠推定・未実測）。対策の順序と検証方法は
[firmware/esp32/README.md](../firmware/esp32/README.md) の「起動時の轟音とその対策」。

**注意: 既定の35%は3.5mmジャックにイヤホンを挿して決めた値。** これまでスピーカーは
接続しておらず、アンプは一度も動かしていない。スピーカーを繋いだら音量は取り直しになる。
最初は35%より**下げて**から鳴らし、耳から離した状態で確かめること
（起動時の轟音対策はソフトで完全には塞げない。[firmware/esp32/README.md](../firmware/esp32/README.md)）。

### 3. ReSpeaker の電源経路（テスター・電圧レンジ）

**3.3V直結が可能なら昇圧が要らなくなる**ので、構成が変わる。回路図が公開されていないため
実機を当たるしかない。

1. USB給電した状態で、基板上の各パッド・部品の電圧を当たる
2. **5Vのまま来ている点**と、**3.3Vに落ちている点**を見つける
3. 3.3V側がどこから来ているか（レギュレータの出力か）を追う
4. XIAOの3V3ピンと導通しているかも確認する（共通なら話が早い）

3.3Vの供給点が特定できれば、リポ（3.7〜4.2V）から降圧するだけで動く可能性がある。
ただし**保証外の使い方**なので、壊してもいい前提で試すこと。判断がつかなければ
素直に5V昇圧で組む（そちらが確実）。

## 決めるべきこと

数字が出たあとに、これを決める必要がある。

- **どれくらい持たせたいか。** 半日か、1日か、使うときだけ入れるのか
- **どれくらいの重さまで許すか。** 2000mAhのリポで約40g。筐体と基板を足すと100g前後になる
- **充電をどうするか。** ケーブルを挿してもらうのか、置くだけにするのか

この3つは技術ではなく使い方の話なので、実機の稼働時間を見ながら決める。

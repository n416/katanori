## 何が起きていたか

つまみを回すとコーデックの出力が死んで音が出なくなった。ESP32 を再起動しても戻らず
（`reboot` でも書き込み直しても）、**USB を抜き差しすると戻る**。数秒で自力復帰することもあった。

**いちばん強い事実は「死ぬのは回している最中で、スイッチが開くより前」だった**（2026-07-30）。

```
[+ 45.3s] creg 正常 (0x3F=0xD4 / P1 0x09=0x3C)
[+ 53.2s] [CODEC] !! リセットを検出しました      <- 死んだ
[+ 58.1s] [KNOB] OFF位置                        <- スイッチが開いたのは 4.9秒“後”
```

これでソフトの経路は消える（会話終了・画面消灯・通信停止はどれもスイッチの OFF 検出より後に走る）。
残っていたのは「**回す**」という物理動作そのもので、**振動で一瞬どこかが繋がる**という筋なら、
半田をやり直しても再発することと辻褄が合う。

🔒 **根本原因は特定していない。特定しないまま、原因ごと部品を捨てて症状を消した。**

## ⚠ 当時「否定した」仮説のうち、1つは後に正しかった

🔴 **当時この文書は「D1(GPIO2) が ReSpeaker 側のリセット線」という仮説を、`low 1` で LOW に
落としても無傷だったことを根拠に否定していた。これは誤りだった。**
2026-08-05 に **`D1`(GPIO2) は XMOS のリセット線（アクティブHIGH）**であることが確定している
（[RESPEAKER-LITE.md](RESPEAKER-LITE.md) 4章の公式回路図で `XU316_RST`）。
**アクティブHIGH なので、LOW に落とす試験では何も起きなくて当然だった。**

⭐ **教訓は「否定の根拠が、その仮説を実際に反証しているかを確かめる」こと。**
LOW を当てて無事だったことは、HIGH で止まる線であることを何も否定していない。

⚠ **`D1` は現在も `pinMode` 禁止である。**

## この調査から出た進め方の教訓

- 🔴 **間欠故障を「直った」と言うには、直る前と同じ操作を同じ回数だけ繰り返して0回であることが要る。**
  一度この文書を【解決】に書き換えたが、根拠は「半田をやり直したあと症状が出なかった」だけだった
- 🔴 **一度に1つしか変えないこと。** つまみを回す操作と `WIFI_OFF` を両方含む試験でコーデックが死に、
  `WIFI_OFF` のせいだと決めつけて実装と文書を書き換えた（commit 4a97a49、後で取り消し）。
  その後 `WIFI_OFF` を15秒保持しても死なないことが分かっている
- **各条件を1回ずつしか試さず、そのたびに結論を出していた。** 実際「3V3を外せば起きない」と
  判断した直後に、同じ条件の2回目で発生している

## 参考: 当時のレジスタ値

| | `0x1B` | `0x3F`(DAC電源) | `P1 0x09`(出力ドライバ) |
|---|---|---|---|
| 正常 | 0x30 | 0xD4 | 0x3C |
| 異常パターン1 | **0x00** | 0x14 | 0x00 |
| 異常パターン2 | 0x30 | 0x14 | 0x00 |

パターン1は全部が初期値で、コーデックのリセットに見える。パターン2は `0x1B` が残っているので
**誰かが I2C で意図的に落としている**。ESP32 は `0x40`/`0x41`/`0x42` しか書かないので、
XMOS の仕業ということになる。

⚠ **`creg` が正常値でも音が出ないことがある。生死の判定材料としては不十分。**

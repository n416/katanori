# 未着手・未検証の一覧

「肩に載せて持ち歩ける自立ロボット」として人に渡すために、まだ無いもの。
会話まわりは動いているが、**それ以外がほぼ手つかず**。

判断のために「渡すのに必須か」で分けてある。

持ち歩く前提の記述が無く、ここは設計そのものが未着手。

| 🔴 | **マスタースイッチ（完全遮断）** | つまみのOFFはEN制御＝**ファームが生きていないと効かない**。今の最後の手段「USBを抜く」は、電池を積んだ瞬間に消える（電池が給電し続ける）。ハングした機体を止める手段が「電池切れを待つ」だけになるため、**電池搭載とセットで必須**。電池と昇圧の間（放電経路）にスライドスイッチ（定格2A以上・実流約700mA）。充電IC〜電池間には入れない＝OFFのまま充電は可能な配置にする。READMEの「スピーカー線に物理スイッチ」（音の安全弁・轟音対策）とは**別物**。日常のON/OFFはつまみ、これは裏面の奥まった位置に置く保管・緊急用。なお再生中にこれでブツ切りすると次回起動の轟音の穴を踏む（だから日常では触らせない） |
| 🟡 | 充電方法 | 高齢者が扱えるか。USB端子を挿してもらうのか、置くだけにするのか |
| 🟡 | 電池残量の取得 | ADCで測って「充電してね」と喋る。今は残量を知る手段が無い |
| 🟡 | 低消費電力（スリープ） | 未着手。常時Wi-Fi接続だと電池が保たない。会話していない間の設計が無い |
| ⚪ | 発熱 | 肩に載る＝身体に触れる。連続稼働時の温度が未確認 |

## 2.5 音量つまみ（⚠ ハード側に未解決の問題あり 2026-07-29）

> **🔴 次にやること**: **条件ごとに10回ずつ回して、落ちた回数を数える。**
> A=全部繋ぐ / B=スイッチ2本を外す / C=3V3を外す。各条件の前に `knobdis` を撃つ。
> コーデックが死ぬとログに自動で出るので数えるだけ。**今までは各条件1回しか試して
> おらず、結論を出せる材料になっていなかった**（1回目が無事でも2回目に落ちた条件がある）。
>
> 症状・確かめた事実・外れた仮説は [KNOB-TROUBLE.md](KNOB-TROUBLE.md)。
> **回避策**: スイッチの2本を外せば、音量つまみとしては使える（OFF機能だけ失う）。
>
> **完了**: つまみで音量が変わり、OFF位置で会話停止＋消音になるところまで実機確認済み。
> 途中で3V3-GND短絡事故（復旧済み）と、beepの退行バグ発見（修正済み）あり。
> 経緯は firmware/esp32/README.md の音量つまみ節を参照。
>
> **進捗**: 部品を購入しユニバーサル基板へ実装、実機で起動確認済み。
> ファームは `pumpVolumeKnob()`（main.cpp）として実装済み — D0のADCを1/8 IIR＋
> デッドバンド2%で読み、dB直線カーブで再生ゲインへ反映。連動スイッチはD1を
> INPUT_PULLUPで読み（ON位置=閉=LOW）、OFF位置で会話終了＋出力ゲート閉。
> 確認コマンド `knob`。実際の配線は firmware/esp32/README.md の表が正。
>
> **疑似電源OFF（2026-07-29 追加・実機未確認）**: OFF位置で、2秒後にOLED消灯、
> 5秒後に `wsDisconnect()`＋Wi-Fi停止（`WIFI_OFF`）→ユーザーLED消灯。段階の途中で
> ONへ戻せば、落とした分だけ戻る（落ちていない段階は実行されない）。一気に落とさない
> のは、回し切る途中で一瞬OFFを通ることと、すぐ戻したときにWi-Fi再接続で十数秒
> 待たされるのを避けるため。`pumpPowerDown()`（main.cpp）。
> **昇圧ICのEN制御はこの5秒後の処理の最後に足す** — そこに置けば
> ミュート→切断→電源断の順序が構造的に守られる。
>
> **未了**: コーデックDACデジタル音量（0x41/0x42）への一本化（下記ソフト側の項）は
> 今回見送り。現状は従来どおり `gain_`（サンプル掛け算）に反映している。

シリアルの `vol` でしか音量を変えられないのは、渡す相手にとって使えないのと同じ。
**物理のつまみにする。** 高齢者に一番伝わるUIで、説明が要らない。

**スイッチ付きボリュームを選ぶ。** 左に回し切ると電源OFF（昔のラジオと同じ）。
これで [1.電源](#1-電源バッテリー) の「電源スイッチ」も同時に片付く
（実際に電源が切れるのは昇圧ICのEN制御が載ってから。それまでは疑似電源OFF）。

| 項目 | 値 |
|---|---|
| カーブ / 抵抗値 | **B（直線）** / 10kΩ ±20% |
| 定格電力 / 最高使用電圧 | 0.08W / 150V |
| 回転角 | 230°±5° |
| 寸法 | φ12.4mm × 高さ **7mm**（薄型・つまみ一体） |
| 実装 | 基板取付（ピン端子） |
| **スイッチ定格** | **DC12V 0.5A**（S.P.S.T、接点抵抗50mΩ以下） |
| 寿命 | VR 15,000回 / SW 10,000回 |

Bカーブなのでソフト補正が要らない。**スイッチ付きでBカーブは少数派**（スイッチ付きは
音量つまみで機器の電源も入れるアナログ機器の作法から生まれた部品なので、通常はAカーブ）。

同じ秋月の「基板取付用ボリューム つまみ付き 薄型 10kΩB 2連」（ALPS RK10J、¥100）は**採らない**。
2連はステレオの左右を同時に絞るための部品で、ADCで1系統読むだけの用途では片側が無駄になり、
かつスイッチが無い。

### 繋ぎ方

XIAO の **D0〜D3（GPIO1〜4）が未使用**で、いずれもADCが使える。

```
3.3V ──┬── ボリューム両端 ── GND
        中点 ──> D0 (GPIO1) でADC読み取り
        スイッチ ──> GPIOで状態を読む（電源線には入れない。理由は下記）
```

**音声信号の経路には入れない。** アンプ出力に可変抵抗を挟むと、熱として捨てるだけで音も悪くなる。

### スイッチは電源線に直結しない（EN制御にする）

**定格が DC12V 0.5A しかないため。** 電池側に流れるのは、会話中の5V×450mAを3.7Vから
昇圧効率85%で取るとして**約700mA**で、定格を超える。昇圧後の5V側に入れても300〜450mAで
余裕がなく、起動時の突入電流で超える。

代わりに、

1. スイッチ → GPIOで**状態を読むだけ**（流れるのは数μA。定格は無関係になる）
2. マイコン → コーデックをミュート → 昇圧ICのEN端子を落として電源断

**この順序が保証されると、起動時の轟音の穴も塞がる。** 現状は「再生中に電源が切れると
ミュート解除のまま保持され、次回起動でROMブートログが増幅される」という穴があり、
ソフト単独では塞げない（[3.ファームウェア](#3-ファームウェア)）。EN制御にすれば
**常にミュートしてから電源が切れる**ため、構造的に解決する。

### ソフト側

- ADCを読んで、**コーデックのDACデジタル音量**（`0x41`/`0x42`、0.5dBステップ）に反映する
- 今の `gain_`（サンプルを掛け算する方式）はビットを削るので、コーデック側へ一本化したい
- `setOutputMute(false)` が `0x41`/`0x42` に 0dB を書いているので、そこを
  「現在のつまみの値」を書くように変える
- ESP32のADCはノイズが多い。移動平均＋デッドバンド（0.5dB未満の変化では書かない）を入れる
- 耳を守るため**上限を設ける**。8Ω 2Wのスピーカーに対しアンプは5Wまで出せる

## いま止まっている理由の整理

会話（レベル0）は動くところまで来た。次に大きいのは**この一覧の🔴**で、
そのほとんどが**ソフトではなくハードと運用**にある。

特に、順番として効くのは3つ。

1. **消費電流を測る** — バッテリー容量も筐体サイズも、この数字が無いと決まらない。
   USBに電流計を挟むだけで測れる。ここが全ての前提
2. **OTA更新** — これが無いまま筐体に封入すると、以降ファームを直せなくなる。
   **筐体を作る前**に入れておくべき
3. **認証と個体管理** — 2台目を作る時点で必ず要る。人に渡す前提なら早い方がいい

呼びかけ検知（WAKEUP.md）は🟡相当。ボタンでも会話は成立するため、
上の3つより優先度は下。

# 未着手・未検証の一覧

「肩に載せて持ち歩ける自立ロボット」として人に渡すために、まだ無いもの。
会話まわりは動いているが、**それ以外がほぼ手つかず**。

判断のために「渡すのに必須か」で分けてある。

| 記号 | 意味 |
|---|---|
| 🔴 | これが無いと人に渡せない |
| 🟡 | 渡せるが、実用で困る |
| ⚪ | あとで良い |

関連: [WAKEUP.md](WAKEUP.md)（呼びかけ検知） / [../仕様書.md](../仕様書.md) / [../README.md](../README.md)

## 1. 電源・バッテリー

**仕様書には「ReSpeaker Lite USB-C (5V給電)」としか書かれていない。**
持ち歩く前提の記述が無く、ここは設計そのものが未着手。

| | 項目 | 内容 |
|---|---|---|
| 🔴 | バッテリー搭載 | 現状USB給電のみ。肩に載せるなら電池が要る。XIAO ESP32S3 は充電回路内蔵でリポを繋げるが **3.7V**。ReSpeaker Lite は **5V** 必要なので昇圧回路が要る。ここが設計の分かれ目 |
| 🔴 | 消費電流の実測 | **一度も測っていない。** ESP32＋XMOS＋OLED＋アンプで、稼働時間がまったく読めない。容量を決められない |
| 🔴 | 電源スイッチ | 物理スイッチが無い。USBを抜き差ししている。轟音問題（再生中の電源断でミュートが解除のまま残る）とも直結 |
| 🟡 | 充電方法 | 高齢者が扱えるか。USB端子を挿してもらうのか、置くだけにするのか |
| 🟡 | 電池残量の取得 | ADCで測って「充電してね」と喋る。今は残量を知る手段が無い |
| 🟡 | 低消費電力（スリープ） | 未着手。常時Wi-Fi接続だと電池が保たない。会話していない間の設計が無い |
| ⚪ | 発熱 | 肩に載る＝身体に触れる。連続稼働時の温度が未確認 |

## 2. 筐体・装着

**未設計。** 基板とスピーカーがむき出しの状態。

| | 項目 | 内容 |
|---|---|---|
| 🔴 | 筐体の設計 | 3Dプリント前提だとして、まだ形が無い。OLEDの窓・スピーカーの開口・マイクの開口・配線の逃げ |
| 🔴 | 肩への固定方法 | クリップか、ベルトか、磁石か。**落ちないこと**と**着けやすいこと**の両立。高齢者が自分で着脱できるか |
| 🔴 | 重量とバランス | 肩に載せて疲れない重さ。電池を積むと重心が変わる |
| 🟡 | スピーカーのキャビティ | 仕様書に「キャビティ付き」とあるが、筐体側で作るのか既製品か未決 |
| 🟡 | アンテナの取り回し | 外付けアンテナ必須（未接続だとRSSIが40dB悪化）。筐体内のどこに這わせるかで通信品質が変わる |
| 🟡 | 配線の固定 | 現状はジャンパ配線。持ち歩くと確実に外れる |
| ⚪ | 防滴・清掃 | 食事中に着けている可能性。拭ける形かどうか |

## 3. ファームウェア

| | 項目 | 内容 |
|---|---|---|
| 🔴 | **OTA更新** | 現状USB書き込みのみ。**渡したら直せない。** 今日だけでもファームを5回書き換えている。手元に無い機体を更新する手段が要る |
| 🟡 | クラッシュ復帰 | ウォッチドッグ・例外時の自動再起動が未整備。固まったら電源を抜くしかない |
| 🟡 | ログの保存 | シリアルにしか出ない。渡した後は何が起きたか分からない |
| 🟡 | 起動時ミュートの穴 | 再生中に電源が切れると解除状態が残り、次回起動で轟音。ソフトでは塞げない（物理スイッチが確実） |
| 🟡 | バージイン（割り込み）の実機確認 | ハードウェアAECを使う前提だが、実機で「喋っている最中に遮る」が成立するか未確認 |
| ⚪ | 時刻同期 | 機体は時計を持たない。今はDOが接続時に時刻を渡している。単体で時間を扱うならNTPが要る |
| ⚪ | 音量調整の手段 | シリアルの `vol` のみ。利用者が変える方法が無い |

## いま止まっている理由の整理

会話（レベル0）は動くところまで来た。次に大きいのは**この一覧の🔴**で、
そのほとんどが**ソフトではなくハードと運用**にある。

特に、順番として効くのは3つ。

1. **消費電流を測る** — バッテリー容量も筐体サイズも、この数字が無いと決まらない。
   USBに電流計を挟むだけで測れる。ここが全ての前提
2. **OTA更新** — これが無いまま筐体に封入すると、以降ファームを直せなくなる。
   **筐体を作る前**に入れておくべき
3. **認証と個体管理** — 2台目を作る時点で必ず要る。人に渡す前提なら早い方がいい

呼びかけ検知（WAKEUP.md）は🟡相当。ボタンでも会話は成立するため、
上の3つより優先度は下。

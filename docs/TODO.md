# 未着手・未検証の一覧

「肩に載せて持ち歩ける自立ロボット」として人に渡すために、まだ無いもの。
会話まわりは動いているが、**それ以外がほぼ手つかず**。

判断のために「渡すのに必須か」で分けてある。

| 記号 | 意味 |
|---|---|
| 🔴 | これが無いと人に渡せない |
| 🟡 | 渡せるが、実用で困る |
| ⚪ | あとで良い |

関連: [WAKEUP.md](WAKEUP.md)（呼びかけ検知） / [../仕様書.md](../仕様書.md) / [../README.md](../README.md)

**仕様書には「ReSpeaker Lite USB-C (5V給電)」としか書かれていない。**
持ち歩く前提の記述が無く、ここは設計そのものが未着手。

| | 項目 | 内容 |
|---|---|---|
| 🟡 | バッテリー搭載 | **✅ 電池駆動を実機で確認済み**（2026-08-01。PowerBoost 1000C ＋ リポ3.7V 1000mAh。スピーカーを鳴らしたまま20分連続で問題なし）。**「1Aで足りるか」はこれで決着**。残るのは①稼働時間の実測（容量の確定）②筐体への組み込み③下の「EN制御の自己遮断」。構成は [POWER.md](POWER.md) |
| 🔴 | **リードスイッチでEN遮断** | **方針決定（2026-08-01）: つまみOFFで完全に落とす**（起動は数秒なので疑似電源OFFで待機電力を垂れ流す意味が無い）。ファームでENを落とすと発振する（自分の電源を切るとGPIOがHi-Zになりプルアップで復帰）ため、**磁石で閉じるリードスイッチを EN⇔GND に入れる**。保持は機械が担う。ミュートの順序は**リードが閉じる数度手前にAS5600の角度閾値を置く**ことで担保。トグルスイッチは並列に入れて非常用。⚠ **磁石が2つになりAS5600へ干渉する**risk あり。設計は [POWER.md](POWER.md) |
| 🔴 | 消費電流の実測 | **一度も測っていない。** 推定では会話中300〜450mA・待機200〜300mA だが、XMOSの消費が非公開で不確定。USB電流チェッカー（1000円前後）を挟めば1点で測れる。[POWER.md](POWER.md) |
| 🔴 | 電源スイッチ | **ソフトは実装済みだが、ハード側が未解決**（下の 2.5。回すとコーデックが死ぬ。半田をやり直しても再発）。以下はソフト側の話: 左に回し切ると会話終了→2秒で画面消灯→5秒でWi-Fi停止まで落ちる（**疑似電源OFF**）。ただし電源基板が無いので**本当に切れてはいない**（XMOSは生きたまま）。残るのは昇圧ICのEN制御だけで、これは「バッテリー搭載」が終わるまで着手できない。轟音問題（再生中の電源断でミュートが解除のまま残る）もEN制御が載って初めて構造的に消える |
| 🔴 | **マスタースイッチ（完全遮断）** | つまみのOFFはEN制御＝**ファームが生きていないと効かない**。今の最後の手段「USBを抜く」は、電池を積んだ瞬間に消える（電池が給電し続ける）。ハングした機体を止める手段が「電池切れを待つ」だけになるため、**電池搭載とセットで必須**。**入手済みのトグルスイッチ MTS-102 を PowerBoost 1000C の `EN`⇔`GND` に入れる**（当初想定の「電池と昇圧の間の放電経路」は、PowerBoost では電池JSTが充電器と共用のため採らない。ENなら昇圧だけ止まり、OFFのまま充電できる）。流れるのは信号レベルのµAなので定格は無関係。READMEの「スピーカー線に物理スイッチ」（音の安全弁・轟音対策）とは**別物**。日常のON/OFFはつまみ、これは裏面の奥まった位置に置く保管・緊急用。なお再生中にこれでブツ切りすると次回起動の轟音の穴を踏む（だから日常では触らせない） |
| 🟡 | 充電方法 | 高齢者が扱えるか。USB端子を挿してもらうのか、置くだけにするのか |
| 🟡 | 電池残量の取得 | ADCで測って「充電してね」と喋る。今は残量を知る手段が無い。**PowerBoost 1000C の `LBO` ピン**（電池が3.2Vを切ると0Vに落ちる）を使えば GPIO 1本で「もうすぐ切れる」が取れる。段階的な残量が要るなら `BAT` をADCで読む |
| 🟡 | 低消費電力（スリープ） | 未着手。常時Wi-Fi接続だと電池が保たない。会話していない間の設計が無い |
| ⚪ | 発熱 | 肩に載る＝身体に触れる。連続稼働時の温度が未確認 |

## 2.5 音量つまみ

シリアルの `vol` でしか音量を変えられないのは、渡す相手にとって使えないのと同じ。
**物理のつまみにする。** 高齢者に一番伝わるUIで、説明が要らない。
**左に回し切ると電源OFF**（昔のラジオと同じ）にして、[1.電源](#1-電源バッテリー) の
「電源スイッチ」も同時に片付ける。

### 状態

| | |
|---|---|
| ✅ | つまみで音量が変わり、OFF位置で会話停止＋消音（実機確認済み） |
| ✅ | 疑似電源OFF（OFF位置で2秒後にOLED消灯、5秒後にWi-Fi切断） |
| 🔴 | **回すとコーデックが死ぬ**（2026-07-30 再発・未解決） |
| 🔒 | **方針確定: AS5600（非接触）へ移行。可変抵抗は使わない**（2026-08-02） |
| ▶ | **次: 治具を刷って回転テスト → ファーム書き換え** |

設計は [KNOB-ENCODER.md](KNOB-ENCODER.md)、症状の切り分けは [KNOB-TROUBLE.md](KNOB-TROUBLE.md)。

### 🔴 回すとコーデックが死ぬ

つまみを回すと音が出なくなり、USBを抜き差しするまで戻らない。半田をやり直したら
止まったように見えたが、**再発した**。

**一番強い事実: 死ぬのは回している最中で、スイッチが開く4.9秒前。**
ソフトが動くのは全部そのあとなので、**ファームの経路は完全に無関係**。

**AS5600へ移行すれば、原因を特定しないまま症状ごと消える見込み。** 回るのは磁石だけで、
基板も配線も静止したままになる。**連動スイッチの2本も無くなる**（OFFは角度の閾値で判定）
ので、一番疑われていた配線が丸ごと消える。→ **印刷した治具での回転テストで確認する。**

⚠ **延命策（3V3線に1kΩ直列）はやらない。** 移行が決まったので、外す部品に手を入れない。
なおこの1kΩは**AS5600には使えない**（6.5mA食うので6.5V落ちる）。AS5600側の保護は
3V3のバルクコンデンサか配線の作り込みで考える。

⚠ **`WIFI_OFF` は無罪。** 一度これを犯人だと結論づけて実装と文書を書き換えたが誤りだった
（commit 4a97a49、取り消し済み）。根拠にした試験が「つまみを回す」操作を含んでいて、
そちらが犯人だった。**一度に1つしか変えないこと。**

### 移行後の姿

| 役割 | 旧（可変抵抗） | 新（確定） |
|---|---|---|
| 音量の入力 | D0のADCで分圧を読む | AS5600の絶対角度をI2Cで読む |
| OFFの検知 | 連動スイッチをD1で読む | **角度の閾値** |
| OFFの実行（電源断） | 同上 | **リードスイッチ＋磁石**が `EN`⇔`GND` を切る（[POWER.md](POWER.md)） |
| 軸受け・回転止め・デテント | 部品に内蔵 | **全部3Dプリント**（[KNOB-ENCODER.md](KNOB-ENCODER.md)） |

**UXは変わらない**（軸の向きを見れば音量が分かる）まま、接点のある部品が無くなる。

### いま載っているもの（移行で外す）

**RV121SF-20-02J-B10K-00K11**（10kΩ Bカーブ・SPST連動スイッチ付き・回転角230°・
φ12.4 × 高さ7mm・基板取付）。手はんだの熱でカーブが歪んでおり、ソフトの実測テーブル
（`kKnobCurve`）で補正して使っている。**買い足さない**（[SHOPPING.md](SHOPPING.md)）。

ファームは `pumpVolumeKnob()`（main.cpp）— D0のADCを 1/8 IIR ＋ デッドバンド2%で読み、
dB直線カーブで再生ゲインへ反映。連動スイッチはD1を INPUT_PULLUP で読み（ON位置＝閉＝LOW）、
OFF位置で会話終了＋出力ゲート閉。確認コマンド `knob`。疑似電源OFFは `pumpPowerDown()`。
**配線は [firmware/esp32/README.md](../firmware/esp32/README.md) の表が正。**

### 電源断は「スイッチで電源線を切る」のではなくEN制御にする

**これは移行後も変わらない設計。** 順序はこう:

1. OFFを検知（旧＝スイッチ / 新＝角度の閾値）
2. マイコンがコーデックをミュート → 会話停止 → Wi-Fi切断
3. **昇圧ICのEN端子が落ちて電源断**（新＝リードスイッチが機械的に落とす）

**この順序が保証されると、起動時の轟音の穴も塞がる。** 現状は「再生中に電源が切れると
ミュート解除のまま保持され、次回起動でROMブートログが増幅される」という穴があり、
ソフト単独では塞げない（[3.ファームウェア](#3-ファームウェア)）。
EN制御なら**常にミュートしてから電源が切れる**ため、構造的に解決する。

⚠ **ファームからENに触らない**（触ると発振する）。落とすのはリードスイッチの役目。

### ソフト側の宿題（移行後も残る）

- **コーデックのDACデジタル音量**（`0x41`/`0x42`、0.5dBステップ）へ一本化する。
  今の `gain_`（サンプルを掛け算する方式）はビットを削る
- `setOutputMute(false)` が `0x41`/`0x42` に 0dB を書いているので、そこを
  「現在のつまみの値」を書くように変える
- 耳を守るため**上限を設ける**。8Ω 2Wのスピーカーに対しアンプは5Wまで出せる

## いま止まっている理由の整理

会話（レベル0）は動くところまで来た。次に大きいのは**この一覧の🔴**で、
そのほとんどが**ソフトではなくハードと運用**にある。

特に、順番として効くのは3つ。

1. **稼働時間を測る** — バッテリー容量も筐体サイズも、この数字が無いと決まらない。
   **「電源が足りるか」はもう答えが出ている**（PowerBoost 1000C ＋ 1000mAh で
   スピーカーを鳴らしたまま20分連続動作・2026-08-01）。残っているのは
   **1000mAhで何時間持つか**で、これは電流計を挟むより**LBOが落ちるまで動かして
   時計を見るほうが直接的**（推定では会話1.5時間・待機2時間）
2. **OTA更新** — ~~これが無いまま筐体に封入すると、以降ファームを直せなくなる~~
   **済み(2026-08-03)**。同一LAN内のOTAは実機確認済み。残るのは遠隔更新(4章の認証と同根)
3. **認証と個体管理** — 2台目を作る時点で必ず要る。人に渡す前提なら早い方がいい

呼びかけ検知（WAKEUP.md）は🟡相当。ボタンでも会話は成立するため、
上の3つより優先度は下。

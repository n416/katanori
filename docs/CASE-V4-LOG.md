## 12. 意匠の追い込みと、それが呼んだ追従（2026-08-25 午後）

出発点はユーザーの一言でした。「フロントパネルと、スピーカーのベベルがすこし大味すぎるので、すこし掘りをゆるめてください」。
掘りを浅くすると画面や振動板が奥に引っ込むので、**浅くした分だけ相手を近づける**のが全体の方針です。
どちらを動かすかは面ごとに違い、フロントは板を動かし、天面は他部品の兼ね合いが大きいのでスピーカーを持ち上げました（どちらもユーザー指定）。

### 12.1 フロント: 窓の裏を彫って壁を 1.0 にし、板ごと 1.0 ハッチ寄せ

OLED のガラスの面は内面 Y=0 にあり、板の内面とツライチです。ここで**板の裏**を窓のまわりだけ 1.0 彫ると、
そこだけ壁の厚みが 2.0 → 1.0 になります（`WIN_SUNK = 1.0`）。彫り込みの縁は段ではなく 45° で開きます。
段にしなかったのは、輪郭が増えて「変」になった充電口の初版と同じ顔を避けるためです。
さらに板そのものを 1.0 だけハッチ寄せ（`FRONT_DY = 1.0`）すると、彫り込みの底がガラスの面に届き、
**外から見た窓の深さが 2.0 → 1.0** になります。外面は平らのままなので、外から見える顔は変わりません。

- 板の前後位置は `FY_OUT`（外面）と `FY_IN`（内面）の 2 つの式に集約しました。既定は `FRONT_DY = 0` なので v1〜v3 の形は変わりません。
- 板が 1.0 内側へ入った分、床・左右の壁・天面・耳の柱は前端がその位置まで詰まります。
- 窓のベベル `WIN_CH` は 1.2 → **0.6**（板厚の 6 割 → 3 割）。マイクのヒゲと口のベベルは触っていません。
- 彫り込みが窓の外へ出る量 `WIN_SUNK_M = 2.5` は ⚠ 仮の値です。

🔴 **継ぎ目の 45° を切り直し忘れて角が開いた。** 天面とフロントを分ける斜面の蝶番が Y=0 に固定されていたため、
板を寄せたあと旧い斜面と新しい板の間に楔形の欠けが 1mm³ 開きました（ユーザー「この穴はふさがないんですか？」→「天板の斜めを切り直してないからだね」）。
`seam_top_half` / `seam_front_half` の起点を `FY_IN` に追従させて 0 になりました。

🔴 **マイクのヒゲ（貫通スリット）を一度消した。** `whisker_cut` の中の `fy` は**相対値**で、呼び出し側の translate に
既に `FY_OUT` が乗っています。そこを二重に補正したためスリットが外面へ届かなくなり、穴が消えました。
ヒゲは v2 から一貫して**外面のベベル＋内面まで貫くスリットの 2 段**で、飾りの溝ではありません。

### 12.2 天面: へこみを浅くした分だけスピーカーを持ち上げる

天面の板は他の部品との兼ね合いが大きいので動かさず、代わりにスピーカーを上げました。

| | 前 | 後 |
|---|---|---|
| へこみ `EMB_H` | 1.2 | **0.6** |
| スピーカーの持ち上げ `SPK_LIFT` | — | **+0.6** |
| 振動板の逃げ `SPK_REL` | 0.4 | **1.0** |
| 振動板 → 外面の距離／グリルの長さ 0.9 | | **据え置き** |

持ち上げると振動板だけでなく**スピーカーの枠（23×15）**が天板に 0.4 食い込みます。逃げが振動板（15×9）の分しか無かったためです。
枠の座を深さ 0.6・片側 0.3 で掘って解消し、`part="chk_top_spk"` で見張るようにしました。

### 12.3 傾斜の座とネジ（🔒 ユーザー「固定具作って下さい」→「ネジにしないと逆さまにしたら落ちちゃう」）

電流計と PowerBoost の 10°（`THETA`）は**座標の回転だけ**で、前縁の下は空でした。浮きは PowerBoost が 3.97、電流計が 3.49 で、
実機なら組んだ瞬間に落ちます。留め帯 A/B/C の天板の上に座を立てて解決しました。

- 座の面は板の裏から `SEAT_GAP = 0.3` 下げ、**ビス 6 か所だけ φ5 のパッド**で板に届かせます。こうすると板の裏の足
  （電流計の L ヘッダ 1.2・PB の 8 ピン列 1.0）は掘らなくても全部逃げます。
- ネジは**鉛直**です。板に直角にするとナットが 10° 傾き、角が天板の裏から 0.35 はみ出して**電池の頭を突きます**（`seathw` で 6mm³ として出た）。
  鉛直ならナットは天板の裏に平らに座ります。頭は 10° の板に片当たりになりますが、M2 の頭 φ3.0 での話です。
- 座と穴は板と同じ変換（`ina_frame` / `pb_frame`）を通しているので、`THETA` や板の位置を動かせば全部追従します。

🔴 **プレビューを破裂させた。** 板の裏の足を「板の CSG を 7 方向にずらして引く」で逃がしたところ、
CSG の正規化が 20 万要素を超えて**空の木**になり、ユーザーの画面が真っ白になりました。`--render`（Manifold）でしか
検算しておらず、F5 の経路を通していなかったのが原因です。上の「座を下げてパッドで受ける」方式に変え、
座の柱も `roof` 依存の `prism_y` をやめて素の cube にしました。

### 12.4 ネジとつまみの +2

ユーザー指示で、天面と底面の**前**のネジ 2 本ずつと、つまみを 2mm ハッチ方向へ動かしました
（後ろのネジは Y 65〜72 でハッチの内面にべったりなので動かせません）。耳は Y 0〜8 → 2〜10、床の前ビスの柱は +2、つまみは +5 → +7 です。
これに伴う追従は、島のノッチを板の後端まで延長したこと、リードの線の潜り点を +2 したこと、
耳の柱と床の右前の柱が ReSpeaker の板の帯に当たる分を欠いたことの 3 つです。

### 13.1 順番を決めたのは 2 つの制約

1 つめは **ハブの口 10 本の上にブリッジの皿と帯が載る**ことです。皿は `Z 21.4〜23.4・X 13〜53`、
壁〜壁の帯は `Y 50.5〜62.9` の全幅で、その真下に口がある束（XIAO・つまみ・BTN2・スピーカー IN/OUT）は
ブリッジを載せた後では届きません。だから**ハブの口は全部ブリッジより先に挿す**ことになります。

2 つめはその裏返しで、**皿や帯の上を通る束**（OLED・INA の I2C・トグル・リード・充電）を先に上げてしまうと、
今度はブリッジが降りません（`CHK="brg_bad"` で **846mm³**）。この 5 束はハブ側の口が左の溝か後ろの縦穴にあり、
ブリッジの後でも挿せるので、**低い車線を先・上の車線を後**に分けました。

この 2 つから出た順番が次の 12 段です。
**① 床にハブ → ② ReSpeaker と Type-C → ③ ハブの口 10 本と低い車線 → ④ 左右の壁と床の 3 本 →
⑤ ブリッジ → ⑥ 電池 → ⑦ 留め帯 → ⑧ 電流計と PowerBoost → ⑨ OLED と上の車線と電源系 →
⑩ 天面の小組と天面側の配線 → ⑪ 天面を降ろしてフロント → ⑫ トグル・ハッチ・蓋・尻尾。**

電池と留め帯と基板を OLED より先に入れるのは、上の車線が電池の真上（`Z 45.2` の OLED の線など）を通るためです。
先に線を上げると電池も帯も基板も真下へ降ろせなくなります（それぞれ 570 / 256 / 573mm³）。

### 13.6 ナットを横から差す捕捉溝（2026-08-25 夜・ユーザー「留め帯の形状を変えても構いません・パーツを追加してもいいです」）

形を変えてよいという許可が出たので、留め帯のナットを**横穴**（側面から差す捕捉溝）に替えました。
六角の穴を高さ 1.7 で開け、帯の一番近い面まで幅 4.3 の通路でつなぎます。ナットは横から差し、
上（天井）と下（床）の肉で閉じ込められるので、帯をどう向けても落ちません。通路の壁が二面幅を挟むので回り止めにもなります。

**上下をひっくり返す案は不可です。** ネジは板の上から来るので、ナットが締める物の反対の端（＝天板の裏側）に
居ないと座を挟めません。上向きにすると板とナットが直に噛むだけで、座は締まりません（床のビスと同じ理屈）。
**横は成立します。** 締める力は天井が受けますが、天井は板とナットの間で**押されるだけ**（曲げではない）なので薄くてよく、

## 15. T-2 の直しと、それが呼んだ追従（2026-08-26・つまみとスピーカーを内側へ 4）

### 15.1 犯人を取り違えた

|---|---|---|
| 天板と L だけ | 8.00 | 8.00 |
| つまみ一式だけ | 8.00 | 8.00 |
| **スピーカーだけ** | 8.00 | **1.29** |

正体は**スピーカーの右前の丸み**（前端 `Y 6.8` ＝ L の裏の面 `6.6` の 0.2 奥）でした。

### 15.2 直し方（🔒 全部ユーザーの指示）

1. 「スピーカーを少しだけ**内側**に移動すればいいのでは」「つまみも一緒に」「**両方を +4 移動させてください**」
   → つまみとスピーカーを**内側（−X・右壁から離す向き）へ 4**。`KNOB4` `SPK4` とも `X 67.204 → 63.204`。
   ⚠ AI は「内側」を +Y（奥）と読み違えて一度 Y で実装しました。この repo では 2026-08-25 の
   🔒「少しだけ内側へ」が **+X を +3 → +1.5 に減らした**記録として残っていて、**内側＝−X** が正です。
   この 4mm は T-2 と別に、**上から見たときのつまみの位置のバランス**（UI）が目的でもあります。
2. 動かすと座の**柱**（AS5600 を吊る 4 本・各 9.9 × 7.9）が INA226（29.2mm³）と PowerBoost（11.7mm³）の
   板に乗りました。柱は削れません（中心にナットの小判スロットが入っていて、左右に残る肉は片側 2.7mm）。
   → 「**バッテリー自体のってるブリッジの帯ごと左に 4mm 移動**」で `BAT_DX` を +1 → **−3**。
   電池・皿・脚・帯 A/B/C・座・両基板が `BAT_X0` から出ているので、この 1 つでまとめて動きます。
   これで柱と両基板の当たりは**完全に 0** になりました。
3. 帯ごと動かすと、今度は INA226 の INPUT/OUT が左の壁に当たりました（板の左端 `1.30` ／ 壁の内面 `1.694`）。
   → 「**INA の傾斜を無くして、左壁側のピンヘッダを垂直にしたらどうだろう**」で
   **INA226 だけ水平（`INA_THETA = 0`）＋電源の口を直立て（`pwr_ra = false`）**。
   ⚠ AI は最初 `ra`（I2C の 5 ピン）を立てて取り違えました。座標で確かめたところ、
   **左壁側の口は電源（INPUT/OUT 4 本）** で `X 4.03〜17.07`、I2C は `X 38.50〜41.80` の右側でした。

### 15.5 電流計の座の 0.1mm（同日・`INA_LIFT`）

水平にしたぶん電流計の座は `2.5`（帯の天板 2.0 ＋ 板の浮き 0.5）しか無く、**M2×4 の先と帯の天板の裏
＝電池の上面が 0.1mm** でした。断面を見る絵を `part="seatgap"` で足して（[_v4_seatgap_zoom.png](../hardware/_v4_seatgap_zoom.png)）、
🔒 ユーザー「0.1 はきついですね」。

ユーザーの問い「**浮きをふやしたらネジの長さは長くすべきなのでは**」への答えは **いいえ** です。
この座はナットが**天井**に居ます（`slot_ceil` ＝ 板の裏から 0.4 下）。板を浮かせるとナットも一緒に上がるので、
ネジから見た距離は動かず、増えるのは**ナットの下の床**だけです。実測で確かめました。

| 電流計の座 | 浮き 0.5 | 浮き 1.0（`INA_LIFT`） |
|---|---|---|
| ナットの上面（板の裏から） | −0.4 | **−0.4（変わらず）** |
| 掛かり | 1.6 | **1.6（変わらず）** |
| ナットの下の床 | 0.4 | 0.9 |
| **ネジの先 → 電池の上面** | **0.1** | **0.6** |

`seat_d` / `seat_nut_d` / `slot_ok` / `seat_nut_ceil` / `seat_hole` / `seat_bolt` に `lift` 引数を足し、
電流計だけ `INA_LIFT` を通しています（既定は `BOARD_LIFT`＝PowerBoost 用）。
板の頭（直立ての口）が `46.0 → 46.5` になるので、そこから出る電源 4 本も `46.8 → 47.3` へ追従。

🔴 このとき `46.8]` を一括置換して**トグルの線まで巻き添えで上げ**、欠き ④ の天井（`Z 48.0`）を
0.05 超えました（`chk_all` 0.88mm³）。座標の一括置換は、当たった行を必ず目で確かめること。


## 16. 蓋のスライドを下から横へ（2026-08-26・[case_v4_shutter.scad](../hardware/case_v4_shutter.scad)）

出発点はユーザーの指摘です。「v4 のバッテリーのロック機構は v3 のものを 180 度回転させてしまっている。
こんな事をするとロックが無いと蓋が空いてしまうので 1 から考え直さないといけない」。

そのとおりでした。v3 の蓋は**上へ持ち上げて外す**型なので、手を離せば自重で閉じ位置に戻り、ロックは念のための止めでした。
§11 はそれを 180° 回したので、自重がそのまま開く向きに効きます。ロックのビスを外した瞬間、蓋を押さえているのは
φ6×2.0 の磁石 2 個だけになる。ファイル冒頭には v3 の「外せば磁石だけで開閉」という文言がそのまま残っていて、
v4 では意味が変わっていました。**ロックが念のための止めではなく構造材になっていた**のが誤りです。

### 横へ回せるかを測った

上は §11 のとおり潰れています（線と DuPont）。そこで横を測りました。

- ハッチの面: 帯の右に 36.7mm、左に 8.66mm 空いている。逃がすのに要るのは `SHUT_SLIDE` = 5.5mm
- 中身との当たり: 帯＋裏の増し肉を**右へ** 5.5 伸ばすと **0mm³**。**左へ**だと Type-C 基板に **45.49mm³**
  （あの板はハッチ内面ではなく左壁の内面にベタ付けなので、左端は使えない）
- 横スライドにすると耳が上下（±Z）へ回るので帯が上下に広がる。その最小の外形で当てると、当たったのは
  **PB の L ピン 3 本（`w_pwr3`）だけ**で 59.83mm³。基板にも壁にもボスにも当たらない

**ユーザー指示で 2 枚に分ける案も測りました。**左のパネルを左へ逃がすには帯の左端が X −1.85 まで要り、
ハッチの端は −0.31 なので 1.54mm 足りません。磁石の部屋を左端に置かなければ収まりますが、
**左のパネルの磁石を置く場所が無くなります**。1 枚のまま右へ滑らせれば足りるので、分けていません。

### 形

型は v3 のまま、軸だけ 90° 入れ替えました。

- スライドは **+X（右）**、耳は上下（±Z）、磁石の部屋（`SHUT_EXT`）は口の**左右**
  （口は Z に 7mm しか無いので、磁石を上下には置けない）
- 耳は上下 1 個ずつ・X の中央。v4 と同じで「上下が同じ位置」でないと逃がし口を 1 か所で通れない
- 逃がし口（リップを抜く所）は帯の**右端**。ここにロックが座る
- ロックは 🔒 ユーザー希望で残した。門形の縦棒が帯の右端、脚が左へ、舌（半円）が蓋の右端に乗る。
  ナットは v3 と同じで上から落とし込む

### 意匠（🔒 ユーザーの朱書き）

- **ロックの外端に、ビスを中心にした半円（`SW4_NOSE_R`）を出す**
- **舌が枠に刺さる 2 か所の入り隅の角を取る**（`SW4_FILLET`。膨らませてから縮める処理でまとめて取る）
- **枠の右端の角丸は足先と同じ小さい角にする**（旧 `SHUT_R - SHUT_CL` = 2.25 → `SHUT_LK_RF`）。
  大きい角丸のままだと、半円の左右に丸い耳が残る

🔴 このとき、彫り込みの角丸を手で数字合わせしていたため「ロックは角が取れているのにハッチは角張ったまま」が
上下で 2 回出て、ユーザーに「仕事が粗い」と言わせました。**彫り込みはロックの輪郭そのものから
`offset(r = SHUT_CL)` でくり抜く**ように直しています。ロックの形を変えれば彫り込みが自動で追従するので、
同じ取り残しは起きません。

### 線の引き直し

`w_pwr3` の 3 車線を **Z 32.2/33.7/35.2 → 35.2/36.7/38.2** へ上げました。
下（Z 20 以下）も測りましたが、筐体の芯と信号線でふさがっていて通りません。空いているのは
ハッチ内面ぎわの Z 34.0〜39.25 と、帯より右（X 61〜64）の縦の道だけです。線は帯の上を右へ走り、
その縦の道で下ります。降りる場所は §11 と同じ（X 64/66.5/69）。

**ユーザーから「1mm や 2mm ならハッチを後ろに下げてもいい」という申し出がありましたが、これは効きません。**
帯の裏の増し肉はかわせますが、ロックのナットのボスはハッチから内側へ深く出ているので、
ハッチを下げるとボスがそのぶん奥へ進んで、かえって線に食い込みます（実測で 21.26 → 30.38mm³ に悪化）。

### 検査（manifold・全部 0）

`chk_shut_slide`（右へずらす軌跡）・`chk_shut_out`（蓋を後ろへ抜く）・`chk_lock_out`（ロックを後ろへ外す・新設）・
`chk_swap`（電池を後ろへ抜く）・`chk_wire_pwr`・`chk_wire_sig`。
刷る向きの底 Z も確認済み（`print_shutter` 2.75 高・`print_lock` 3.0 高・どちらも底 Z 0）。

### 交換の手順（§11 から向きだけ変わる）

M2 を 1 本外す → ロックを後ろへ外す → 蓋を**右へ** 5.5 ずらして後ろへ抜く → 電池の JST を抜く → 電池を後ろへ引き出す。

⬜ ユーザー: 蓋の裏 ↔ 電池の尻の遊びの詰め物。ロックを常時締める運用にするか。

## 17. 組む順の掃引で出たブリッジ ↔ J2（2026-08-26・[_v4_core.scad](../hardware/_v4_core.scad)）

**組み立てマニュアル（[assembly_v4.html](../hardware/assembly_v4.html)）の検算で見つかりました。**
静止の検査（`chk_all` ほか §15.4 の一覧）は全部 0 のままなのに、**手順 5「ブリッジを上から降ろす」が成立していませんでした。**

### 何が当たっていたか

皿の左縁 `X 9.00` が、ReSpeaker の **J2（スピーカーのソケット）の右端 `X 10.08`** に **1.08mm** 入っていました。

| 相手 | 量 | 区画 |
|---|---|---|
| J2 ソケットの**実体** | **7mm³** | `X 9.00〜10.08 / Y 12.90〜16.87 / Z 21.40〜23.40` |
| プラグ＋線の**確保空間**（§2 の「面から 15」）| 17mm³ | 同じ X で `Y 16.87〜25.03` |
| 降ろす軌跡 `CHK="brg"` の合計 | 60.5mm³ | 上の 26 ＋ BTN2 の枝 35（枝の相手のタクトは手順 10 の部品なので、この時点では存在しない）|

出どころは §15.2 の 🔒「バッテリー自体のってるブリッジの帯ごと左に 4mm 移動」（`BAT_DX` +1 → −3）です。
皿の左縁が **13.0 → 9.0** になり、**4 のうち最後の 1.08 が J2 に乗りました**。
静止の検査は全部回し直しましたが、**`_asm_sim_v4.scad` の組む順の掃引だけ回していなかった**ので素通りしました。

### 選択肢と代金（測った値）

| | 消えるもの | 代金 |
|---|---|---|
| ① 皿の前左の角を欠く（`X 9.0 → 10.2` を `Y 12.9〜16.9`）| ソケットの実体 7mm³ | 留め帯 A の左足の座が `Y 15.45〜16.9` の 1.45mm だけ幅 2.0 → 0.8 |
| ② ①を `Y 25.1` まで伸ばす | 確保空間も含めて全部 | 帯 A の左足の座 8mm 全部が 0.8 幅＋左の土手の根元 3.6mm が 1.1 幅 |
| ③ 帯ごと右へ 1.1 戻す | 全部（欠き無し）| **落ちる。**板を +0.5 で天面の部品に 0.13mm³・**+1.1 で 3.49mm³**。§15.2 の「柱が INA/PB の板に乗る」が戻る |
| ④ J2 の確保空間を詰める | 確保空間の 17mm³ だけ | **落ちる。**ソケットの実体 7mm³ が残るのでブリッジは降りない |

### 🔒 ユーザーの選択は ①

`BRGJ2_X = 10.2` / `BRGJ2_Y = 16.9` と `brg_j2_cut()` を新設し、`brg_v4()` の `difference()` に足しました。
欠くのは**皿（`Z 21.4〜23.4`）だけ**で、左の土手は `Y 21.45` から始まるので触れていません。

- ✅ ソケットの実体との当たり **7 → 0**（掃引・静止とも）。`CHK="brg"` は 60.5 → **46.4**。
- ⬜ 確保空間へ **16.3mm³** 残る（`W="brgchk"`）。「基板面から 15」は仮の包絡なので、
  **PHR-2 の尻の実測が出るまで保留**というのが ① の中身です。
- 留め帯 A の左足の角とソケットの頭は **0.09mm** 重なりますが（`X 9.23〜10.08`・0.08mm³）、**項目にしません**。
  ユーザーの手の精度は 0.3mm で、印刷の公差より小さい値です。**検査の非ゼロを全部項目に格上げすると宿題が際限なく増える**ので、
  この筐体では **0.3mm 未満の重なり／0.5mm³ 未満の当たりは報告しない**ことにします（0 厚の膜と同じ扱い）。

### 掃引の検査（2026-08-26・欠きを入れた後）

`CHK="bat"` / `"whigh"` / `"top_oled"` は 0。`"strap"` `"strap_dry"` は 0.57（帯 A の左足 ↔ J2 の確保空間・上記）。
`"boards"` 12.0 のうち 11.4 は BTN2 の枝（手順 10 の部品）で、残り 0.6 が電流計の縁 ↔ 帯 A の座（§既知）。
反例は `"rsp_after"` 444・`"brg_bad"` 1037・`"strap_top"` 81・`"strap_bad"` 201・`close_desk` 156 で、**順番の縛りは効いています**。


## 18. 4 度目の机上の通し（2026-08-27・[assembly_v4.html](../hardware/assembly_v4.html)）

3 度目までの検査は、**部品が通るか**（当たり体積）と**ビス・ナット・指の道**（円筒の探針）でした。

  ⇒ 手順 4 の行に「**板を手に持っているうちに挿す**」を書きました。CAD は触っていません。
- **スピーカー IN の J2 側**。手順 5 で皿（`X 9〜49・Z 21.4〜23.4`）が真上に載ります（真上から φ5 が 22.6mm ＝

### ✅ 手順 12（ハッチの姿勢）の線の長さを測った

## 20. D-1 充電基板の受けを床から出した（2026-08-27・[case_v4.scad](../hardware/case_v4.scad)）

|---|---|---|---|
| 横から壁の面へ当てる（−X） | **0** | **111.4mm³** | ④ 後ろの控え 98.0（全高 20.5）／③ 前の返し 13.4 |

## 27. 15 度目の机上の通し — 「0」が本物かを確かめた（2026-08-28・[assembly_v4.html](../hardware/assembly_v4.html)）

### ① 0 が「両側に実体がある 0」かを機械で確かめた

当たり検査は `intersection(){ 動く側; 相手側; }` なので、**どちらか一方が空でも 0 が出ます**。
14 度目までは、その空を見る仕組みがありませんでした。0 で通っている検査ぜんぶについて、

### ② 見つけた穴は 1 つ ── E リングの検査が、ねじを障害物に数えていなかった

`knob_v5.scad` の `ering_obstacles()` が、「ねじの胴のうち `Z_BOSS_BOT` より下へ出る分」を
自前の円柱で描いていました。その高さは `Z_BOSS_BOT − SCR_TIP_Z = −10.5 − (−10.3) = **−0.2**` ——
**負の円柱**で、OpenSCAD は黙って何も作りません。つまり `part="eringpath"` も `part="eringpathx"` も、
**ねじが 1 本も居ない状態で「空＝通る」を出していました**。

- **直し**: 自前の円柱をやめ、ねじの現物 `stop_screws()` をそのまま相手にしました。
  `eringpath`（±Y）は直した後も **0** で、結論は変わりません。
- **ついでに分かったこと**: 実体で当て直すと **±X も 0**（当たらない）になります。
  ねじの先は `Z −10.3` で、リングの帯（`Z −11.6〜−10.8`）の**上端より 0.5mm 上で終わって**いて、
  いまのねじはリングの高さまで下りて来ません。[KNOB-ENCODER.md](KNOB-ENCODER.md) の
  「ねじが y=0 に居るので X から入れると轢く」は、ねじが `Z −12.0` まで出ていた頃の話でした。
- 🔒 **それでも「差し込みは ±Y のみ」は動かしていません。**決めたのはユーザーで、
  2026-08-21 に実物で「非常に難しかったが工作できないほどではない」と判定済みです。
  ±X を許すかどうかは⬜ **ユーザーの判断待ち**にしてあります。

### ③ 刷る側 ── ブリッジの掘り込みの天井が支え無しだった

STL 18 点を書き出し直し（形は 18 点とも**体積が完全一致**＝古くなっていませんでした）、
`_stl_preflight.py` を通しました。1 つだけ記録と食い違います。

- `v4_bridge`: **支えの無い天井 65mm²**（刷る向きで `Z 1.10`・`X 19.9〜38.2`・`Y 15.3〜18.5`・1 層）。
  正体は**前板のフランジが入る掘り込み**（皿の裏のへこみ）の天井で、皿を伏せて刷ると下を向きます。
  掘り込みは前（首を通す抜きの側）へ開いているので、天井を支える壁は左右と奥の 3 方だけです。
- 🔴 **初報で「支柱は立てられない」と書いたのは間違いでした**（同日、ユーザー「え。サポート付ければ
  いいんじゃないの？」で訂正）。掘り込みはプレートへ向かって開いていて、**柱を立てる空間はあります**。
  `_v4_props.py` が 0 本なのは `keepout_bridge()` が `brgf_cuts()`（この掘り込みそのもの）を
  keepout に入れているからで、**こちらが書いたルール**です。物理ではありません。
- 本当の制約は**痕**です。掘り込みの実寸は**公称 1.0 ＋ 逃げ 0.1 ＝ 1.1**、フランジは 1.0 ＝
  **差し込みの逃げ 0.1mm**。支柱の痕の実績は **0.3mm** で、痕はフランジが滑り込む天井の面に残ります。
  ⇒ サポートを入れるなら**先に掘り込みを深くする**（`BRGF_SINK` 一箇所）。その代わり前板が前へ倒れる
  余裕が増えます（逃げ 0.1 で約 1°・0.4 なら約 4°）。⬜ ユーザー判断。
- **危険度の見立て**: 天井は膜ではなく**厚み 0.9mm の棚**（皿 2.0 − 掘り込み 1.1）で、左右と奥の
  3 辺で繋がり、自由なのは手前の 1 辺だけ。一番遠い点でも奥の壁から **6.0mm** です。
  preflight の「支えから 2.0mm 超」は部品を選ばない一般のしきい値なので、
  **このまま刷って前板が入るかを見る**のが安いと考えます。
- 🔴 §T-6（[CASE-V4-OPEN.md](CASE-V4-OPEN.md)）には「支えの無い天井 **なし**・接地 2304mm²」と

## 28. 16 度目の机上の通し — つまみの STL が 5 つに割れていた（2026-08-28・[assembly_v4.html](../hardware/assembly_v4.html)）

15 度目は「当たり検査の 0 が本物か（相手が空でないか）」を潰しました。今回は**同じ疑いを、工具と手の道の側**へ
向けました。円筒を撃つ検査も、相手に居ない物には当たりません。あわせて、刷る側も見直しました。

### ① いちばん重いもの ── `stl/v4/v4_knob.stl` は 5 つのバラバラな塊だった

`_stl_preflight.py` が **中身 5 個**と言いました。連結成分ごとに焼いて測ると、つまみは
**持ち手 / 持ち手の裏の 0.3mm の円板 / 軸 / ツメ / 軸の先の 0.3mm の円板**の 5 つに分かれていて、
そのあいだに **0.01mm の隙間**が空いていました（Z 7.695・8.005・21.095 に三角形が 1 枚もありません）。
manifold と CGAL の両方で同じ結果なので、書き出しの癖ではなく**形そのもの**です。

犯人は面取りの抜き `ch_bot()` でした。

```
translate([0, 0, z - 0.01]) difference() {
    cylinder(r = r + 3, h = c + 0.02);                    // z-0.01 〜 z+c+0.01
    translate([0, 0, 0.01]) cylinder(r1 = r-c, r2 = r, h = c);   // z 〜 z+c
}
```

外側の筒だけが円錐より**上下に 0.01 ずつ長い**ので、その 2 か所は円錐に守られない
**半径いっぱいの円板**になります。抜きなので、そこで部品が丸ごと輪切りになります。
`z` は部品の**下の面**なので、下のはみ出しはその面を跨ぐ物（軸とツメ）を切り、
上のはみ出しは持ち手そのものを切っていました。

- **直し**: はみ出しをやめて、筒も円錐も `z 〜 z+c` にそろえました（[knob_v5.scad](../hardware/knob_v5.scad)）。
  面取りの寸法は変えていません（持ち手 半径 13.5 → 13.2 ／ 軸 3.5 → 3.2・どちらも 0.3mm のまま）。
- **結果**: 連結成分 **5 → 1**（manifold・CGAL とも）。体積 4941.72 → **4947.98mm³**（＋6.26 ＝ 誤って抜けていた 2 枚の 0.01mm の円板）。
  preflight は **中身 1 個・支えの無い天井なし・島 0・薄肉なし・接地 496mm²（無事の実績 513 の側）** で全部合格になりました。
- 当たり検査 48 本と工具の道は、この 6.26mm³ を戻した後も**全部同じ値**でした（戻った肉はどこにも当たりません）。
- ⚠ `ch_top()` にも同じ形のはみ出しがありますが、`z` が部品の**上の面**で、その先には何もありません。
  いまは切っていないので触っていません。

### ② 工具の道の穴 ── 手順 3 の「口を摑む」が、口の無いハブへ撃っていた

`_asm_access.py` の 20 行（10 口 × ピンセット・指）は、相手が **`st2` ＝ 口が 1 本も挿さっていない姿**でした。

- **直し**: `ST="nb_<ID>"`（手順 2 まで ＋ その口以外の 9 本）を足し、相手をそちらに変えました。
  向きも直しました（真上へ撃つと出発点が口の頭に重なり、隣の口の**下の面**を跨いでしまう。道具は上から降りて来ます）。
- **出たこと**: **トグルとリードの 2 口だけ、指の腹（φ12）が口の頭まで 4.5mm 届きません。**
  後列は 1 列に並んでいて、トグル ↔ リードは **7.6mm**。隣の口が上に取っている線の逃げ（半径 2.25）を
  よけて φ12（半径 6.0）を降ろすには **8.25mm** 要ります。**ピンセットなら 10 口とも届きます**（残り 4.0mm）。

### ③ 手順 9 の中の順番が、実は効いていた

コネクタを挿す検査は `ST="st9r"`（線を **10 束とも**障害物から外した姿）へ撃っています。
自分の線と当たるのを避けるための除外ですが、**隣の束まで消えて**いました。
`ST="w9_<束>"`（その口自身の束だけを抜く）を足して測り直すと、**OLED の 4 連**の挿し代が
**12.7 → 5.0mm**（要る 6.0）に落ちます。相手は**電流計 → PowerBoost の 2 本**で、
これが OLED の口の真上（Z 40.8〜48.0）を渡ります。

マニュアルは前から OLED を先に書いていましたが、「**先でなければならない**」とは書いておらず、裏取りもありませんでした。
反例の行を 1 本足し、本文にも「この段の中では OLED の 4 連をいちばん先に挿す」を書きました。

⚠ **線は剛体の管で描いてあります。**電流計の INPUT と OUT のように、同じ列の隣どうしが互いの真上を
渡っている所は、この描き方だと必ず当たります（1.5mm で止まる）。実物の線は逃げるので、
**straight-cylinder の検査では線どうしの当たりは判定できません。**それが `st9r` が 10 束を外している理由で、
その判断自体は妥当です。今回足したのは「**順番が効いているか**」を見るための段です。

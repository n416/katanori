# 自前の音声の板（ReSpeaker Lite ＋ XIAO の置き換え・2026-09-15 着手）

ReSpeaker Lite ＋ XIAO ESP32S3 をやめ、**XU316 の音声部と ESP32-S3 を載せた自前の音声の板**を ReSpeaker Lite の場所に入れる。ハブ（v6.1）とはライザーでつなぐ。
この資料は「なぜ・何を借りて・何を変えるか」と、面積とピンの**叩き台**だけを持つ。
板の外形・穴・口の座標は、今までどおり筐体（`hardware/case_v6_1.scad`）と [PCB-V61.md](PCB-V61.md) が持つ。

## 3. 爆音の穴を回路で塞ぐ（リレーの代わり）

リレーを入れた理由は [firmware/esp32/README.md](../firmware/esp32/README.md) の「起動時の轟音とその対策」にある。
**ESP32 だけがリセットされて、音の出口が開いたまま残る**場面（書き込み・電池切れ・クラッシュ）を塞ぐためだった。

Voice PE の回路（`DAC.kicad_sch`）では、この場面が次のように塞がる。

- TPA6211A1 の `SHUTDOWN`（Low で停止）＝ `AMP_CTL`
  - ESP32 の GPIO47 から R25（4.7kΩ）経由で駆動する
  - **R35（470kΩ）で GND に引き下げてある**
  - C29（10nF）が GND へ入っている
- ヘッドホンを挿すと Q2（BSS138）が `AMP_CTL` を Low に落とす
- ⇒ **ESP32 がどんな理由でリセットされても、ピンが浮けばアンプは止まる。** リレーの「無通電で開」と同じ働き

🔴 **アンプの EN は必ず ESP32 のピンだけで握る。**
- XMOS に握らせると、XMOS は ESP32 と一緒にリセットされないので、今のコーデックのミュートと同じ罠に戻る。ReSpeaker Lite の X0D31 がこれにあたる。
- Voice PE には、0Ω（R37）で別の信号を同じ節点へ入れる箇所がある。つながる先は未確認。流用するときは外す。

🔒 **I2S は UART0（GPIO43/44）に出さない。** GPIO43/44 はテストパッドにだけ出す（USB が死んだとき、ROM ログを読むための最後の経路）。

ROM ログを eFuse で止める案は、2026-08-03 に不採用のまま。この板でも要らない。

⚠ 1 枚案（v6.1 の板に全部）のときの見積もり。2 枚案では音声の板が ReSpeaker Lite と同じ中身（XU316・コーデック・アンプ・マイク）に ESP32 モジュール（XIAO の代わり）を載せるだけなので、面積の心配は小さい（11 章）。

`kicad_pcb` から部品ごとの courtyard を読んで合計した。配線の余白は入っていない。

## 7. 部品の在庫（JLCPCB / LCSC の API・2026-09-15 取得）

Voice PE の部品は**全部 Extended**（Basic も Preferred も無い）。1 枚あたり約 24 種類ある。

**欠品で、代わりに替える物**（XU316 以外は同じ足形・同じピン配置）:

| Voice PE の部品 | 状況 | 替える物 | 違い |
|---|---|---|---|
| XU316-1024-QF60B-C24 | 在庫 0 | **QF60B-C32（C7397517）** | ピン互換で速い版。**JLC・LCSC とも在庫 12 個しかない ⇒ DigiKey（2026-09-14 時点で 571 個）で買って持ち込む**。QF60A は IO が全部 1.8V なので使えない |
| ZB25VQ32DSJG（XU316 の Flash） | 取り扱いなし | W25Q32JVSSIQ（C179173・在庫 2.4 万） | 電源の下限が 2.7V（Voice PE の Flash の電源が 3.3V かは ⬜ 未確認） |
| Y2400FE001（24MHz） | 見つからず | HY24MSMD2016FA1R30（C5265838） | ESR 45Ω。XMOS の条件（ESR 60Ω 以下・12pF）に収まる |
| LC1458CB5TR33 | 取り扱いなし | ME6211C33M5G-N（C82942） | ピン配置は同じ。Voice PE でも U19 は DNP |
| SGM2594BDXN5G（電源スイッチ） | 取り扱いなし | RT9742CGJ5（C250546） | ピン配置は同じ。電流制限の値は ⬜ データシートで確かめる |
| ESDPSA0402V05（Semitel） | 在庫 0 | SLESDPSA0402V05（C7496591） | 同じ系列の互換品 |
| MSM261DHP006（マイク） | **在庫あり（C22390138・2508）** | そのまま使う | — |

**ESP32**: ESP32-S3-WROOM-1U-N16R8（C3013946）は JLC に 11,135 個ある。

**AS5600（C79815）: LCSC は 0 だが、JLCPCB 側に 813 個ある ⇒ JLCPCB の実装なら使える。**
発注までに減るおそれがある。控えは次の 2 つ。
- AS5600L: 在庫 6 個で足りない。
- MT6701CT-STD-R（C3003196・8,592 個）: ピン 3・4・6・7 は同じだが、ピン 2・5・8 の役目が違う。I2C のアドレスは 0x06、レジスタも別物。載せ替えには板とファームの両方の変更が要る。

## 8. 回路図（2 枚・2026-09-15 夜）

```
python hardware/pcb/gen_sch_voice.py && python hardware/pcb/check_sch_voice.py
```

| 板 | 出力 | 部品 | 中身 |
|---|---|---|---|
| 音声の板 | `hardware/pcb/katanori61_audio/`（A1） | 192 | Voice PE の XMOS・DAC・Power の写し、マイク 2 個、ESP32-S3-WROOM-1U とその周り、JTAG のパッド、ライザーの 2 列（J21・J22）、スピーカーの口 J23 |
| ハブ | `hardware/pcb/katanori61_hub/`（A3） | 49 | v6.1 から、リレーまわり・SPK IN（J4）・SPK OUT（J5）・XIAO の受けを外し、ライザーの口 J1 を 2x07 に |

- v6.1 の `katanori61/` はそのまま残っている（比べる元にするため）。
- Voice PE の部品は、**部品番号に 100 を足して**写した（R36 → R136）。
- `gen_sch.py` は書き出し部分だけを使い回せるように直した。v6.1 の出力は 1 バイトも変わっていない。

### ライザー（音声の板 ↔ ハブ）

音声の板の J21・J22 は、XIAO のピンがあった 2 列（11 章）に立てる 1x07 のオス。ハブの J1（2x07）の奇数番が J21、偶数番が J22。

| 番 | J21（電源の列） | J22（信号の列） |
|---|---|---|
| 1 | V5 | GND |
| 2 | GND | USB_DN |
| 3 | V33 | USB_DP |
| 4 | BTN | SDA |
| 5 | OLED_RES | SCL |
| 6 | OLED_DC | OLED_SCL |
| 7 | OLED_CS | OLED_SDA |

- 3.3V は音声の板（Voice PE の TPS62827）が作り、ハブの INA226・AS5600・画面へ送る。5V はハブの昇圧から来る。
- 共用の I2C の引き上げは音声の板の R223・R228（Voice PE の R123・R128）。ハブの R42・R43 は画面の I2C の引き上げ。
- スピーカーは音声の板の J23（PH2.0・上から挿す）に直に挿す。ハブの J5 は無くなった。

### 検算（`check_sch_voice.py`）

KiCad が書き出した 2 枚のネットリストを、ライザーでつないで 1 つにし、元の 2 つと突き合わせる。
1. Voice PE から写した部品: 168 個・487 ピンが Voice PE と同じ組み合わせでつながっているか
2. ESP32 のピン: Voice PE の ESP32 の GPIOn と、この板の IOn の相手が同じか。変えた 15 本（画面・会話ボタン・I2C はライザー越しにハブの相手まで）と、ライザーを越える電源と USB の 5 本を確かめる。JTAG のパッド 7 個
3. 爆音の穴:
   - アンプの SHUTDOWN に乗っているのが、470kΩ・4.7kΩ・10nF・アンプだけか
   - その向こうが ESP32 の IO47 だけか
   - UART0 がテストパッドだけか
4. v6.1 から残した部品（ハブ）: 146 ピンのつながりが変わっていないか

2026-09-15 の時点で**食い違いは 0 件**。ライザーの USB の 2 本を音声の板の側だけ入れ替えると、2 件の食い違いとして出ることも確かめた。

KiCad の ERC のエラーは、ハブの Q1 のベースの 1 件だけ（v6.1 の時点から同じ。昇圧 IC の LBO はオープンドレイン）。音声の板は 0 件。

**写さなかった物**（外した理由はどれも「katanori に無い部品のためのもの」）:

| シート | 外した物 |
|---|---|
| Power | 2 つ目の USB-C・USB の切替（SGM7222）・VBUS から 5V を作るスイッチ（SGM2594）とその周り |
| DAC | 3.5mm ジャックとその経路・ヘッドホン検出（Q2 がアンプを止める回路）・スピーカーの口 J2（音声の板の J23 に替える） |
| XMOS | ミュートのスライドスイッチとその検出・XU316 の USB の VBUS 検出・ESP32 との予備線・JTAG の 20 ピン J5 と xLink の 22Ω（R32・R33。JTAG はテストパッド J16） |

**変えたつなぎ方**:
- ミュート: スライドスイッチの代わりに、ESP32 の IO2 で握る。
- USB: USB の ESD 保護と 22Ω は写し、ハブの USB-C からライザーを通して ESP32 へ。
- 画面: ハブの J2 を 1x07 にし、画面専用の I2C（後から SPI）に替える。
- マイク: 足元に 100nF（C301・C302）を足した。Voice PE はマイクが XU316 の近くにあるので、この 100nF が無い。

**⬜ まだの物**:
- **受動部品の LCSC 番号**（IC は 7 章の番号を入れた）
- **5V の電流**: ハブの昇圧 TPS61090 で、XU316・ESP32・アンプを全部まかなえるか
- **基板**: 音声の板（4 層・82.024 × 34.007・両面に部品）とハブ（v6.1 から中身が変わった）の配置と配線。`gen_pcb_voice.py` はまだ 1 枚案の板を作るコードのままで、今の回路図では動かない。音声の板を作るコードに書き換える（次の作業）

## 10. 1 枚案の基板の記録（4 層・2026-09-15・取りやめ）

v6.1 の板（82.024 × 37.4）に全部を載せる案で、配置と自動配線まで進めて**やめた**（1 章）。
道具（`gen_pcb_voice.py`・`route.py`・`dsn.py`・`voicepe.py`）は 2 枚に分けた板を作るときに使い回す。1 枚案の出力（`hardware/pcb/katanori61_voice/`・`katanori61_mic/`）は消した（git の履歴にはある）。
2 枚案でもそのまま効く教訓だけを残す。

### 足形（そのまま使う）

Voice PE の `.kicad_pcb` から `hardware/pcb/voicepe.pretty`（26 種）を起こした（`voicepe.py`）。
- **検算**: 元と同じ面・同じ回転で置き直すと、171 部品すべてでパッドの位置・向き・層が一致する。
- **同じ名前で形の違う足形**: C0603・R0603 に 2 種類あったので、2 つ目を `_v2` に分けた。
- **XU316 の外形**: 長さ 0 の線と余計な線が混ざっていたので、長方形 1 つに替えた。

### 置き方の教訓

- Voice PE は大半が裏面。**裏から見た鏡像**（X を鏡にし、向きは 180 − a、層は F↔B・In1↔In2）で写す。
- 押し離し（relax）は解けなかった（79 組）。⇒ **大きい順に、狙った位置に一番近い空きへ置く**（`legalize`）。
- 枠は courtyard に**パッドの実寸**と**丸の本当の半径**を足して測る（courtyard だけではパッドが 25 か所で触れた）。
- IC の周りの余白: 足 16 本以上は 0.6、6 本以上は 0.3（0.05 では XU316 のピンが引き出せなかった）。
- 裏の部品の貫通の足の真上（表）には部品を置かない。

### 自動配線の教訓（Freerouting 2.4.1）

- 内層を DSN の plane にすると例外で止まる（`drillShapes` is null）。⇒ 4 層とも配線の層にし、GND のベタを 4 層に敷く。
- 最適化の段は、配線の段より悪い版を書き出すことがある。⇒ 止める（`--router.optimizer.enabled=false`）。
- ネックダウン（細いピッチの手前で線を半分まで細くする）は止める（`--router.automatic_neckdown=false`）。
- 🔴 **CLI で渡した `--router.*` は `%APPDATA%\freerouting\freerouting.json` に残り、次の起動にも効く。** `route.py` は板ごとに全部の値を明示する。
- 金属化していない穴（USB-C の位置決めの足）は、DSN で配線禁止にする（入れ忘れて VBUS のビアが 25 個乗った）。
- 多角形のパッドと斜めのパッドは、DSN に**凸包の多角形**で渡す（小さく渡したら線がパッドに 0.044 まで寄った）。
- **すきま**: マイクの LDO（U118・X2SON4）はパッド 3–5 の間が 0.123、XU316 は 0.146。規則はネットクラスを 0.12 にし、**線・穴・ベタだけ 0.15** を `kicad_dru` で掛ける（ネットクラスを 0.15 にすると XU316 の隣り合うパッドが 56 件の違反になる）。

### 結果と、やめた理由

| 回 | 規則 | 結果 |
|---|---|---|
| 3 回目 | 線 0.15・すきま 0.12 | 未接続 4（JTAG の 20 ピンが XU316 から 45mm） |
| 5 回目 | 同上・JTAG をテストパッドに | 未接続 6（全部 XU316 の水晶・PLL・I2S の周り）・すきま 0.1147 が 3 件 |
| 6 回目 | 線 0.2・すきま 0.15（受動部品を 0402 に） | パス 4 で 44 本（5 回目の同じパスは 12 本）。途中で止めた |

- 5 回目の板を見たユーザー:「ごっちゃごちゃ。簡単にショートしそう」。緩めると通らない＝**面積が足りない**。手で引いても通り道は増えない。
- ⇒ 2 枚に分けた（1 章）。

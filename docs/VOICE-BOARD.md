# 音声まわりを v6.1 の板へ統合する（2026-09-15 着手）

ReSpeaker Lite ＋ XIAO ESP32S3 をやめ、**XU316 の音声部と ESP32-S3 を v6.1 の 1 枚基板に載せる**。
この資料は「なぜ・何を借りて・何を変えるか」と、面積とピンの**叩き台**だけを持つ。
板の外形・穴・口の座標は、今までどおり筐体（`hardware/case_v6_1.scad`）と [PCB-V61.md](PCB-V61.md) が持つ。

## 1. 決まったこと

| 🔒 決定 | 理由 |
|---|---|
| **XU316 をそのまま載せる**（ソフトの AEC や半二重にはしない） | 声での割り込みが必須。割り込みの要らない版は Android と Web で既にある（ユーザー 2026-09-14） |
| **20 台以上作る前提** | ReSpeaker Lite は日本から大量に入手するのが面倒（ユーザー 2026-09-15） |
| **v6.1 の板と 1 枚にまとめる** | ユーザー 2026-09-15。v6.1 は未発注なので、そのまま変えられる |
| **ミュートリレーを外す** | 下の 3 章。アンプの SHUTDOWN を ESP32 のピンで握り、プルダウンで代わりにする |
| **マイク間隔は 71.0mm** | ReSpeaker Lite（[RESPEAKER-LITE.md](RESPEAKER-LITE.md) の U4/U5：中心 5.49 と 76.49）、Voice PE、XMOS 純正リファレンスのどれも 71mm。XMOS は 71mm で評価し、他の間隔は「適応するが性能は変わりうる」としている |
| **マイクだけを前の面の細い板に分ける** | ユーザー 2026-09-15「マイクだけ前にあればいい」。主の板は v6.1 の位置と向きのままなので、AS5600 とつまみの軸の機構は変わらない。前を向いた 71mm 間隔のマイクという、今の実機で効いている配置も保てる |
| **マイク・XU316・コーデックは今と同じ部品** | 今の実機で割り込めていて、遠くの声も拾えている（ユーザー 2026-09-15） |

## 3. 爆音の穴を回路で塞ぐ（リレーの代わり）

リレーを入れた理由は [firmware/esp32/README.md](../firmware/esp32/README.md) の「起動時の轟音とその対策」にある。
**ESP32 だけがリセットされて、音の出口が開いたまま残る**場面（書き込み・電池切れ・クラッシュ）を塞ぐためだった。

Voice PE の回路（`DAC.kicad_sch`）では、この場面が次のように塞がる。

- TPA6211A1 の `SHUTDOWN`（Low で停止）＝ `AMP_CTL`
  - ESP32 の GPIO47 から R25（4.7kΩ）経由で駆動する
  - **R35（470kΩ）で GND に引き下げてある**
  - C29（10nF）が GND へ入っている
- ヘッドホンを挿すと Q2（BSS138）が `AMP_CTL` を Low に落とす
- ⇒ **ESP32 がどんな理由でリセットされても、ピンが浮けばアンプは止まる。** リレーの「無通電で開」と同じ働き

🔴 **アンプの EN は必ず ESP32 のピンだけで握る。**
- XMOS に握らせると、XMOS は ESP32 と一緒にリセットされないので、今のコーデックのミュートと同じ罠に戻る。ReSpeaker Lite の X0D31 がこれにあたる。
- Voice PE には、0Ω（R37）で別の信号を同じ節点へ入れる箇所がある。つながる先は未確認。流用するときは外す。

🔒 **I2S は UART0（GPIO43/44）に出さない。** GPIO43/44 はテストパッドにだけ出す（USB が死んだとき、ROM ログを読むための最後の経路）。

ROM ログを eFuse で止める案は、2026-08-03 に不採用のまま。この板でも要らない。

| **マイクのライザー。** 🔒 前の面に**ライザー**を立て、マイクを前へ出す（ユーザー 2026-09-15）。つなぎ方は今の XIAO のライザーと同じく、主の板にオスのピンヘッダ、ライザーの裏に L 字のメスを付ける。2 個のマイクはクロックとデータを共用し、L/R の選択ピンで分けるので、信号は `VDD_MIC`・`MIC_CLK`・`MIC_DATA` の 3 本で済む。PDM のクロックは約 3MHz なので、**GND・CLK・GND・DATA・VDD の 1x05** にしてクロックの隣を GND にし、主の板側でクロックに直列抵抗を入れる。線より短いので、FFC より有利。ただし、同じ板にマイクを置いた評価済みの条件からは外れる。初回の板で、割り込みと遠くの声を今の実機と聞き比べる | 回路 |

## 7. 部品の在庫（JLCPCB / LCSC の API・2026-09-15 取得）

Voice PE の部品は**全部 Extended**（Basic も Preferred も無い）。1 枚あたり約 24 種類ある。

**欠品で、代わりに替える物**（XU316 以外は同じ足形・同じピン配置）:

| Voice PE の部品 | 状況 | 替える物 | 違い |
|---|---|---|---|
| XU316-1024-QF60B-C24 | 在庫 0 | **QF60B-C32（C7397517）** | ピン互換で速い版。**JLC・LCSC とも在庫 12 個しかない ⇒ DigiKey（2026-09-14 時点で 571 個）で買って持ち込む**。QF60A は IO が全部 1.8V なので使えない |
| ZB25VQ32DSJG（XU316 の Flash） | 取り扱いなし | W25Q32JVSSIQ（C179173・在庫 2.4 万） | 電源の下限が 2.7V（Voice PE の Flash の電源が 3.3V かは ⬜ 未確認） |
| Y2400FE001（24MHz） | 見つからず | HY24MSMD2016FA1R30（C5265838） | ESR 45Ω。XMOS の条件（ESR 60Ω 以下・12pF）に収まる |
| LC1458CB5TR33 | 取り扱いなし | ME6211C33M5G-N（C82942） | ピン配置は同じ。Voice PE でも U19 は DNP |
| SGM2594BDXN5G（電源スイッチ） | 取り扱いなし | RT9742CGJ5（C250546） | ピン配置は同じ。電流制限の値は ⬜ データシートで確かめる |
| ESDPSA0402V05（Semitel） | 在庫 0 | SLESDPSA0402V05（C7496591） | 同じ系列の互換品 |
| MSM261DHP006（マイク） | **在庫あり（C22390138・2508）** | そのまま使う | — |

**ESP32**: ESP32-S3-WROOM-1U-N16R8（C3013946）は JLC に 11,135 個ある。

**AS5600（C79815）: LCSC は 0 だが、JLCPCB 側に 813 個ある ⇒ JLCPCB の実装なら使える。**
発注までに減るおそれがある。控えは次の 2 つ。
- AS5600L: 在庫 6 個で足りない。
- MT6701CT-STD-R（C3003196・8,592 個）: ピン 3・4・6・7 は同じだが、ピン 2・5・8 の役目が違う。I2C のアドレスは 0x06、レジスタも別物。載せ替えには板とファームの両方の変更が要る。

## 8. 回路図（2026-09-15）

```
python hardware/pcb/gen_sch_voice.py && python hardware/pcb/check_sch_voice.py
```

- 出力は 2 枚ある。
  - 主の板: `hardware/pcb/katanori61_voice/`（222 部品・A1）
  - マイクのライザー: `hardware/pcb/katanori61_mic/`（17 部品・A4）
- v6.1 の `katanori61/` はそのまま残っている（比べる元にするため）。
- `gen_sch.py` は書き出し部分だけを使い回せるように直した。v6.1 の出力は 1 バイトも変わっていない。
- Voice PE の部品は、**部品番号に 100 を足して**写した（R36 → R136）。

**検算（`check_sch_voice.py`）** は、KiCad が書き出したネットリストを元の 2 つと突き合わせる。
1. Voice PE から写した部品: 171 個・511 ピンが Voice PE と同じ組み合わせでつながっているか
2. ESP32 のピン: Voice PE の ESP32 の GPIOn と、この板の IOn の相手が同じか。変えた 13 本は、それぞれの相手を確かめる
3. 爆音の穴:
   - アンプの SHUTDOWN に乗っているのが、470kΩ・4.7kΩ・10nF・アンプだけか
   - その向こうが ESP32 の IO47 だけか
   - UART0 がテストパッドだけか
4. v6.1 から残した部品: 148 ピンのつながりが変わっていないか

2026-09-15 の時点で**食い違いは 0 件**。

KiCad の ERC は、エラーが Q1 のベースの 1 件だけ（v6.1 の時点から同じ。昇圧 IC の LBO はオープンドレイン）。
警告は、足形のライブラリ `voicepe:` がまだ無いことによる。

**写さなかった物**（外した理由はどれも「katanori に無い部品のためのもの」）:

| シート | 外した物 |
|---|---|
| Power | 2 つ目の USB-C・USB の切替（SGM7222）・VBUS から 5V を作るスイッチ（SGM2594）とその周り |
| DAC | 3.5mm ジャックとその経路・ヘッドホン検出（Q2 がアンプを止める回路）・スピーカーの口 J2（v6.1 の J5 を使う） |
| XMOS | ミュートのスライドスイッチとその検出・XU316 の USB の VBUS 検出・ESP32 との予備線 |

**変えたつなぎ方**:
- ミュート: スライドスイッチの代わりに、ESP32 の IO2 で握る。
- スピーカー: SPK+ を SPKO（J5 の 2 番）、SPK− を SPKM（J5 の 1 番）へつなぐ。
- USB: USB の ESD 保護と 22Ω は写し、v6.1 の USB-C から ESP32 へ通す。
- 画面: J2 を 1x07 にし、画面専用の I2C に替える。
- マイクのライザー: マイクの足元に 100nF を足した。Voice PE はマイクが板の上で近いので、この 100nF が無い。

**⬜ まだの物**:
- **受動部品の LCSC 番号**（IC は 7 章の番号を入れた）
- **足形**: Voice PE の `.kicad_pcb` から `voicepe.pretty` を起こす
- **4 層への対応**
- **J5（XSYS2 の 20 ピン）を板のどこに置くか**
- **5V の電流**: 昇圧の TPS61090 で、XU316・ESP32・アンプを全部まかなえるか

## 10. 基板（4 層・配置と自動配線・2026-09-15 夜）

```
python hardware/pcb/gen_pcb_voice.py && python hardware/pcb/route.py --board katanori61_voice
```

### 足形

Voice PE の `.kicad_pcb` から `hardware/pcb/voicepe.pretty`（26 種）を起こした（`voicepe.py`）。

- **検算**: 元と同じ面・同じ回転で置き直すと、171 部品すべてでパッドの位置・向き・層が一致する。
- **1 番ピン**: QFN・TSSOP・SOIC・SOT-23-5・マイクは、上から見て反時計回りに並ぶ。
- **同じ名前で形の違う足形**: C0603・R0603 に 2 種類あったので、2 つ目を `_v2` に分けた。
- **XU316 の外形**: 長さ 0 の線と余計な線が混ざっていたので、長方形 1 つに替えた。

### 置き方

**固定した物**（v6.1 と同じ枠）:
- 口・USB-C・AS5600・画面の口 J2（1x07）
- マイクのライザーの口 J15（XIAO のライザーの枠に 1x05）
- ESP32-S3-WROOM-1U（中央の奥）

**残りの物**は、まとまりごとに区画を決めた。
- v6.1 の電源: v6 の板の並び
- 音声部: Voice PE の板の並び。Voice PE は大半が裏面なので、**裏から見た鏡像**（X を鏡にし、向きは 180 − a）にして区画へ縮める

縮めたまま押し離すと解けなかった（79 組が重なって残った）。⇒ **大きい順に、狙った位置に一番近い空きへ置く**方式に替えた。
- **枠**: courtyard に**パッドの実寸**と**丸の本当の半径**を足して測る。courtyard だけで置いたら、パッドどうしが 25 か所で触れた。
- **IC の周りの余白**: 足 16 本以上は 0.6、6 本以上は 0.3。0.05 で詰めたら、XU316 のピンが引き出せなかった。
- **裏の部品の貫通の足**: 真上（表）には部品を置かない。電池の口 J10 の上に R16 が乗っていた。

配線前の DRC はエラー 0。

### 自動配線（Freerouting 2.4.1・4 層・線 0.15・穴 0.45/0.2）

- **内層を GND の面（DSN の plane）として渡すと、Freerouting が例外で止まる**（`drillShapes` is null）。⇒ 4 層とも配線の層として渡し、GND のベタを 4 層に敷く。
- **1 回目**:
  - 配線の段: パス 33 で未接続 **2 本**。
  - 最適化の段: 別の版（9 本）から始まり、その版が書き出された。⇒ 最適化の段を止めた（`--router.optimizer.enabled=false`）。
  - USB-C の位置決めの穴の上に VBUS のビアが打たれた。⇒ 金属化していない穴を配線禁止にした。
  - 細いピッチの手前で線が 0.112・0.09 に細くなる（ネックダウン）。⇒ 最小線幅の規則を 0.09 にした（JLCPCB の 4 層で作れる値）。
- **2 回目**:
  - 配線の段: 未接続 10 本。
  - DRC: エラーは未接続 11 と、すきま 2 だけ。
  - **すきま 2 件の原因**: マイクの LDO（U118・X2SON4）の足形そのもの（パッド 3–5 が 0.123）。⇒ すきまを 0.12 にした。
- **3 回目**（すきま 0.12）:
  - 配線の段: パス 21 で未接続 2 本・約 16 分（1 回目の半分）。
  - **DRC の未接続は 4 本で、4 本とも JTAG の口の線**。XU316 の RST_N・TDI・TDO と、xLink の X1D19 で、**それ以外のネットは全部つながった**。
  - **DRC のエラー**（未接続のほか）:
    - すきま 2 件（マイクの LDO U118 の足元。**0.044 は実質の接触寸前**）
    - 線幅 0.075 が 5 本（ESP_EN・GNDA。Freerouting が 0.15 の半分まで細くした所で、JLCPCB の下限 0.09 を割る）
  - 板は `hardware/pcb/katanori61_voice/`（配線済み）。
- **残る未接続は JTAG に集まっている**。
  - JTAG の 20 ピン（J105・DNP）は、裏で置ける所が右の帯しか無く、XU316 から 45mm 離れている。

### ⬜ 決めること

- **JTAG の口**: 20 ピンの XSYS2（XTAG4 がそのまま挿さる）を、XU316 のそばの小さな口に替えるか。
  - 候補: Tag-Connect かテストパッドを XU316 の近くに置き、書き込みは治具でする。
  - xLink（XL_UP/DN）は xSCOPE のデバッグ用で、書き込み（xflash）には要らない。
- **音声向けの配置の詰め**: 今は「配線が通る」ことだけを見ている。
  - アナログ（コーデック・マイクの電源）と、昇圧・DC-DC の距離
  - GND の分け方（GNDA）
  - 水晶の周り

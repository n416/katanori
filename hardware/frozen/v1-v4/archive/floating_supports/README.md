# 凍結: 傾けて浮かせる支柱のパイプライン（2026-09-03）

🔒 ユーザー「帯については浮かすのも傾けるのもやめましょう。この帯については柱を立てる方の
パイプラインで作りましょう」「浮かすパイプラインは凍結。使われないようにしてアーカイブしておきましょう」。

## 何だったか

`_v4_post_props.py` … 部品をプレートから 5mm 浮かせ、**柱＋球＋円錐**で法線方向から受ける支柱と
スケート型のラフトを書き出す生成器。向き（傾き・方位）は `_tilt_sweep.py` の物差し
（1 層あたりの断面積の増分）で選んでいた。`_spot_props.py` はその部品の形をそのまま借りて、
検算が出した 1 か所にだけ支柱を足す道具（依存しているのでここへ一緒に置く）。

## なぜ作られ、なぜ凍結したか

作った理由は **支柱（スペーサー）6 本**を刷るためだった（🔒 2026-09-01・docs/PRINT.md §3.9）。
φ2.0 の細い軸を立てると断面が z 1.60 で 1.74 → 26.37mm² へ一段に跳ぶので、傾けて跳ねを
0.7mm²/層に落とし、接地が消えるぶんを浮かせて足で受ける、という筋だった。

**その支柱は 2026-09-03 に留め帯と一体になり、部品として消えた。** 相手が 40mm の帯に変わったあと、
この道具は次の 3 つを同時に満たせなかった:

1. **開始点（宙から始まる肉）を 0 にできない。** 傾けると E リングの溝の上の段（0.25mm）や足の裏の角が
   下向きの縁になる。軸の縁は「触ってはいけない面」なので柱を当てられず、原理的に消せない。
   ⇒ 直置き（0°）なら 3 本とも開始点 0（実測）。
2. **正しい角度を出せない。** 向きは球面上の連続な 2 自由度なのに、傾き 5° × 方位 45° の 145 点しか
   見ていない。上位どうしの差（1.12 対 1.14mm²）は網の目より細かく、意味を持たない。
3. **遅い。** 1 本あたり 5〜15 分。CHITUBOX のオートサポートは一瞬で、結果も同等以上だった。

⚠ 記録に残っていた見立て（docs/PRINT.md §3.9 の ⬜「このシステムを続けるかは未決」）と同じ結論に
なった。**残す価値があるのは向きの選定（`_tilt_sweep.py`）**で、あれは凍結していない（hardware/ に残す）。
